# 工作计划：元意识知识库全面审校

> 原则：内容由作者定，流程与工具由项目组执行；每改一条都留痕、可回查、可回滚。

作者投入：每日 1–2 小时；项目组负责导入、校验、发布。

## 三、审校流程（每批）

1. 作者在工作簿中逐条填「审校结论」：保留 / 修改 / 删除 / 新增 / 待定；
2. 需要修改的，填「修改后文本」；
3. 项目组按结论执行，生成变更记录；
4. 跑 `mcai verify` 与测试；
5. 有引文受影响的，同步检查区间与出处；
6. 打一个批次 tag，可回滚。

## 四、审校原则

1. **只改内容，不改结构**：字段、分类体系保持不变，除非作者明确要求；
2. **每条改动写理由**：一句话，进变更记录；
3. **定义改动必须仍有出处**：新增内容不能没有引文；
4. **不新增无出处内容**：宁可标「待补」；
5. **保留历史版本**：旧版可查，不覆盖；
6. **术语改动要查依赖**：该术语被哪些问答、关系引用，一并检查。

## 五、质量门槛（每批）

- 引文核验通过率 100%（与底本一致）；
- thin 定义比例不高于上一版；
- 术语与问答无悬空引用（related/source_terms 均存在）；
- 测试全绿；
- 作者签字确认本批。

## 六、交付物

- 审校工作簿（xlsx，四个 sheet + 依赖表）；
- 批次变更记录；
- 发布版知识库（0.4.0）；
- 数据集新版本（Zenodo）；
- 审校报告（改了什么、为什么、影响范围）。

## 七、风险

| 风险 | 应对 |
|---|---|
| 改动引发连锁不一致 | 先建依赖图，改术语时同步查问答与关系 |
| 作者时间不稳定 | 按批次推进，不设硬截止 |
| 引文被改动后失效 | 每批跑 verify，失败即停 |
| 版本混乱 | 每批 tag + 变更记录 |
| 审校范围膨胀 | 只审现有 64/122/270/213，不新增范围 |
