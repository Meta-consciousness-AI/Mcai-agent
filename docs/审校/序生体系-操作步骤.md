## 一、术语审校（16 条，逐条过）

每条问九个问题：

| # | 检查项 | 判定 |
|---|---|---|
| 1 | 定义是否准确、完整 | 不准确/有遗漏 → 改 |
| 2 | 是否混入编者解释 | 混入 → 拆到 editor_note 或删 |
| 3 | 简短定义是否与完整定义一致 | 不一致 → 改 |
| 4 | 英文名是否恰当 | 不恰当 → 改 |
| 5 | 别名是否必要 | 不必要 → 删 |
| 6 | 分类与排序是否正确 | 不对 → 调 |
| 7 | 出处是否对应、区间是否准确 | 不对 → 修或标待补 |
| 8 | 与其它术语是否冲突或重复 | 冲突 → 合并或加区分 |
| 9 | 是否被问答正确引用 | 引用不对 → 记下来，问答阶段改 |

**判定原则**：

- 保留：九项都过；
- 修改：有明确问题，且能当场改；
- 删除：术语不成立，或与另一条重复；
- 新增：有遗漏的核心概念（需有出处）；
- 待定：需要再想，或需查资料。

## 二、问答审校（31 条）

逐条对照修改后的术语：

| # | 检查项 |
|---|---|
| 1 | 问题是否是真实问法（不是生造的） |
| 2 | 答案是否与最新定义一致 |
| 3 | 是否保留出处与区间 |
| 4 | 是否引入了定义之外的内容 |
| 5 | 关联术语是否正确 |
| 6 | 是否过时（提到了已被修改的说法） |

结论填：保留 / 修改 / 删除 / 新增 / 待定。

## 三、关系审校（95 条）

| # | 检查项 |
|---|---|
| 1 | 关系类型是否正确（上下位/并列/因果/条件/引用/提及） |
| 2 | 方向是否正确（A→B 还是 B→A） |
| 3 | 依据是否来自原文 |
| 4 | 层级是否正确（core/derived/mention） |
| 5 | 目标术语是否存在、是否同名冲突 |

## 五、引文核验

定义改动后：

- 原有出处仍能匹配 → 保留；
- 不能匹配 → 补新出处，或标「待补」；
- 新增内容没有出处 → 不进发布版。
