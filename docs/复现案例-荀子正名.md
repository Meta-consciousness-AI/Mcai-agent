# 复现案例：荀子《正名》（第三语料）

> 目的：用一篇「定义密集」的先秦哲学文本，检验方法在抽象概念与单字术语上的表现。

## 一、语料

- 文本：《荀子·正名》原文（公共领域）；
- 来源：公开网页 `chinesebooks.github.io`，仅取「原文」段，剔除译文；
- 规模：75 段、约 10,000 字；
- 工作区：`workspaces/xunzi/`。

## 二、做法

1. 从原文直接抽取 12 个定义句，写成「术语：原句」词表（`corpus/glossary.txt`）；
2. 原文全文作为 `evidence` 文档；
3. 人工补英文名、三类分类与 9 条人工关系；
4. 用同一套流水线构建：`mcai build --home workspaces/xunzi`。

## 三、结果

| 指标 | 元意识 | 孙子兵法 | 荀子正名 |
|---|---|---|---|
| 概念 | 64 | 13 | **12** |
| 问答 | 122 | 17 | 5 |
| 关系 | 270 | 6 | 9 |
| 引证 | 213 | 9 | 12 |
| 引文核验 | 55/55 | 13/13 | **12/12** |

问答抽样：

- 「什么是性」→ `concept`，原文「生之所以然者谓之性」，1 条出处；
- 「名和辞有什么关系」→ `relation`，返回「连属」，2 条出处；
- 「什么是约定俗成」→ `concept`，原文「约定俗成谓之宜」，2 条出处。

## 四、这一轮暴露的问题

| 问题 | 表现 | 修复 |
|---|---|---|
| 单字术语被拒 | 「性」「情」「名」「辞」等 8 个术语全部丢失 | 允许单字，但必须在人工分类中列出 |
| 关系问句只认多字术语 | 「名和辞有什么关系」返回 none | 关系正则由 `{2,20}` 放宽到 `{1,20}` |

## 五、与孙子兵法的对比

| 维度 | 孙子兵法 | 荀子正名 |
|---|---|---|
| 定义密度 | 中（部分「X 者，Y 也」） | 高（大量「谓之」句式） |
| 术语长度 | 多字 | 单字为主 |
| 关系来源 | 人工 | 人工 |
| 抽取难度 | 低 | 中（单字需白名单） |
| 哲学抽象度 | 中 | 高 |

## 六、结论

1. 对「定义密集型」哲学文本，流水线可以直接产出高质量词条，几乎不需要改写；
2. 单字术语是先秦文本的常态，必须有条件放行，否则会丢掉一半概念；
3. 关系仍需人工，但关系问句的解析要能处理单字；
4. 规范 V1.1 的修订项增加到四条：
   - 无词表文本先做「术语—原句」对照；
   - 允许中文数字开头术语；
   - 允许人工登记的单字术语；
   - 非定义性文本（如道德经）定义必须分层为「原文句 + 编者释义」。

## 七、复现命令

```bash
python -m mcai build --home workspaces/xunzi
python tools/verify_citations.py --kb workspaces/xunzi/data/kb.json --config workspaces/xunzi/config/corpus.json
```
