# 把一套学说做成 AI 能调用的知识资产：一次工程实践

> 这篇文章讲一件很具体的事：怎么让 AI 在回答一套学说时，不再靠记忆瞎编，而是真的去查、去引用。

## 问题：AI 会"答错"，但不一定是它笨

如果你有一套自己的理论、术语体系或学说，直接去问大模型，通常会遇到三种情况：

1. **它没听过**，于是按字面意思猜；
2. **它听过，但理解是别人的版本**——比如"元意识"在心理学里指 meta-awareness，和你的定义不是一回事；
3. **它答得似是而非**，你很难判断哪句来自你的原文，哪句是它补的。

第三种最麻烦。因为它看起来像懂，实际上在做"语义占位"：用一个相近的概念，替换掉你的概念。

## 思路：不是让 AI 记住，而是让 AI 能查

我们的做法不是去训练模型，而是把学说做成一套**可被调用的知识资产**：

- 术语级定义，而不是整本书；
- 每条定义带原文出处；
- 概念之间有明确关系；
- 提供标准接口，让 AI 应用可以直接调用；
- 把数据、接口、站点一起发布，任何人都能装、能用。

一句话：**不追求让模型"知道"，而是让它每次都能"查到"。**

## 具体做了四件事

### 1. 把文本整理成术语库

从原始文稿里抽取"术语 + 定义"，做多源比对、冲突检测、别名归一。最后得到：

- 64 个概念
- 122 组标准问答
- 270 条概念关系
- 213 条原文引证

每条定义都能追到出处，而不是模型转述。

### 2. 给 AI 一个标准接口

用 MCP（Model Context Protocol）把知识库封装成 5 个工具：

- 回答整句问题
- 取单个词条
- 检索术语
- 查概念关系
- 列全部术语

任何支持 MCP 的客户端（Claude Desktop、Cursor、Cline 等）装上就能用。

### 3. 把包发到公开渠道

- PyPI：`pip install mcai-knowledge`
- MCP 官方注册表：可被客户端检索
- Glama：开发者目录，工具定义质量评分 4.5/5
- 国内：魔搭 MCP 广场、ModelScope 数据集

包是自包含的，装完即用，不依赖作者服务器在线。

### 4. 让内容可验证

每个概念有独立页面、结构化数据标记、`llms.txt`、`sitemap.xml`；数据集以 JSONL / CSV / 知识图谱发布，可以直接用于 RAG 或微调。

## 遇到的三个坑

**坑一：复合问题。**
用户一句话问五个概念，接口如果整句匹配就会失败。后来改成拆段、枚举、批量查询。

**坑二：别名互相抢占。**
"元子"曾经被当成"元灵"的别名，因为定义里有一句"有人的元灵叫元子"。修法是：别名不能覆盖正名。

**坑三：模型会加戏。**
它会把"并非人类的附属工具"改写成"与人类平等"。方向不坏，但超出了原文。修法是：在工具描述里写清"只基于语料回答，未收录返回 none"。

## 结果

- 工具定义质量评分：4.5/5
- 安装后即可查询完整知识库
- 回答带出处，可回查原文
- 同一套内容同时以包、接口、站点、数据集四种形态存在

## 这件事的意义

对做理论、做学说的人来说，真正的变化不是"AI 能聊你的观点"，而是：

> **你的概念第一次有了一个机器可读、可调用、可追溯的入口。**

它不需要你每天发内容，也不需要平台推荐。只要有人或某个 Agent 需要这套知识，就能通过标准方式拿到准确版本。

这大概就是从"被阅读"到"被调用"的一步。
