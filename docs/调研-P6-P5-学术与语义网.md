# 调研 P6/P5：学术接入与语义网服务

> 时间：2026-11-17

## P6 学术接入（数字人文、图书馆、博物馆）

### 需求证据（有预算）

| 项目 | 预算/中标 | 采购方 |
|---|---|---|
| 河北博物院古籍数字化与知识图谱应用展示 | 预算 319.89 万，中标 275.69 万 | 河北博物院 |
| 中州文献资源库（玄奘全集 + 地方志 + 禅宗） | 32 万 | 中州古籍出版社 |
| 上海图书馆古籍联合目录及循证平台 | 长期投入 | 上海图书馆 |

- 上图已用关联数据发布古籍本体（BIBFRAME 扩展），并提供 SPARQL 端点；
- 高校图书馆有基于关联数据的延伸服务实践；
- 学界在讨论「古籍数字人文基础设施」。

判断：**需求真实、有预算，但是政府采购/机构项目。**

### 竞争与门槛

- 中标方：北京昆仑文保科技有限公司（博物馆数字化方向）；
- 平台方：上海图书馆、国图、北大图书馆；
- 门槛：投标资质、案例、团队规模、履约能力。

判断：**我们不具备投标资格，也扛不住 300 万级项目的履约。**

### 结论

**P6：D（不作为主承包），C（可作为数据建模/规范顾问的分包）。**

理由：有钱但拿不到；我们的 RDF 与规范能力，只能作为大项目里的一小块。

## P5 语义网服务化（SPARQL、推理、托管图谱）

- 上图已有 SPARQL 端点，可查古籍联合目录；
- ctext 有 API；
- 我们的 TTL 已发布，但查询需求未验证。

判断：**技术不难，需求不明。**

### 结论

**P5：C（暂缓）。** 除非出现「有人要查我们的图」的具体需求，否则不做。

## 合并结论

学术侧的钱在机构项目里，不在小团队手里。我们要么成为分包，要么放弃。
