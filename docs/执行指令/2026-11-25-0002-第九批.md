# 执行指令：`0002` 第九批（2026-11-25，推标签）

> 下达：`0001`｜状态：待转交｜来源：2026-11-25 推 `v0.4.4` 时暴露——`推送标签.cmd` 把标签名写死成 `v0.3.9`；`push-github.ps1` 只会推 `main`

## 我们的指令是

请 `0002` 做两件事，让「推标签」这件事不再靠临时手打命令。

### 一、`deploy/push-github.ps1` 支持推标签

现状：脚本只推 `main`，推标签只能手打 `git push origin <tag>`；而这条直连在 DNS 指向被封 IP 时会 21 秒超时，等于把「筛 IP → 固定 → 还原」这套已经验证过的能力浪费掉。

要的行为：

- 新增参数 `-Tag <name>`：只推这一个标签，走**与推分支完全相同的**「筛 IP → 固定 → 推送 → 复核 → `finally` 还原 hosts」流程，不重复实现任何一套逻辑；
- **默认行为不变**：不带 `-Tag` 时仍是推分支 `main`；
- `-Tag` 与 `-ForcePin` 可以组合使用（`-ForcePin -Tag v0.4.4`）；
- 推送后复核要用**标签对象的 sha**：附注标签的 `refs/tags/<name>` 指向的是 tag 对象，不是 commit，所以要比对 `git rev-parse <name>`（tag 对象 sha）与 `git ls-remote origin refs/tags/<name>`，不要拿 `HEAD` 去比，否则永远不相等；
- 不做 `git push --tags`（一次性推所有标签），只推指定的一个。

### 二、`推送标签.cmd` 不再写死版本号

现状：第 4 行是 `git push origin v0.3.9`，双击只会推一个不存在的标签。

要的行为：

- 支持传参：`推送标签.cmd v0.4.4` → 推该标签；
- 不带参数时，取当前最近的一个标签（`git describe --tags --abbrev=0`）再推；
- **改为调用 `deploy/push-github.ps1 -Tag <name>`**，从而复用固定 IP 的能力；不要自己直接 `git push`；
- 打不出标签（仓库里没有标签）时给出清楚提示，不要静默失败。
