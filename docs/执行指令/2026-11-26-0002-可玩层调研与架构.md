## 三、市场调查：回答六个问题

### A. 需求是否存在

- 谁想要“经历一套学说”，而不是读文章、问 AI？
- 候选人群：大学生/研究生、数字人文与博物馆从业者、哲学爱好者、独立游戏玩家、AI/Agent 开发者、课程教师、文化机构；
- 每个群体：规模感、获取渠道、付费意愿、现有替代品；
- 证据来源：评论、论坛、社群讨论、众筹、课程采购、博物馆项目、平台销量/愿望单、招聘需求；
- 如果找不到证据，写“未找到”，不要用 TAM 数字撑场面。

### B. 直接与间接竞品

最多 **8 个直接竞品 + 8 个间接竞品 + 5 个 AI 工具**，每个不超过 150 字，重点写“它证明了什么 / 没证明什么”。

直接/间接参考方向（不限于）：

- 互动论文/可解释性作品：Explorable Explanations、Nicky Case 的《信任的演化》《多边形寓言》、NYT 互动报道；
- 哲学/思辨游戏：《The Witness》《Outer Wilds》《极乐迪斯科》《天堂的穹顶》《Citizen Sleeper》《The Talos Principle》；
- 中文叙事/文化游戏：《山海旅人》《三伏》《烟火》等（选与“理解一套观念”相关的）；
- 教育模拟：Brilliant、Duolingo、博物馆互动装置、严肃游戏（serious games）；
- AI 原生：Summer Engine、Rosebud、CocosGen、秒哒、Trae/CodeBuddy 的游戏 demo；
- 知识库产品：Wolfram Demonstrations、语义网/知识图谱的可视化探索工具。

对每个竞品**必填三行**（其余从简，不必凑表格）：

| 项 | 内容 |
|---|---|
| 它是什么 | 一句话，含价格与分发方式 |
| 它证明了什么 | 哪种“可玩理解”成立 |
| 它没证明什么 | 哪些仍失败、为什么 |

可选补充（有料才写，一句即可）：谁在用、规模感、对我们的启示。

> `0001` 附注：原设计是六行表格 ×21 个竞品，信息量大部分重复，5 人日内做不完，也超出判断所需。**宁可 21 个竞品各三行写实，不要 6 行表格填满但都是套话。**

### C. 经济模型

给三档预算，全部用人民币，写清假设：

1. **极简 MVP**：3 个微场景、20–30 分钟、网页、无账号、无后端；
2. **标准场景库**：10–20 个场景、可复用运行时、可导出漫画/动画分镜；
3. **完整产品**：商业游戏或动画短片集（只做量级判断，不展开制作）。

每档写：

- 一次性成本：工程、美术、音频、文案、测试、法务/合规；
- 持续成本：托管、域名、AI API、维护；
- 人力：需要什么角色、几个人、几个月；
- 收入可能：买断、课程/工作坊、博物馆/机构授权、免费引流；
- 谁付费、为什么付费、客单价量级；
- 最坏情况亏多少。

**不要**假设订阅制；**不要**把“下载量”当“用户量”；**不要**把“平台收录”当“平台托管”。

### D. 分发路径

比较至少五条：

1. 现有静态站内嵌网页；
2. 独立网页 + 链接分享；
3. Steam（买断）；
4. TapTap / 微信小游戏；
5. B 站/小红书（内容引流）；
6. 博物馆/课堂/工作坊（B2B）。

每条写：第一版适配度、获客成本量级、审核/合规、成功案例、失败案例。

最后回答：**第一版最应该走哪条？为什么？**

### E. 技术工具与成本

- 静态网页（HTML/JS/Canvas）vs 游戏引擎（Godot/Phaser/Cocos）vs AI 原生叙事运行时，各自的能力边界；
- AI 生成美术/音频/视频的可用工具、价格、授权、一致性水平；
- 国内可用性与合规（AI 生成内容标识、肖像权、商用条款）；
- 是否适合 MCP：`mcai_scene_list` / `mcai_scene_start` / `mcai_scene_choose` / `mcai_scene_cite` 是否值得做；
- 不要推荐需要长期订阅或高维护的技术栈。

### F. 风险与反证

主动找“不该做”的证据：

- 教育游戏/严肃游戏常见的失败模式；
- 哲学游戏叫好不叫座的原因；
- AI 生成内容导致的同质化与信任问题；
- 知识库团队做内容产品的机会成本；
- 正典被剧情绑架的风险；
- 作者时间占用（人日）与这件事的可持续性——只算工时，不评价人。

## 四、架构建议：至少三种方案

不要只给一种。至少比较：

### 方案 A：静态场景播放器

- JSON 场景 + 轻量前端；无后端、无账号；
- 优点：最便宜、最快、最可控、易嵌入现有站；
- 缺点：交互浅、难做复杂状态、难商业化；
- 适合：第一版验证“能不能让人懂”。

### 方案 B：游戏引擎路线

- Godot / Phaser / Cocos；可做更丰富的交互与表现；
- 优点：体验上限高、可上 Steam/TapTap；
- 缺点：成本高、周期长、需要游戏设计能力；
- 适合：验证成功后做“完整作品”。

### 方案 C：AI 原生叙事运行时

- LLM + 场景图 + 知识库检索；NPC/旁白可对话；
- 优点：最像“序生智能体”，差异化最强；
- 缺点：幻觉、成本、延迟、评测难、正典风险最高；
- 适合：作为“实验分支”，不作为第一版主干。

对三种方案按同一张表打分：

| 维度 | A | B | C |
|---|---|---|---|
| 首版成本 | | | |
| 首版周期 | | | |
| 体验上限 | | | |
| 正典安全 | | | |
| 可维护性 | | | |
| 分发适配 | | | |
| 商业潜力 | | | |
| 技术风险 | | | |

最后给出：

1. **第一版选哪个，为什么；**
2. **三年后想长成哪个，为什么；**
3. **从 A 到 B/C 的迁移路径，什么时候值得迁移。**

## 五、第一版 MVP 建议（必须具体）

如果结论是“做”或“先做小样”，给出一个可执行的最小版本：

- **场景数**：3 个；
- **时长**：20–30 分钟；
- **形态**：网页，无账号、无后端、无支付；
- **机制**：一个核心机制，不堆玩法；
- **内容**：每个场景一条命题、三条概念关系、结尾回看引证；
- **美术**：极简风格或少量插画，不做 3D；
- **音频**：可选，先不做；
- **团队**：作者（设定裁定）、编辑（场景）、工程（前端）、测试（5–10 人）；
- **成本/时间**：给区间与假设；
- **验收**：完成率、复述率、回看率、下一幕率；加 5–10 个深访；**注意：n≤10 的样本算不出有统计意义的比率，四个指标只作内部方向参考，结论以深访的定性描述为准，不得把 n=8 的百分比写成统计结论**；
- **停止线**：什么情况下不要再加场景。

> **以我们现在的资产、团队和耐心，知识库该不该长出可玩层；如果该，第一步最小到什么程度。**

请按这个标准写。
