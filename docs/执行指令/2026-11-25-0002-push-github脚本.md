> 下达：`0001`｜状态：待转交｜来源：2026-11-25 01:30 两端推送完成后的实测结论

## 我们的指令是

请 `0002` 修 `deploy/push-github.ps1` 两处，并补一个只用于验证的开关。

**第一条：直连 `git push` 失败时，先重试一次，不要立刻抛错。**

2026-11-25 01:28 实测：直连下 `git ls-remote` 能通，`git push` 第一次被 `Recv failure: Connection was reset` 掐断，**同样的命令重试一次即成功**；而脚本当时在直连分支直接 `throw`，把已经能通的通路放弃了。

要的行为：`push` 返回非 0 时，间隔 3 秒重试 1 次；仍非 0 才抛错。抛错前不要动 hosts。

**第二条：把「固定 IP 后等解析生效」这条分支真正走一遍。**

该逻辑 2026-11-25 已写入（`Resolve-DnsName` 轮询最多 6 轮、每轮 0.8 秒，确认解析指向目标 IP 后再连），但当天两次跑通都走了直连路径，**这条分支从未被执行过**。

要的行为：加一个 `-ForcePin` 开关，跳过直连尝试、直接走筛选 IP → 固定 → 推送 → 还原，用来人为验证该分支。默认不加，正常行为不变。

## 我们会核

逐条核，每条给出可看的输出或命令：

1. 直连被掐时脚本不直接退出，日志里能看到「重试」字样，且最终推送成功；
2. `-ForcePin` 能强制走固定 IP 路径，输出里出现「解析已指向 <ip>」，并成功推送；
3. 跑完后 `C:\Windows\System32\drivers\etc\hosts` 不含 `github.com` 映射，`hosts.bak-*` 备份仍在；
4. 脚本仍是 **UTF-8 带 BOM**（`[System.IO.File]::ReadAllBytes($p)[0..2]` 为 `EF BB BF`）——不带 BOM 会被 PowerShell 5.1 按 GBK 读成乱码并报「缺少引号」这类错;
5. `python -m unittest discover -s tests` 仍全部通过（改脚本不应影响测试，但要有这条基线）。

## 边界与约束

- 不加 `--force`，不改「非快进即停」的原则；
- 不改 hosts 的「备份→改→整体覆盖还原」逻辑，也不把还原从 `finally` 里移出；
- 不引入第三方工具或依赖，`git` 与系统自带 `curl.exe` 之外不加东西;
- 不改 `.gitignore`、不动 `data/`、`config/`、不改任何知识库内容；
- 候选 IP 列表可以补充，但不要删掉已有的；顺序上可把近期实测能通的放前面;
- 测试时如果走到固定 IP 路径，必须确认 hosts 已还原，不许留着过夜。

## 停止条件

出现下列任一情况，停下回报，不要自己决定：

- 需要改远端仓库设置、分支保护或凭据；
- 需要管理员以外的系统改动（注册表、防火墙、DNS 服务）；
- hosts 还原失败或发现残留;
- 自测两轮仍无法让 `-ForcePin` 走通（可能是网络当时完全不可达，不是代码问题）。
