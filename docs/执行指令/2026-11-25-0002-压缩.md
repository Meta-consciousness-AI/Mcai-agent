## 我们的指令是

请 `0002` 按 `docs/工作法-上下文压缩.md` 的流程做一次压缩准备：**把记忆从上下文搬到文件，然后等用户执行 `/compact`**。压缩我这边不能触发，你也不需要触发。

### 第一步：清点

读这四份，找出「你上下文里有、但文件里没有」的事实：

```

```

再翻你自己本轮写过的回执（第四批到第九批），确认里面的事都已进文件。

### 第二步：落盘到一份交接文件

新建 `docs/执行回执/2026-11-25-压缩交接.md`，按下列六类写，**每一类都要有，不许省**：

1. **当前状态**：版本号、本机 HEAD、工作树是否干净。
   - SHA 写成「某时刻为 X」，并注明「当前状态以 `git ls-remote` 为准」——不要写「领先 N 个提交」。
2. **本轮做完的事**：一行一件，带提交号（至少覆盖：判据改写、`finally` 三态、`Add-Pin` 修复、`push-gitee` 四处、IndexNow 脚本、`pipeline`/`site` 旧 key 清除、`-Tag` 支持、`推送标签.cmd`、0.4.4 版本准备与版本字段同步）。
3. **未做完 / 待办 / 待定**：写清卡在谁那里（多数是「留用户窗口」）。
4. **本轮推翻或修正过的结论**：至少两条，必须显式写「作废」：
   - 「`Add-Pin` 已生效、只是判据看不到」→ 作废，真相是 hosts 末行无换行导致写入成了注释；
   - 「Bing 零命中、未收录」→ 作废，登录后实测收录 15 页。
5. **本轮新增的规则**：指向 `docs/工作原则.md` 里的条目名即可（凭据不靠剪贴板、回执要短、待办提示以文件为准、Bing 必须登录查），不要重复粘贴全文。
6. **外部等待项**：等什么、回查看什么。

### 第三步：自检三问

在交接文件末尾，只用文件内容（不看上下文）回答：

1. 现在在哪（版本、HEAD、工作树）？
2. 下一步做什么（一项）？
3. 哪些旧结论已作废？

三问答不出，回第二步补写。

### 第四步：写压缩后的第一句话

在交接文件最后，写一段**压缩后你要说的第一句**，按这个模板填空：

```
按 docs/工作法-上下文压缩.md 接续：已读 HANDOFF.md 与 docs/执行回执/2026-11-25-压缩交接.md。
当前：<版本>，本机 <HEAD>，工作树 <干净/有改动>。
下一步：<一句话，一项>。
已作废结论：<一条，写明作废什么、新结论是什么>。
```

然后告诉用户「可以执行 `/compact` 了」。

1. `docs/执行回执/2026-11-25-压缩交接.md` 存在，六类齐全，缺哪类要说明为什么；
