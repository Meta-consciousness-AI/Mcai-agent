现状：判定「hosts 已生效、解析已指向固定 IP」用的是 `Resolve-DnsName github.com -Type A`。该命令取的是 **DNS 客户端的答案，不读 hosts 里刚写进去的那一行**。

2026-11-25 09:42 真实运行（管理员窗口）实测：脚本固定 `20.233.83.145`，判据却连报六轮 `解析尚未生效（20.247.166.64）`，最后打 `解析仍为 20.247.166.64，先试一次（可能仍会失败）`，靠兜底才推成功。那个 `20.247.166.64` 不在候选列表的八个 IP 当中——它来自 DNS，不是我们写进 hosts 的值。**pin 是有效的，验证方法是无效的**：每次白等约五秒（六轮 × 0.8 秒），且打印出来的话会把人引向「解析没生效」的误判。

要的行为：

- 判据改成能真正证明「固定生效」的形式，两条都要满足才打印 `解析已指向 <ip>`：
  1. 从 hosts 文件里读回那一行，确认存在 `<ip> github.com`（用 `$hostsPath` 变量，不要硬编码路径）；
  2. 对 `github.com:443` 做一次真实 TCP 连接（如 `Test-NetConnection -ComputerName github.com -Port 443 -InformationLevel Quiet`，它会走 hosts）。
- 无法确认时，打印的话必须是真的：不要再说「解析尚未生效」这种把 DNS 答案当依据的结论，改成「hosts 已写入，但连接未能确认」之类的如实描述。
- 兜底「先试一次」可以保留——它在 09:42 救了场。

### 二、`finally` 的「hosts 未改动。」文案

多 IP 逐个尝试时，前一个 IP 失败会先 `Undo-Pin`，`finally` 仍然打印「hosts 未改动。」——实际是「改过又还原」，读日志的人会误判成全程没动过 hosts。

要的行为：用状态区分三种情况，各自打印不同的话——

1. 全程没动过 hosts →「hosts 未改动。」
2. 改过、已还原 →「hosts 已还原。」
3. 还原失败 → 明确的失败提示，并且不吞掉异常。

**只改打印，不改还原机制**：备份→整体覆盖还原的逻辑、还原必须留在 `finally`、失败也要还原，这三条一律不动。
