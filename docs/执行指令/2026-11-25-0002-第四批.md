### 一、`tools/submit_indexnow.py`

功能：读 `dist/sitemap.xml` 里的全部 `<loc>`，按 IndexNow 协议一次性提交给 `https://api.indexnow.org/indexnow`。

要点：

- 只用标准库（`urllib.request`、`json`、`xml.etree.ElementTree`），不引入第三方依赖；
- 请求体结构：

  ```json
  {
    "host": "mcai-knowledge-d7gtizltz910e2269-1316838521.tcloudbaseapp.com",
    "key": "<key>",
    "keyLocation": "https://<host>/<key>.txt",
    "urlList": ["<url1>", "<url2>", "..."]
  }
  ```

- 参数：
  - `--dry-run`：只打印将要提交的 URL 数量与首尾各 2 条，不联网；
  - `--write-key`：把 key 写成 `dist/<key>.txt`（内容就是 key 本身，末尾带换行），可重复执行且结果一致；
  - `--endpoint`：可换成其它地址，用于本地验证请求体；
- 输出与退出码：
  - `200` / `202` → 打印成功与提交条数，退出码 0；
  - `403` → 提示「key 校验失败：keyLocation 是否可访问、内容是否与 key 完全一致」；
  - `422` → 提示「URL 不属于该 host」；
  - `429` → 提示「请求过快，稍后再试」；
  - 其它非 2xx → 打印状态码与响应正文前几行，退出码非 0；
- 单次请求的 URL 数上限 10000（本站在 71 条，远未触及），若超出请分批并打印每批条数。

### 二、key 的存放与生成顺序

- key 用 32 位十六进制随机串（IndexNow 允许 `a-z A-Z 0-9 -`，长度 8–128）——**key 是公开信息，不是秘密**，可以入库；
- 建议存 `config/indexnow.json`：`{"key": "..."}`，脚本从那里读；不要把 key 硬编码散落在多处；
- 站点是构建产物，`dist/` 会被重建清掉，所以执行顺序要写进脚本文档字符串与回执：
  1. `python tools/build_site_from_kb.py`
  2. `python tools/submit_indexnow.py --write-key`
  3. `python tools/submit_indexnow.py`（真正提交）
  4. 部署 `dist/`（这一步是用户窗口做的，不归你）
