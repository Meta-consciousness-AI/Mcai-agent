## 我们的指令是

请 `0002` 修 `deploy/push-github.ps1` 的固定 IP 写入，并把演练的前提补对。

### 一、`Add-Pin` 从未生效

事实链（都可在现场复核）：

- 10:28 真实运行（管理员窗口）：`-ForcePin` 筛出 `20.233.83.145` 可用 → `hosts 已备份` → 新判据连报六轮 `hosts 里还没读到 20.233.83.145 github.com` → 兜底推成功（`b3868e3..aa2c1d5`）→ `hosts 已还原`；
- 事后核对 `C:\Windows\System32\drivers\etc\hosts`：822 字节，**最后一行 `#\t::1             localhost` 之后没有换行符**（末字节 `0x74`，即 `t`）；
- `Add-Pin` 是 `Add-Content -LiteralPath $hostsPath -Value "$ip github.com" -Encoding ASCII`。向一个不以换行结尾的文件追加，内容直接接在末行尾部，结果是：

  ```
  #	::1             localhost20.233.83.145 github.com
  ```

  整行以 `#` 开头——**是一行注释**；
- 所以 git 没被固定，判据也读不到（**判据这次说的是真话**，第一批判据没有错，它只是第一次让这件事变得可见）；
- 推论：01:28、09:42、10:28 三次「推成功」实际都走 DNS 当时返回的可连 IP，与固定无关。`-ForcePin` 报告「可用 IP」是真的（TLS 筛选走 `curl --resolve`，不经 hosts），但固定不上。

要的行为：

- 写入前先判断 hosts 是否以换行（`\n`）结尾；不是就先补一个 `CRLF`，再追加 `<ip> github.com`；
- 写完后自己回读一次，确认 `Test-HostsPin` 能读到该行，读不到就抛错；
- 「备份 → 改 → 整体覆盖还原」与「还原留在 `finally`」一律不动；
- 写入失败仍抛错。

### 二、演练必须复现这个前提

上一批演练用的是临时 hosts 文件，那份文件以换行结尾，所以正例通过、真相被掩盖。这次要求：

1. 正例的临时 hosts **末行必须无换行**，内容尽量贴近系统默认（末行为 `#\t::1             localhost`），并贴出该文件的末几个字节作为证据；
2. 若修法成立，正例应打印 `解析已指向 <ip>（hosts 已写入，443 可连）` 并推送成功；
3. 再加一个反例：**用改动前的旧 `Add-Pin` 打同一个文件**，确认不打印该句——证明这次演练确实能抓到这个缺陷（而不是换个理想输入又通过一遍）；
4. 演练说明里写清这条前提：「输入文件末行可能没有换行」，别再用理想化的输入。
