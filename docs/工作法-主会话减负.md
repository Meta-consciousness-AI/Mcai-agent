# 工作法：主会话减负

> 建立：2026-11-22
> 目的：让 `mcai-knowledge` 主会话保持轻量，随时能接重大问题。

## 一、三层分工

| 层 | 谁 | 做什么 |
|---|---|---|
| 主会话 | `mcai-knowledge` | 重大问题、跨领域决策、最终定稿、方向判断 |
| 专项会话 | `mcai-knowledge-platform` / `content` / `release` / `search` | 平台操作、内容审校、发布执行、搜索跟进 |
| 文件 | `HANDOFF.md` / `docs/` | 长期记忆、状态、原则、记录 |

主会话不承担长执行，专项会话不承担方向决策。

## 二、主会话里应该留什么

- 需要跨领域权衡的问题；
- 会影响后续方向的决定；
- 对外口径、原则、边界；
- 对专项会话结果的最终裁定。

## 三、主会话里不应该留什么

- 平台控制台一步步操作；
- 批量审校的逐条细节；
- 发布部署的完整命令流水；
- 长篇定义、长表格、长日志；
- 已经结案的调查过程。

这些放文件或专项会话。

## 五、主会话减负动作

每个阶段结束时：

1. 用三句话写清：做了什么、定了什么、下一步；
2. 更新 `HANDOFF.md`；
3. 明细移入 `docs/`；
4. 执行类工作交给专项会话；
5. 主会话只保留方向与裁定。

## 六、主会话恢复包

如果主会话上下文变轻或换新主会话，按顺序读：

1. `HANDOFF.md`
2. `docs/待办.md`
3. `docs/工作原则.md`
4. `docs/工作法-会话管理.md`
5. 涉及内容时再读 `docs/审校/审校标准-问答与关系.md`

## 七、判断口诀

> 方向留主会话，执行去专项，细节进文件。
> 主会话只记“为什么”，文件记“是什么”，专项会话做“怎么做”。

## 八、会话治理

- 专项会话的设立、命名、范围、边界，由主会话决定；
- 专项会话不自行开新会话；确有需要，回报主会话定名；
- 专项会话只做范围内的事，不扩权；
- 会话清单见 `docs/会话台账.md`；
- 主会话只做重大问题、方向决策与最终裁定，不做执行。
