# 调研计划：核验器 C+D

> 依据：《工作原则》「先穷尽调研，再定动作」。
> 目的：在写架构之前，看清这条路谁走过、怎么走的、哪里翻车。
> 产出：一页研判 v2 + 一个明确动作。

## 一、要回答的问题

1. 已经有哪些机构在做「引文忠实度核验」？
2. 学界给出的指标与协议，是否已成事实标准？
3. 有人尝试过做标准或基准吗？为什么没成？
4. 出版社/期刊现在怎么采购这类工具？预算从哪来？
5. 我们的 C+D 路线，和已有玩家是互补还是正面冲突？

## 二、四张图

### 图 1：谁在做

- 学术项目：ALCE、CiteEval、AtomCite、DocCite 等基准；
- 商业产品：Edifix、RefChecker、CoChat、WPS 黑马；
- 出版社自建：STM Integrity Hub、各社编辑部工具；
- 开源项目：引用校验、参考管理插件。

要求：每个列「做什么、覆盖到哪、缺什么」。

### 图 2：学术与标准

- 引文忠实度的指标定义（ALCE 的 correctness/citation quality）；
- 验证协议（gold-anchored、conformal guard）；
- 标准草案（NISO CREC、C2PA、VC）；
- 中文语境下的研究（古籍引文、编辑校对）。

要求：能画出「指标—协议—标准」的层次图。

### 图 3：失败与坑

- 有没有公司做过引文核验后停掉？为什么？
- 基准类项目为什么多数停在论文，没有变成服务？
- 出版社采购工具的真实门槛（合规、预算、流程）。

要求：至少 3 个失败或受挫案例，写清原因。

### 图 4：市场与合规

- 中国出版社/期刊的数字化预算与采购路径；
- 数据合规：书稿保密、扫描件版权；
- 竞品定价与交付方式。

要求：给出「谁付钱、怎么付、付多少」的初步答案。

## 三、来源要求

- 总数 ≥ 20 个可核查来源；
- 学术 ≥ 8 篇（含 2024–2026）；
- 产品/机构 ≥ 6 个；
- 失败案例 ≥ 3 个；
- 中文来源不少于 5 个。

## 四、产出

`docs/研判-核验器-调研v2.md`，包含：

1. 赛道图（四段，谁强谁弱）；
2. 标准与指标现状；
3. 失败案例与教训；
4. 三个可选动作（含我们 C+D）；
5. 唯一推荐动作与理由；
6. 不确定性与复盘点。

## 五、时间

- 3–5 天完成检索与整理；
- 完成后先内部评审，再决定是否进入规范写作。

## 六、不做的事

- 不写架构；
- 不写代码；
- 不联系客户；
- 不对外发布。
