# 工作法：线上获客系统

> 目标：把「找客户、写邮件、跟进、复盘」做成可重复的日常流程。
> 原则：少而准，人工确认，不群发。

## 一、系统分层

```
采集（人工 + 检索）
   ↓
名单（data/prospects.jsonl）
   ↓
筛选（类型、引文密度、联系方式）
   ↓
草稿（模板 + 个性化）
   ↓
人工发送（今天用邮箱客户端）
   ↓
跟进（状态机）
   ↓
统计（回复率、试点数）
```

## 二、现在的实现

`tools/prospect.py`：

```bash
# 加一家
python tools/prospect.py add --name "某出版社" --type 出版社 --city 北京 \
  --url https://example.com --email edit@example.com --book "《某书》"

# 看名单
python tools/prospect.py list
python tools/prospect.py list --status new

# 生成邮件草稿
python tools/prospect.py draft --id p-xxxxxx

# 改状态
python tools/prospect.py status --id p-xxxxxx --to sent
python tools/prospect.py status --id p-xxxxxx --to replied --note "编辑回复，想看书稿样例"

# 漏斗
python tools/prospect.py stats
```

状态：`new → queued → sent → replied → pilot`，异常为 `rejected`、`bounced`。

数据在 `data/prospects.jsonl`，本地保存，不入库（含联系人信息）。

## 三、阶段计划

| 阶段 | 做什么 | 现在的状态 |
|---|---|---|
| 1 | 手工录入 + 草稿 + 统计 | 已可用 |
| 2 | 检索辅助：按关键词/地区找官网与邮箱 | 待做 |
| 3 | 发送与退信跟踪（SMTP，限速） | 待做 |
| 4 | 回复分类与自动跟进提醒 | 待做 |

每一阶段先跑通再往上加，不一次做全。

## 四、合规

- 不发垃圾邮件，一次 5–10 封；
- 每封人工改写第一段；
- 有真实署名与联系方式；
- 提供不再联系选项；
- 不用爬虫批量抓邮箱。

## 五、指标

| 指标 | 首月目标 |
|---|---|
| 名单 | 30 家 |
| 发出 | 30 封 |
| 回复率 | ≥15% |
| 试点意向 | ≥2 |
| 实际试点 | 1 |
