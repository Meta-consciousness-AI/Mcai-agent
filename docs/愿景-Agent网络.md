# 愿景：Agent 网络

> 性质：北极星，不是任务，不排期。
> 记录时间：2026-11-14

## 终局

主体工作从「人做事」变成「人组织 Agent」：

```
战略雷达（感知）
   ↓
规划与评估（判断）
   ↓
执行终端（写作、发布、部署、验证）
   ↓
反馈回雷达
```

形成一个从感知到执行的 Agent 网络，人只做三件事：定方向、做判断、担责任。

## 现在到终局的阶梯

| 阶段 | 特征 | 我们已有什么 |
|---|---|---|
| 1. 工具化 | 每件事变成可复用的命令/脚本 | `mcai all`、`mcai-verify`、发布脚本 |
| 2. 半自动 | 人定流程，脚本执行，人审阅 | 每日信号、综合参考整理 |
| 3. 编排 | Agent 之间传递任务与结果 | 尚未开始 |
| 4. 网络 | 感知、判断、执行自动闭环 | 愿景 |

## 一个必要的顺序

**先把每件事做成「可被调用的单元」，再谈网络。**

- 没有验证器，Agent 产出的内容不可信；
- 没有评测基准，Agent 的质量无法比较；
- 没有统一 CLI，Agent 无法调用彼此；
- 没有触发条件表，Agent 不知道该做什么。

所以现在的 P1–P5、T11，本质上都是在造「网络里的节点」。

## 不做什么

- 不为了「像未来」而提前搭编排框架；
- 不在单个节点还不稳定时做网络；
- 不把愿景写进季度计划。

## 触发条件

出现以下情况时，开始设计编排层：

1. 至少 5 个稳定的可调用单元（命令或 Agent）；
2. 人工在单元之间搬运任务的耗时超过总工时 30%；
3. 有一个真实的、重复的跨单元流程需要每天跑。

## 一句话

**Agent 网络不是搭出来的，是长出来的——每个节点先能独立工作，网络才有意义。**
