# 一个原创学说，怎么变成 AI 能调用的资产

一套自己写的学说，怎么让 AI 不只是「听说过」，而是每次都能查到准确的版本？

这件事我们做了六个月，下面是把过程拆开的样子。每一步都留下可查的东西，不靠自述。

## 一、先把学说固化成术语表

学说是连续的论述，AI 需要的是离散的、可定位的条目。

我们把它拆成：

- 64 个术语；
- 122 组标准问答；
- 270 条术语之间的关系。

每个术语有唯一标识、英文名、分类、简短定义、完整定义、别名、上下位关系。

这一步不难，难的是**克制**：只收学说里已经确定的用法，不临时发挥，不把解释写成定义。

## 二、每条定义绑定出处

术语表最容易出的问题是：读者不知道这句话是原文，还是整理者的理解。

我们的做法：

- 每条定义标记类型：原文、编者归纳、待定；
- 原文类定义保留文档、章节、原句、版本；
- 编者注单独字段存放，不混进定义正文。

这就是「字符级溯源」的实际含义：不是口号，是字段结构决定的。

## 三、做成 AI 可调用的知识包

有了结构化数据，下一步是让 AI 能调用。

我们把它做成 MCP 服务器，提供 5 个工具：

| 工具 | 作用 |
|---|---|
| `mcai_answer` | 回答完整问题，带出处 |
| `mcai_concept` | 查单个术语的完整条目 |
| `mcai_search` | 按关键词检索 |
| `mcai_related` | 查术语关系 |
| `mcai_list` | 列出全部术语 |

同时给了一个关键约定：**问题超出知识库时，返回 `type='none'`，不编造**。

这一条比多给几个工具重要。知识库的价值不是「什么都能答」，是「答不了的明确说答不了」。

## 四、分发到 AI 能找到的地方

知识包做完，如果只放在硬盘里，等于没做。

我们把它发布到：

- PyPI：`pip install mcai-knowledge`，当前 0.3.5；
- MCP 官方注册表：`io.github.Meta-consciousness-AI/mcai-knowledge`；
- Glama 目录：Discovery 评分 92%；
- mcprush：已认领，Grade A；
- 自建站点：70 个页面，术语、问答、数据集都可直接浏览。

这一步的意义是：任何人、任何 AI 客户端，都能用标准方式接入，不需要认识我们。

## 五、做学术存证

软件包的版本会变，链接会失效，所以还需要一个不随项目变动的地方。

我们做了：

- 数据集 DOI：`10.5281/zenodo.23789330`；
- 预印本 DOI：`10.5281/zenodo.23830600`；
- 规范文档 DOI：`10.5281/zenodo.23850554`；
- PhilArchive 收录：`philarchive.org/rec/MCAKAO`；
- OpenAIRE 已索引。

这些编号的作用不是好看，是让「某年某月这一版是什么样」可以被独立引用。

## 六、去作者化

一套学说容易变成「作者说了算」。要让它能被长期调用，必须反过来：

- 引用指向标准词表，不指向某个人；
- 术语有稳定标识，换作者不影响检索；
- 编者判断有独立字段，不冒充原文。

去作者化不是抹掉作者，是让资产在作者不在场时仍然可用。

## 七、现在到哪一步

诚实地说：

- 资产做完了，分发做完了，存证做完了；
- 真实业务调用还是 0；
- Zenodo 累计浏览 146、下载 18；
- GitHub 0 Star。

也就是说，**链路通了，但还没有人真的用起来**。

这是下一步要解决的问题，不是靠再写一篇文章能解决的。

## 八、这件事的结构

回头看，这套东西由四层构成：

```
学说 → 术语纪律 → 知识包 → 分发与存证
```

单层都不新鲜。难的是四层用同一套标准串起来：

- 术语表要能被机器读；
- 知识包要能被 AI 调；
- 分发要能被索引；
- 存证要能被引用。

任何一层偷懒，后面都会塌。

## 九、一句话

**知识资产的调用，不是让 AI 记住一套学说，而是让它每次都能查到准确的版本。**
