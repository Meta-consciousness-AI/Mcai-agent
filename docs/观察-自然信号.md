## 魔搭 MCP 指标口径（2026-11-16）

从详情页 JSON 读到：

```
CallVolume: 0
ViewCount: 14
```

- 卡片上的 👁 数字是**浏览量**，不是安装量或调用量；
- `CallVolume` 是魔搭网关统计的调用，0 表示没有经过它网关的调用；
- 用户本地 `uvx` 运行不会计入；
- 14 次浏览里包含我们自己的多次访问。

结论：魔搭的 11/14 不能证明有人装过，也不能证明没人装过；目前没有任何渠道能证明存在真实用户。

## 每日信号脚本 v2（2026-11-18）

### 为什么改

旧版失败率高，且只显示异常类型（HTTPError / URLError），无法判断原因。实测确认：

- Zenodo：并发请求触发 403 限流；
- GitHub：网页版超时，但 api.github.com 正常；
- CloudBase：冷启动时首个请求超时；
- 本机 PowerShell/curl 走 schannel 取不到证书，但 Python/OpenSSL 正常。

### 改了什么

1. 错误显示 HTTP 状态码，区分「限流 / 服务端错误 / 超时 / 连接失败」；
2. 403、429、5xx 与超时按指数退避重试；
3. GitHub 改用 api.github.com；
4. Zenodo 串行执行，间隔 1.2 秒；
5. CloudBase 健康检查超时放宽到 90 秒；
6. 失败时显示上次成功值（data/signal_last.json），趋势不中断；
7. 新增 `--only`、`--verbose`、`--no-cache`。

### 实测

2026-11-18 首次运行：11 项全部成功，无失败。
