# 发现工作计划

> 目标：让 AI / Agent 更容易找到并调用知识库，不做人类内容营销。
> 原则：每天 20–30 分钟，只做可验证的动作；用完即止，不挤占构建与复现时间。

## 每日节奏

| 星期 | 当日动作 | 预计 |
|---|---|---|
| 周一 | 跑指标脚本，记录趋势（已有 09:00 提醒） | 20 分钟 |
| 周二 | 检查一个 MCP 目录：注册表 / Glama / PulseMCP / mcp.so / Smithery | 15 分钟 |
| 周三 | IndexNow 提交（有页面更新时）+ Bing `site:` 抽查 | 10 分钟 |
| 周四 | PyPI / 注册表的关键词与描述是否仍准确 | 10 分钟 |
| 周五 | 搜索第三方提及（DOI、项目名、包名） | 10 分钟 |
| 周六 | 数据集同步：Zenodo / ModelScope 是否落后于最新构建 | 20 分钟 |
| 周日 | 不做发现工作，留白 | — |

## 每月

- 汇总各渠道的下载、Star、提及，判断哪个渠道真的带来取用；
- 对连续两个月零效果的渠道，降级或停止投入；
- 新增渠道一次只加一个，观察两周再决定是否保留。

## 内容发布惯例（自 2026-11 起）

公众号、知乎等平台的每一篇技术文章，在文末或文中合适位置固定放置：

- 智能体直达链接：`https://www.coze.cn/store/agent/7702301472461242409?bot_id=true`
- 或对应的二维码

理由：读者多数不会去装包或打开 GitHub，但可能愿意点一下直接用。这是「零安装入口」，不替代机器渠道，只补上转化动作。

## 构建者渠道（两周观察）

2026-11 起先试 PulseMCP 提交，观察两周内是否带来 Star、MCP 调用或第三方提及；无变化则换下一家，不叠加投入。

## 判断标准

发现工作是否有效，只看三个硬信号：

1. Zenodo / ModelScope 是否出现**下载**（不是浏览）；
2. GitHub 是否出现 Star 或 Fork；
3. 是否出现第三方引用或提及。

没有变化时，不追加投入，也不改结论。
