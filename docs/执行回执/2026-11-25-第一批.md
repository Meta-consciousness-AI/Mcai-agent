## 二、`finally` 三态

| 状态 | 触发条件 | 文案 | 演练 |
|---|---|---|---|
| 一 | 全程没动过 hosts | `hosts 未改动。` | 演练 C |
| 二 | 改过、已还原 | `hosts 已还原（备份 … 可删）` | 演练 A / B |
| 三 | 还原失败 | `⚠ hosts 还原失败：<异常>` ＋手工还原命令，随后 `throw` | 演练 D |

实现（第 313–336 行）：`$pinned` 改成 `$touched`，**只在 `Add-Pin` 成功后置真、循环里失败换 IP 时不再重置**（原来 `$pinned = $false` 正是误报「未改动」的根源，已删）。还原仍是 `Undo-Pin` → `Copy-Item -Force` 整体覆盖；仍在 `finally`；失败时先打印再 `throw`，不吞异常。

状态一在正常路径下已几乎不可达（进入 `try` 后第一个 IP 必然写 hosts），只有「写 hosts 本身失败」时才会出现——演练 C 即用这种故障触发的。

## 四、演练的替代点（沙箱限制，逐条列出）

沙箱内：`git ls-remote https://github.com` 报 `schannel: SEC_E_NO_CREDENTIALS`；本地路径 remote 也报 `sh.exe: couldn't create signal pipe, Win32 error 5`（管道被禁）；写 hosts 需管理员（当前非管理员）。因此演练副本替换了 5 处，其余与生产文件逐行相同：

1. 权限门 `if (-not $CheckOnly -and -not (Test-Elevated))` → `if ($false)`；
2. `Test-Tls` 开头加 `if ($env:MCAI_DRILL -eq '1') { return $true }`（TLS 探测在沙箱里必然失败）；
3. `$hostsPath` → 工作区临时文件（绕开管理员）；
4. `Add-Pin` 开头加 `MCAI_DRILL_PINFAIL` / `MCAI_DRILL_NOPIN` 两个钩子（造状态一、造反例）；
5. `Undo-Pin` 开头加 `MCAI_DRILL_RESTORE_FAIL` 钩子（造状态三）。

未替换的部分：`Test-HostsPin` 真读文件、`Test-GithubTcp` **真连 github.com:443**（沙箱里 TCP 可通，本次实测 `tcp-connected=True`）、推送重试、三态文案、还原与备份。

**未验证**：真实网络下的整链推送（需要用户窗口，且 09:42 已跑通过一次；改动只涉及判据与文案，不涉及网络层）。
