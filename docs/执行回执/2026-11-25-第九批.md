## 一、`-Tag` 怎么实现的（没有复制一套流程）

只引入三个变量，其余（`Get-RemoteSha`、`Invoke-Push`、`Test-Tls`、`Add-Pin`、`Undo-Pin`、三态 `finally`）全部原样复用：

| 变量 | 推分支 | 推标签 |
|---|---|---|
| `$refSpec`（推哪个 ref） | `main` | `refs/tags/<tag>` |
| `$refRemote`（查哪个 ref） | `refs/heads/main` | `refs/tags/<tag>` |
| `$targetSha`（拿谁的 sha 比） | `HEAD` | 标签对象的 sha |

- L46–58：按 `-Tag` 选这三样；
- L126–141 `Get-RemoteSha`：`ls-remote $remote $refRemote`（原来写死 `refs/heads/$branch`）；
- L163–181 `Invoke-Push`：`push $remote $refSpec`，重试逻辑不变；
- L143–160 新增 `Get-LocalTagSha`：`git rev-parse --verify refs/tags/<name>`；
- L200–215：标签模式下取 `$targetSha`，取不到就抛「本地没有标签 X」；
- 三处比对（L240、L250、L350、L358）全部改成比 `$targetSha`；
- 结尾 L395 打印 `完成：origin/<ref> = <sha>（标签 X）`，并提示没有创建 Release。

## 二、为什么复核要比 tag 对象 sha

附注标签的 `refs/tags/<name>` 指向的是 **tag 对象**，不是 commit。本机实测：

```
git rev-parse v0.4.4          = e7b9442…（tag 对象）
git rev-parse HEAD            = fccdec3…（commit）
```

所以 `ls-remote origin refs/tags/v0.4.4` 永远不会等于 `HEAD`——拿 `HEAD` 比会把每次都判成「复核不一致」。脚本现在比的是 `git rev-parse --verify refs/tags/<tag>` 与 `ls-remote` 的返回值（轻量标签两者都是 commit sha，同样成立）。

## 三、`推送标签.cmd` 全文（已无任何版本号）

```bat
@echo off
chcp 65001 >nul
setlocal
cd /d "%~dp0"

rem Usage:  this .cmd <tag-name>
rem Without an argument, push the most recent tag (git describe --tags --abbrev=0).
rem The real work (IP pinning, hosts backup/restore, verification) is in
rem deploy\push-github.ps1 -Tag, so this file never calls git push directly.

set "TAG=%~1"
if not "%TAG%"=="" goto have_tag

rem Note: --abbrev=0 must be quoted inside for /f, otherwise cmd splits it at "="
rem and git reports "Not a valid object name 0".
for /f "delims=" %%t in ('git describe --tags "--abbrev=0" 2^>nul') do set "TAG=%%t"
if "%TAG%"=="" (
    echo.
    echo No tag found in this repository.
    echo Create one first, for example:  git tag -a ^<tag^> -m "release message"
    echo.
    pause
    exit /b 1
)

:have_tag
echo Pushing tag %TAG% to GitHub...
echo.
powershell -NoProfile -ExecutionPolicy Bypass -File "%~dp0deploy\push-github.ps1" -Tag "%TAG%"
if errorlevel 1 (
    echo.
    echo Push failed. If it asks for administrator rights, rerun this from an
    echo elevated PowerShell window; otherwise check the tag name and network.
) else (
    echo.
    echo Tag pushed. Next: create a GitHub Release from this tag in the web UI.
)
pause
```

踩到的坑：`for /f ('git describe --tags --abbrev=0')` 里 cmd 会在 `=` 处切断参数，git 报 `Not a valid object name 0`；把选项写成 `"--abbrev=0"` 即正常（实测：本仓库取到 `v0.4.4`，无标签的临时仓库取到空串并走报错分支）。

真实运行（非管理员，停在权限检查）：

```
Pushing tag v0.4.4 to GitHub...
本机标签 v0.4.4：e7b9442
远端：origin/refs/tags/v0.4.4
改 hosts 需要管理员权限。请用管理员 PowerShell 重跑：…
```

带 `v0.4.0` 参数也正确取到该标签（`96ab8bd`），证明没有写死任何版本。
