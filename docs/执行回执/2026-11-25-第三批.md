## 二、六条核定

### 1. 令牌来源与形状校验

正常（32 位十六进制，来自凭据库）：

```
令牌来源：凭据库  len=32 shape=OK
推送到 Gitee：Meta-consciousness-AI/Mcai-agent ...

✅ 已推送到 Gitee，远端 master = 1111111（与本机一致）
A exit=0
```

明显不是令牌（把「那两行命令」当令牌放进凭据库）：

```
令牌来源：凭据库  len=96 shape=不对
这不像令牌（Gitee 私人令牌应为 32 位十六进制）。可能是剪贴板里放的是别的内容；已停止，未连接远端。
B exit=1
B state-file-created=False        ← 假 git 一次都没被调用，确实没去连远端
```

真实凭据库的核对（**只报长度与形状，不打印内容**）：`file len=32 shapeOK=True`——即真实文件会走 `shape=OK` 分支。

### 2. 失败时打印 git 原话

用假 git 模拟认证失败（它把收到的 URL 原样回显，正好当泄漏源）：

```
令牌来源：凭据库  len=32 shape=OK
推送到 Gitee：Meta-consciousness-AI/Mcai-agent ...
git 原话：
  remote: Invalid username or password.
  fatal: Authentication failed for 'https://oauth2:***@gitee.com/Meta-consciousness-AI/Mcai-agent.git'
  error: failed to push some refs to 'https://oauth2:***@gitee.com/Meta-consciousness-AI/Mcai-agent.git'
C exit=1
```

不再是只有一句通用文案。

### 3. 令牌脱敏（前后对照）

**脱敏前**（假 git 直接吐出的原话）：

```
fatal: Authentication failed for 'https://oauth2:0123456789abcdef0123456789abcdef@gitee.com/Meta-consciousness-AI/Mcai-agent.git'
```

**脱敏后**（脚本打印的同一行）：

```
fatal: Authentication failed for 'https://oauth2:***@gitee.com/Meta-consciousness-AI/Mcai-agent.git'
```

自动核对：`token-in-output=False`、`masked-count=2`（那 3 行里有 2 行带 URL，都被换掉）。整段演练输出里**没有出现令牌明文**。

补充：成功推送时脚本**不打印** `git push` 的输出（只打印复核结果），所以 `To https://oauth2:…` 那类行也不会漏出来。

### 4. 推送后复核

假 git 让 `ls-remote` 返回另一个 sha：

```
令牌来源：凭据库  len=32 shape=OK
推送到 Gitee：Meta-consciousness-AI/Mcai-agent ...
推送后复核不一致：远端 3333333333333333333333333333333333333333，本机 1111111111111111111111111111111111111111
D exit=1
```

正向：`✅ 已推送到 Gitee，远端 master = 1111111（与本机一致）`（见 §1 A 例）。
