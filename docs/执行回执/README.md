# 执行回执（`0002` 及后续执行会话写入）

> 目的：主会话（`0001`）看不到执行会话的对话，只能读工作区文件。执行结果必须**落盘**，否则等于没发生。

## 规则

1. 每次执行任务，在 `docs/执行回执/` 下新建一个文件，命名 `YYYY-MM-DD-HHmm-<任务简称>.md`；
2. 回执必须包含五段（缺一不算完成）：
   - **做了什么**：命令、访问的 URL、读写的文件；
   - **看到的**：版本号、数字、页面原文摘录（外部信息一律带 URL；数字要能回到页面）；
   - **结论**：一两句，不写推断当事实；
   - **卡点**：哪一步没做成、为什么、停在哪里；
   - **未完成**：需要下一轮或其他会话接着做的事。
3. 只写事实与结论，不写过程流水账；回执控制在 40 行内；
4. 回执本身**不提交 git**（`0001` 判读后再决定是否入库或并入 HANDOFF）；
5. 关键事实由 `0001` 摘入 `HANDOFF.md`，回执保留为原始记录。

## 为什么不用聊天汇报

- 主会话无法读取其他会话的上下文；贴图、贴输出都会在会话切换后消失；
- 文件可以被 grep、被 diff、被下个会话读到，也可回溯“当时看到的原文是什么”。
