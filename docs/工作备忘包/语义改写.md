# 语义改写：问题与结论

> 记录时间：2026-11-13
> 状态：暂不解决，保留评测层

## 一、问题

用户提问常常不出现知识库里的词：

| 提问 | 库里对应的概念 |
|---|---|
| 世界的源头是什么？ | 元意识（本源） |
| 没人看的时候，事物还存在吗？ | 观测创造实在 |
| 知识能当钱用会怎样？ | 元知社会 |

按字面匹配无法命中，回答会退化成「相关词条」，没有出处。

## 二、做过的尝试

### 尝试 1：按定义原文匹配（已上线 0.3.7）

- 方法：提问与定义做最长公共片段匹配；
- 结果：抽取式改写（含原句）100%，真正语义改写 0%。

### 尝试 2：同义词表 + 语义线索短语（未采用）

- 方法：`config/synonyms.json` 做口语替换；`config/semantic_cues.json` 给每个概念配口语线索；
- 结果：
  - 参与调词的 10 题：100%；
  - 未参与调词的留出题 5 题：**20%**（且 1 题误答成别的概念）；
- 结论：本质是背题，不能泛化，已回退代码，文件留存在 `docs/实验/语义改写/`。

## 三、为什么不上向量

1. 语义改写的说法空间几乎无限，词表与规则都覆盖不全；
2. 真要全覆盖，等于做一个小型语言模型，超出我们的定位与成本；
3. 向量模型也只是「更宽的覆盖」，同样不保证全中，还会带来体积、阈值、可解释性问题；
4. 我们的核心价值在**准确、可核验**，不在「什么都能答」。

## 四、当前决定

- 暂不引入向量模型；
- 不改检索策略；
- 保留 semantic 与 semantic-heldout 两层评测题，作为以后方案的对照基线；
- 语义改写的问题记录在案，等条件成熟再处理。

## 五、什么时候重新考虑

出现以下任一信号时，再拿出来评估：

1. 真实日志里「换说法」的未命中占比明显上升；
2. 有用户明确反馈「问法不被理解」；
3. 出现轻量、可离线、易集成的中文向量方案（体积与依赖可接受）；
4. 我们有余力做「候选召回 + 引文验证」的两段式检索。
