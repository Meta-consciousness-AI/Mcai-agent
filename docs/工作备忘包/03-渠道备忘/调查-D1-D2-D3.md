# 调查：D1 SPARQL / D2 HuggingFace / D3 学术图谱

> 时间：2026-11-14
> 结论先说：三项都**暂不投入**，各有明确理由与替代方案。

## D1：SPARQL 查询服务

### 需求侧

- 会查 SPARQL 的主要是语义网与数字人文研究者，人数少；
- 中文古籍领域的实际入口是 **ctext.org 的文本 API**（按 URN 取原文、检索），不是 SPARQL；
- 未检索到面向中文经典的公开 SPARQL 端点；
- 学术侧已有 ClaOnto（Heritage Science, 2024）以《道德经》为案例做本体与知识图谱，说明学界自己做本体，不依赖外部端点。

### 供给侧（依赖）

- 本环境 `pip install rdflib` 持续挂起，无法安装；
- 没有 rdflib 就没有现成的 SPARQL 引擎，自研不现实；
- 外部三库（如 GraphDB、Virtuoso）需要账号、部署与费用，违背「不订阅」原则。

### 判断

- **不做完整 SPARQL 端点**；
- 替代方案：写一份「查询手册」（10 条常见 SPARQL 查询 + 预期结果 JSON），成本半天，证明数据可用，不承担运行成本；
- 触发条件：出现真实的 SPARQL 查询需求，或依赖问题解决。

## D2：HuggingFace 渠道

### 规则

- 单文件上限 500GB，单目录 <1 万文件，格式建议 Parquet/CSV/JSON；
- 需要账号；公共数据集免费；
- 中国大陆直连 huggingface.co 不可用，镜像 hf-mirror.com 可用。

### 竞争

- 镜像站检索「daodejing」只有 1 个数据集，下载量很低；
- 说明该品类在 HF 上几乎没有供给，也几乎没有需求。

### 判断

- **暂不上传**；
- 理由：受众与 PyPI/MCP 高度重叠，上传后还要长期维护同步，收益不明；
- 若要做，只做一次性镜像：v1.2 的 JSONL + 数据集卡，注明不再更新；
- 触发条件：有开发者明确说「在 HF 上找不到」。

## D3：学术图谱接入 Demo

### 受众

- 数字人文团队确实用 Neo4j / Jena / Obsidian，但他们通常自建本体（如 ClaOnto）；
- 我们的差异点是**引文级溯源 + MCP 调用**，不是又一个本体；
- 没有证据表明有人会为了导入我们的 TTL 而专门用 Neo4j。

### 判断

- **暂不做完整 Demo**；
- 替代方案：在文档里加一节「如何导入 Jena / Neo4j」，10 行命令，成本极低；
- 触发条件：有人问「怎么导入图谱」。

## 三项的共同结论

| 项 | 决定 | 替代 | 触发条件 |
|---|---|---|---|
| D1 SPARQL | 不做 | 查询手册 | 真实查询需求 |
| D2 HuggingFace | 暂不上传 | 一次性镜像 | 有人明确要找 |
| D3 学术 Demo | 暂不做 | 导入说明 | 有人问怎么导入 |

## 一个额外发现

ctext.org 的 API 是中文古籍事实上的入口。如果以后要做「经典 + 学说」的联动，**把引文对上 ctext 的 URN** 比自建 SPARQL 更有价值。
