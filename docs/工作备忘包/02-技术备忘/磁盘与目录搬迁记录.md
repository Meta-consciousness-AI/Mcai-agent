# 磁盘与目录搬迁记录（本机，2026-11-25）

> 性质：本机维护，不是项目内容。目的是让以后的会话看到「联接」时不会误判成垃圾目录。
> 结论一句话：没有调整分区，只做了三处搬家；C 盘空闲 30.0GB → 37.4GB。

## 一、为什么没调分区

C 107GB / 空闲 30GB（28%），偏紧但不告警。重新分区要压缩相邻的 D，中途失败会损坏分区表、整盘受影响，恢复以半天计；而同样十几 GB 用「搬家」就能拿到，风险接近于零。**Windows 也没有跨盘共享空间的机制**，所谓「D/E 借给 C」只能靠搬家 + 目录联接实现。

判断线：C 盘空闲**低于 15GB，或系统更新失败**时再考虑更彻底的办法。

## 二、搬了什么

| # | 对象 | 原位置 | 现位置 | 方式 | 回收 |
|---|---|---|---|---|---|
| 1 | 微信存储 | `C:\Users\HP\Documents\xwechat_files` | `E:\WeChatData` | 应用内「存储位置→更改」，旧目录自动清空 | ~0.3GB |
| 2 | 剪映缓存 | `C:\Users\HP\AppData\Local\JianyingPro` | 原地（应用内清缓存） | 剪映设置里清缓存；草稿位置可另行改到 `D:\JianyingDrafts` | ~2.9GB（6.7→3.8） |
| 3 | 豆包 | `C:\Users\HP\AppData\Local\Doubao` | **`D:\Doubao`（联接）** | 复制 → 校验 → 删原件 → `mklink /J` | ~5.9GB |

结果：C 30.0 → **37.4GB**，D 31.3 → 25.3GB，E 31.4 → 31.5GB。豆包已实测可正常启动、历史对话在位。

## 三、唯一使用联接的目录（重点）

```
C:\Users\HP\AppData\Local\Doubao   （Junction）
        └── 真身：D:\Doubao        21639 个文件 / 5.94GB
```

- **不要**把 `D:\Doubao` 当垃圾目录删除或清理；删掉真身，豆包就会丢数据。
- 重装豆包前，先解开联接（见下）再让安装程序写原位置。
- 判断方式：`(Get-Item 'C:\Users\HP\AppData\Local\Doubao' -Force).LinkType` 返回 `Junction`。

### 撤销（回到原状）

```powershell
# 1. 删掉联接（只删链接，不动 D:\Doubao 里的数据）
cmd /c rmdir "C:\Users\HP\AppData\Local\Doubao"
# 2. 把数据拷回原位
robocopy "D:\Doubao" "C:\Users\HP\AppData\Local\Doubao" /E /R:1 /W:1
```

## 四、明确没动的，以及原因

| 对象 | 占用 | 为什么不动 |
|---|---:|---|
| `AppData\Local\Programs` | 7.2GB | 是已安装程序本体，改路径会破坏卸载与更新 |
| `AppData\Local\Microsoft` | 2.3GB | 系统组件与 Office 相关，不宜搬 |
| `AppData\Roaming\Tencent\QQLive` | 2.23GB | 属程序数据（播放记录等），不是缓存；腾讯视频的缓存目录本来就设在 `D:\a9a09b83…`，上限 5GB |
| Windows 目录 | — | 不动 |

## 五、搬运时的规矩（以后照此办）

1. **先复制、校验、再删原件**，不用「剪切」；
2. 校验标准：两边**文件数与总大小**一致（影片类可再加哈希抽样）；
3. **能用应用内设置就别用联接**——官方路径最稳，联接只在应用不支持改路径时才用；
4. 搬完**必须实际启动一次**应用确认可用，文件数对上不等于应用认；
5. 按用途放，不按大小均摊：项目与备份在 D，媒体与缓存类在 E。
