## 启动规则

1. 当前主会话先定：名称、范围、边界、验收；
2. 新会话第一句读 `HANDOFF.md`、`docs/待办.md`、`docs/工作原则.md`、`docs/工作法-会话管理.md`；
3. 专项会话只做范围内的事，不自行扩权；
4. 需要再开新会话时，回报当前主会话定名；
5. `0002` 是执行主渠道，不限于平台事务：新执行工作默认进 `0002`；其上下文达到 60% 后，新任务直接进下一个编号，不排队；
6. 执行会话在 70% 上下文时硬性换会话（细则见 `docs/工作法-会话管理.md`「执行会话的量化分流」）；
7. 阶段结束，专项会话更新 HANDOFF 相关事实，当前主会话做最终裁定。

## 主会话不写代码（2026-11-25 定）

起因：2026-11-25 排查 GitHub 推送时，`0001` 自己写了 `deploy/push-github.ps1`，又连改两轮（加报错输出、加等待解析生效）。这是执行工作，本应进 `0002`。

界线：

| 事项 | 归谁 |
|---|---|
| 方案（是否改用脚本、固定 IP＋还原的策略、取舍） | `0001` |
| 写脚本、改脚本、写测试、改构建 | `0002`（或 `000N`） |
| 判定标准（什么算跑通、什么算失败） | `0001` 给 |
| 执行与回报输出 | `0002`；系统级操作（管理员窗口、改 hosts、推送）由用户执行 |

- 文档与规则（`HANDOFF.md`、`docs/待办.md`、`docs/*.md`）归 `0001`：那是决策记录，不是代码；
- 唯一例外：**必须当场试验才能决定下一步**（如断网诊断要连续探测），且预计写入量小于一页。此时 `0001` 可临时做，但要在同一轮写明「这段代码的后续归属」，交回 `0002`；
- 「慢」不是例外理由。写一页交接给 `0002` 比自己做慢，这是分工的成本，接受它；
- 自查方式：动手前问一句「这段字是要变成程序，还是要变成决定？」前者停下，后者继续。

## 编号规则

- `0000`：永久历史主会话，专门保留；
- `0001`：当前主会话；
- `0002` 起：专项会话，单调递增，四位固定，永不复用；
- 归档不释放编号，新会话取下一个号；
- 主会话换代：取当前最大编号 + 1（`0004` 之后为 `0005`），台账里「当前主会话」标记随人走，旧主会话转 `archived`、仍可查；
- 到 `9999` 再讨论扩容，不提前重排。
