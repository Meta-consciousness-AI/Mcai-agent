# 会话台账

> 规则：新会话的名称、范围、边界由当前主会话决定；专项会话不自行开新会话。
> 命名：`mcai-knowledge-0000` 为永久历史主会话；`0001` 为当前主会话；`0002` 起为专项，四位固定，永不复用。
> 上限：0000 永久保留、不计入执行上限；执行型会话同时活跃 3 个，工作量大 5 个，极限 9 个。

| 会话名 | 类型 | 范围 | 状态 | 备注 |
|---|---|---|---|---|
| `mcai-knowledge-0000` | 历史主会话 | 低频战略、重大决策、历史记忆 | 永久保留 | 不归档、不执行；置顶显示 |
| `mcai-knowledge-0001` | 当前主会话 | 日常重大决策、方向判断、最终裁定 | active | 2026-11-22 建立；本会话为 0001 |
| `mcai-knowledge-0002` | 专项（执行主渠道） | 平台事务为首要，其余执行工作默认进这里 | paused | 原 `mcai-knowledge-platform`；Bing 11-25 复查；60% 后新任务转下一编号；**已确认存在**：最后活跃 2026-11-22 13:13，4 轮 / 90 步，提交 `c5e2756`（MCP 0.4.3 + HANDOFF/待办刷新） |
| `mcai-knowledge-0003` | 专项 | 下一轮问答/关系审校（N08） | planned | 需要时由 0001 启动 |
| `mcai-knowledge-0004` | 专项 | 发布/部署（如需要） | planned | 通常并入 0002 或临时开 |
| `mcai-knowledge-ops` | 历史专项 | Git 卫生、备份、维护 | archived | 旧命名；工作已完成 |

## 启动规则

1. 当前主会话先定：名称、范围、边界、验收；
2. 新会话第一句读 `HANDOFF.md`、`docs/待办.md`、`docs/工作原则.md`、`docs/工作法-会话管理.md`；
3. 专项会话只做范围内的事，不自行扩权；
4. 需要再开新会话时，回报当前主会话定名；
5. `0002` 是执行主渠道，不限于平台事务：新执行工作默认进 `0002`；其上下文达到 60% 后，新任务直接进下一个编号，不排队；
6. 执行会话在 70% 上下文时硬性换会话（细则见 `docs/工作法-会话管理.md`「执行会话的量化分流」）；
7. 阶段结束，专项会话更新 HANDOFF 相关事实，当前主会话做最终裁定。

## 编号规则

- `0000`：永久历史主会话，专门保留；
- `0001`：当前主会话；
- `0002` 起：专项会话，单调递增，四位固定，永不复用；
- 归档不释放编号，新会话取下一个号；
- 主会话换代：取当前最大编号 + 1（`0004` 之后为 `0005`），台账里「当前主会话」标记随人走，旧主会话转 `archived`、仍可查；
- 到 `9999` 再讨论扩容，不提前重排。
