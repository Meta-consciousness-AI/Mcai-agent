## 四、关键发现：调用方式变了

10-21、10-22 出现了**同一秒内 3 次并行请求**：

```
2026-10-21 12:55:58  3 次
2026-10-21 12:56:07  3 次
2026-10-22 08:56:28  3 次
```

且问题形态是"把一个大问题拆成几个子问题"：

- 元意识学说的整体主张和核心概念体系是什么？
- 元识、元知、元灵、元子、元网分别是什么概念？
- 元子的形式化身份 `<C,I,O,K,N,P>` 每个字段的含义和验证方式是什么？
- 元意识学说的社会模型、公民身份、确权体系是怎样的？序生协议是什么？

**这是 Agent 在"分解问题 + 并行检索"，不是人在逐条输入。** 说明调用方已经把它当工具用，而不只是问答。

代价是：复合问题超出单概念路由的能力，返回 `related`（低置信）。

## 六、结论

1. **调用是真实的**：31 次业务问答，20 次来自 PowerShell 客户端，其中 10 次发生在我未参与的日期（10-21、10-22）。
2. **调用方式升级了**：从"单次提问"变成"并行分解"，这是 Agent 式使用。
3. **命中率是短板**：复合问题 60% 命中率，`related` 占比高。
4. **范围仍限于本机**：376 次请求全部来自 `127.0.0.1`，没有任何外部网络来源。

## 七、建议

1. **在技能里加一条规则**：遇到"A、B、C 分别是什么"这类复合问题，拆成多次单概念查询，
   或用 `/api/v1/answer/batch` 一次提交多个问题；
2. **给 `query.ps1` 加自定义 User-Agent**（如 `mcai-skill/1.0`），把"技能调用"与"人工命令"区分开，
   日志归因会更准；
3. 后续可以考虑让 `answer` 支持简单的多概念拆分，而不是整句丢给检索。
