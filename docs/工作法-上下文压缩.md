# 上下文压缩：标准流程

> 用途：`0001`（主会话，决策）与 `0002`/`000N`（执行会话）通用。
> 核心判断：压缩不是「清空聊天」，是**把记忆从上下文搬到文件**。搬不走的，压缩后就等于没有。
> 相关：`docs/工作法-会话管理.md`（阈值与分工）、`docs/主会话交接包.md`（新主会话启动语）、`docs/工作原则.md`（回执要短）。

## 一、什么时候压

| 角色 | 开始准备 | 必须交接 | 硬性上限 |
|---|---|---|---|
| 主会话（`0001`） | 40% | 50% | — |
| 执行会话（`0002`/`000N`） | 50% | 60% | 70% 硬换、80% 只回一句 |

补充两条经验：

- **一个完整话题做完就压**，比按百分比更划算——半句话被打断的损失，比早压一次大得多；
- 压缩动作由**用户**执行（`/compact`），会话自己不能触发。所以「准备压缩」＝把文件写到「随时可压」的状态。

## 二、压缩前必须落盘的六类事实

逐条过，缺一条就会在压缩后变成「没人知道」。

1. **当前状态**：版本号、两端 SHA、分支/标签、工作树是否干净。
   - SHA 一律写成「某时间点为 X」，并注明**当前状态以 `git ls-remote` 为准**；不要写「现在领先 N 个提交」——写完就过时。
2. **本轮做完的事**：一行一件，带提交号。不是「优化了脚本」，而是「`Add-Pin` 补 CRLF + 回读，提交 `f6e91cf`」。
3. **未做完 / 待定**：谁在做、卡在哪、等谁的一句话。
4. **本轮推翻或修正过的结论**：必须显式写「作废」并给新结论。
   - 例：2026-11-25「pin 有效、验证方法无效」作废 →「pin 从未生效，推成功走的是 DNS」。
   - 只改新结论、不标旧结论作废，下个会话会照着旧的做。
5. **新增规则与教训**：写进 `docs/工作原则.md` 或 `docs/会话台账.md`，不要只留在对话里。
6. **外部等待项**：等什么、等多久、回查要看哪个指标（Bing 收录数、Glama `releases/latest`…）。

## 三、四步执行

### 第 1 步：清点

读这四份，找出「上下文里有、文件里没有」的事实：

```
HANDOFF.md
docs/待办.md
docs/工作计划.md
docs/工作备忘包/00-总索引-触发条件.md
```

### 第 2 步：落盘

按上面六类改文件。规矩：

- **长内容进文件，不留上下文**；对话里只留结论与指针；
- 数字类口径（65/130/263/164）改动时，`README`、`主会话交接包`、`发布记录` 要一起改——它们是同一份事实的四个副本；
- 台账类改动（编号、状态）顺手加一行「变更记录」，写清改了什么、为什么。

### 第 3 步：自检（压缩前唯一必做的验证）

不看上下文，只打开文件，回答三问：

1. **现在在哪**（版本、SHA、工作树）？
2. **下一步做什么**（一项，不是一堆）？
3. **哪些旧结论已作废**？

三问答不出来，说明还有东西没落盘，回第 2 步。

### 第 4 步：触发压缩

由用户输入 `/compact`。压缩后按顺序读：

```
HANDOFF.md → docs/待办.md → docs/工作计划.md → docs/工作原则.md
```

## 四、执行会话（`0002`/`000N`）专用

交接四行，缺一不可：

1. 改了哪些文件与提交号；
2. 还剩什么（没做的、做了一半的）；
3. 下一步交给谁（哪个会话、哪一步）；
4. 停止条件（遇到什么就停下回报）。

**回执另有三条硬规矩**（见 `docs/工作原则.md`「回执要短」）：

- 对话里只写结论，不超过 15 行；过程、演练输出、替代点进 `docs/执行回执/`；
- 「待办提示」必须以当场读过的 `docs/待办.md` 为准，不复述印象；
- 凡「仍欠 X」，落笔前先回文件确认 X 是否还挂着。

## 五、压缩后接续

1. 按第四节顺序读文件；
2. 复述三问的答案给用户听（这是接续自检，也是对齐机会）；
3. 只为「下一步」动手，不为「历史」动手。

## 六、常见失败

| 现象 | 后果 | 预防 |
|---|---|---|
| 把 SHA / 领先数写死 | 一提交就过时，下次拿错基线 | 写「某时刻为 X」+「以 `ls-remote` 为准」 |
| 旧结论没标作废 | 下个会话照旧执行，重复踩坑 | 显式写「作废」，并给新结论与依据 |
| 「已完成」里混进「待决定」 | 决定被当成事实，再没人回头看 | 已完成 / 待定分两处写 |
| 规则只留在对话里 | 压缩即丢失，下一轮又讨论一遍 | 当轮写进 `工作原则` 或 `会话台账` |
| 长输出留在上下文 | 压缩时先烧掉的就是它 | 细节进 `执行回执`，对话只留结论 |
| 台账多副本各写一套 | 数字互相矛盾，没人知道哪个对 | 每个数字只有一个权威来源，其它副本只引用 |
