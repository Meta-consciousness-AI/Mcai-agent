# 调研计划 v3：Agent 引用核验的规范与凭证

> 依据：`研判-核验器-调研v2.md` 的修正——出版社工具段（B）已有强玩家，放弃；聚焦 Agent 侧。
> 原则：先穷尽调研，再定动作；不写架构、不写代码。

## 一、方向定义

**做什么**：为 Agent 的输出提供「引用是否忠实于来源」的核验，并把结果做成可验证的凭证。

**不做什么**：出版社审校工具（古联、方正、WPS 已占）、通用查重、论文工厂检测。

## 二、保留与新增的调研组

| 组 | 主题 | 处理 |
|---|---|---|
| D | Agent 平台是否有引用核验需求 | 保留，重点 |
| E | 保密、责任、扫描件合规 | 保留 |
| C | 标准与基准 | 选择性：只看与 Agent 相关的部分 |
| B | 出版社采购与成本 | **删除** |
| F | **凭证技术**（新增） | 新增 |
| G | **协议与生态位**（新增） | 新增 |
| H | **付费方与采购路径**（新增） | 新增 |

## 三、问题清单

### D. 需求（6 问）

1. RAG/Agent 团队现在怎么处理引用错误？
2. 有没有团队已经在做「引用核验」？用什么方法？
3. 引用错误造成过什么实际损失（客诉、合规、返工）？
4. Agent 产品对外承诺「有出处」时，怎么证明？
5. 企业采购 Agent 时，是否要求可审计的引用？
6. 需求是「开发时评测」还是「运行时核验」？

### E. 合规（4 问）

7. Agent 输出与来源文本的存储、跨境、留存要求？
8. 核验报告出错的责任如何划分？
9. 扫描件/PDF 的文本提取质量与版权边界？
10. 中国生成式 AI 管理办法对「可追溯」的要求？

### C. 标准（选择性，3 问）

11. 与 Agent 输出相关的标准：W3C VC、C2PA、OpenTelemetry GenAI、A2A？
12. 有没有「AI 输出可验证」的标准草案？
13. CiteCheck 等中文基准，能否作为我们的评测基础？

### F. 凭证技术（5 问）

14. 一份核验凭证应包含哪些字段？
15. 如何绑定到具体输出（哈希、签名、时间戳）？
16. 谁来验证凭证？需要信任颁发者吗？
17. 撤销、过期、版本更新怎么处理？
18. 是否需要透明日志（transparency log）？

### G. 协议与生态位（4 问）

19. MCP / A2A / ERC-8004 / x402 各自能挂在哪一层？
20. 大厂（OpenAI、Anthropic、Google）是否已内置来源核验？
21. 我们做「协议之上的凭证」，还是「协议之内的工具」？
22. 如果协议方自己做核验，我们的位置在哪？

### H. 付费方（4 问）

23. 谁为「Agent 可信」付钱：企业、平台、监管？
24. 采购流程与预算科目是什么？
25. 定价方式：按次、按席位、按年？
26. 最小可付费单元是什么？

## 四、方法

- 每组先做检索，再做交叉验证；
- 每个结论至少两个来源；
- 记录反例与失败案例；
- 不采信单一厂商的宣传页。

## 五、产出

`docs/研判-核验器-调研v3.md`：

1. Agent 侧需求证据；
2. 凭证技术方案对比；
3. 生态位判断；
4. 三个可选动作与唯一推荐；
5. 不确定性与复盘点。

## 六、时间

不限时，直到 26 个问题都有答案或明确「查不到」。
