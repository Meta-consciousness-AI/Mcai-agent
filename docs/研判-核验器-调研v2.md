## A 组：谁在做（中文市场）

### 1. 古联「文达智校」（中华书局全资子公司）

来源：[光明日报报道](http://www.zhbc.com.cn/zhsj/fg/news/info.html)、[中国作家网](http://www.chinawriter.com.cn/n1/2026/0915/c403994-40798943.html)

- 2026 年 9 月上线；
- 依托 **7000 余种古籍资源**与文史知识库；
- 核查：引文、人物、地名、职官、历史事件、纪年、繁简字、异体字；
- 形态：WPS 插件、Word 插件、网页端；
- 面向：人文学术、人文社科图书、期刊、数字人文。

判断：**这就是我们设想的「B 出版社引文核对」的中文版本，而且资源比我们厚。**

### 2. 古联「籍合审校」

- 同一时期上线，面向人文社科全场景；
- 支持 PDF 排版文件与 Word；
- 多模型协同、交叉比对、审校报告；
- 强调「知识核查」而不只是错别字。

判断：**产品化程度高，已进入出版机构。**

### 3. 方正智能辅助审校

来源：[方正中标广西师大出版社](https://mp.weixin.qq.com/s/8-aceEomSYLmrQgOP01uYA)

- 已中标出版社项目，落地「三审三校」；
- 专项检查含「参考文献全项核查」「重要讲话/法律法规引文比对」；
- 基于星空出版大模型；
- 支持 Word/WPS 插件、桌面端、网页端。

判断：**渠道与集成能力强，出版社采购路径成熟。**

### 4. WPS 黑马校对

来源：[WPS 黑马参考文献条目核对](https://365.wps.cn/content/816505bf7608409ebef30427efb9c9e2.html)

- 文内引用与文末文献交叉匹配；
- GB/T 7714 格式、编号连续性、元数据比对；
- 公有云订阅与私有化部署。

判断：**偏格式与元数据，逐字引文核对不是主打。**

### 5. 学术侧：CiteCheck（中文引文忠实度数据集）

来源：[CiteCheck 论文](https://arxiv.deeppaper.ai/papers/2502.10881v1)

- 2025 年 2 月，第一个大规模**中文**引文忠实度检测数据集；
- 两阶段人工标注，正负样本平衡；
- 结论：即使是先进 LLM 也难以高精度完成；小模型微调后效果好；
- 数据集公开。

判断：**C 的「中文基准」已有人做，且是学术团队。**

### 6. 国际侧（前一轮）

- RefChecker、Edifix、CoChat：英文文献为主；
- ALCE/CiteEval：英文基准；
- Ragas/LangSmith 等：评估行为，不做来源核验。

## 对三个问题的修正

### 「谁在做」

- 中文出版侧：古联、方正、WPS，**已产品化、已进出版社**；
- 中文基准侧：CiteCheck，学术团队已占位；
- Agent 侧：仍是空的（Ragas 等只做 LLM 判断）。

### 「为什么现在还能做」

原来的六条理由，有三条被削弱：

- 「中文出版是空档」——**不成立**，古联与方正已占；
- 「逐字核对没人做」——**部分不成立**，文达智校明确做引文核查；
- 「标准没人管」——仍成立，但基准已有 CiteCheck。

仍然成立的三条：

1. **Agent 侧空白**：他们的产品面向编辑工作流，不面向 Agent 调用；
2. **开放标准空白**：三家都是闭源商业产品，没有公开规范与认证；
3. **可验证凭证空白**：没有「签名核验报告」这类可审计产物。

### 「大机构进来怎么办」

已经进来了，而且是以「出版社工具」的形态。

所以我们不能做「又一个出版社审校工具」，只能做他们不做的：

- 面向 Agent 的核验接口；
- 开放规范与公开基准；
- 第三方可验证的凭证。

## 初步结论（待 B–E 组验证）

1. **B 段（出版社工具）放弃**：古联、方正、WPS 已占，资源与渠道都强于我们；
2. **C 段收窄**：不做通用基准，做「Agent 引用核验」的规范与凭证；
3. **D 段是主战场**：Agent 侧还没有人做「来源级核验」。

这比上一版研判更窄，也更清楚。

## 待查（B–E 组）

- B：出版社现在的人工成本与采购价；
- C：WPS/方正/古联是否提供 API 或对外核验服务；
- D：Agent 平台是否已有引用核验需求；
- E：书稿保密、责任边界、扫描件合规。
