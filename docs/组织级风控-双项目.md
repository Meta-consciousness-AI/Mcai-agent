# 组织级风控：两个包，一个主体

> 背景：`mcai-knowledge` 与 `mcai-chinese-classics` 同属 Meta-consciousness-AI。
> 目标：享受统一品牌的好处，同时把「一损俱损」的风险压到可接受。

## 一、共享了什么

| 资源 | 是否共享 | 说明 |
|---|---|---|
| GitHub 组织 | 共享 | 同一组织下的两个仓库 |
| PyPI 账号 | 共享 | 同一 owner，两个项目名 |
| MCP 注册表命名空间 | 共享 | `io.github.Meta-consciousness-AI/*` |
| Glama / mcprush 作者页 | 共享 | 同一 publisher |
| CloudBase 环境 | 共享 | 资源点、隔离状态共用 |
| 品牌与声誉 | 共享 | 一个包出事，另一个被连带看待 |
| 法务/投诉记录 | 共享 | 平台按账号累计 |

## 二、风险矩阵

| 风险 | 可能性 | 影响 | 说明 |
|---|---|---|---|
| 版权投诉（误用现代点校本/译注） | 中 | 高 | 下架、账号警告，严重时封禁 |
| 平台内容政策（宗教、历史、政治段落） | 低—中 | 中—高 | 不同平台尺度不同 |
| 质量问题（编者注被当成原文） | 中 | 中 | 损害「可回查」信誉 |
| 共享配额耗尽 | 高 | 中 | 已发生过：CloudBase 隔离，两个服务同时停 |
| 账号级处罚 | 低 | 高 | 一次严重违规影响全部 |
| 品牌稀释 | 中 | 中 | 经典包做得糙，拉低主项目可信度 |

## 三、结论

**可以放在同一组织，但必须满足四个前提：**

1. 内容准入有硬标准，且每次发布前检查；
2. 基础设施有独立预算与监控，不能让一个项目的流量/额度拖垮另一个；
3. 任一产品触红线，视为全组织红线，立即暂停两边发布；
4. 有可执行的事故隔离方案：能单独停掉一个包，不影响另一个。

## 四、内容准入（最关键）

新项目只允许：

- 公共领域原文（先秦至清、民国前）；
- 公共领域古注（宋及以前，或明确公有领域版本）；
- 自己撰写的术语、问答、编者注，且标明「编者注」。

禁止：

- 现代点校本、校勘、标点（有版权）；
- 现代白话译文、注释、研究著作；
- 来源不明的扫描件、OCR 文本；
- 未经授权的数据库内容。

每次新增一部经典，必须留：

- 底本名称与来源 URL；
- 版本/校勘说明；
- `ATTRIBUTION.md` 更新；
- 引文可回查（字符区间）。

## 五、基础设施隔离

- **静态站与云托管分开计**：静态站不消耗云托管资源点，主项目的站点应保持独立可访问；
- **新项目单独服务**：不要和 `mcai-mcp-public` 共用同一个云托管服务；
- **配额监控**：每周看一次资源点余量，低于 20% 提前处理；
- **可回退**：新项目出问题，能单独下线其服务与包，不影响 mcai-knowledge。

## 六、发布节奏隔离

- 两个项目独立发版，不捆绑；
- 新项目发版前，先确认主项目没有待发布的变更；
- 任一项目进入「观察期」（被投诉、被警告、内容争议），两边都暂停新版本，直到结论明确。

## 七、事故响应（一页流程）

1. **发现**：平台通知、投诉、或自查发现；
2. **冻结**：暂停两个项目的新发布与推广动作；
3. **定性**：是内容问题、版权问题，还是平台误判；
4. **隔离**：只下线涉事包/服务，保留另一个；
5. **整改**：删除或替换涉事内容，更新来源与说明；
6. **复盘**：写入 `docs/`，更新准入清单；
7. **恢复**：先恢复未涉事项目，再评估涉事项目。

## 八、品牌表述

对外统一：

> Meta-consciousness-AI 提供可验证的知识资产；
> 一个盒子，两种内容：原创学说（mcai-knowledge）与中国经典（mcai-chinese-classics）。

不把两个包说成「同一个产品」，避免一个出问题时被理解为整体失效。

## 九、检查清单（每次新项目发版前）

- [ ] 全部内容来源为公共领域，且有出处记录；
- [ ] 没有现代点校本、译注、研究著作的文字；
- [ ] `ATTRIBUTION.md` 已更新；
- [ ] 编者注与原文分开标注；
- [ ] 新项目使用独立服务/独立配额；
- [ ] 主项目当前无待发布变更；
- [ ] 事故响应联系人与流程已知。

## 十、判断标准

一个问题是否值得冒组织级风险：

- 出事后能否只停一个包？
- 有没有合规替代？
- 不做会损失什么？

如果「不做也没什么损失」，就不做。
