# 学说知识资产化规范 V1.2（试行版）

> 状态：V1.2 试行版，基于四个语料的完整实践；定义分层与版本字段（edition）均已实现并回填。
> 目的：把「一套学说」整理成可被 AI / Agent 调用的知识资产，并规定最小可交付标准。
> 适用：原创学说、术语体系、思想文本、公共领域经典。
> 不适用：内容营销、观点生成、自动问答扩写。

---

## 1. 目标与边界

### 1.1 目标

让外部 AI / Agent 能以最低成本、最高保真度拿到：

- 术语定义
- 概念关系
- 原文出处
- 标准问答

### 1.2 硬边界

- **只收学说术语，不收人物、机构、商业信息。**
- **不自动生成问答。** 问答涉及语境与共情，必须人工撰写。
- **不做观点生成。** 系统只做检索、引用、组织，不做新主张。
- **不把「被阅读」当目标。** 唯一目标是「被调用」。

## 2. 数据模型

最小知识库由四类对象组成。

### 2.1 概念（Concept）

```json
{
  "term": "元识",
  "en": "Meta-recognition",
  "aliases": ["元识行为"],
  "definition": "……",
  "definition_type": "quote",
  "editor_note": "",
  "sources": [
    {"doc_title": "元意识学说极简版（标准词表）", "section": "元意识学说的社会模型：元子社会", "quote": "……"}
  ],
  "relations": [{"to": "元知", "type": "contrast"}],
  "status": "core"
}
```

必填：`term`、`definition`、`sources`（至少一条）。
可选：`en`、`aliases`、`relations`、`status`、`definition_type`、`editor_note`。

**定义分层规则（V1.1 新增）**：

- `definition_type = "quote"`：`definition` 必须是原文原句，逐字可核验；适用于有定义句的文本。
- `definition_type = "editor"`：`definition` 仍是原文原句，`editor_note` 放编者释义；适用于无定义句的文本（如道德经）。
- 任何情况下，编者释义不得伪装成原文定义；接口返回时两者必须分开。

### 2.2 问答（FAQ）

```json
{
  "question": "什么是元识？",
  "answer": "……",
  "sources": [{"doc_title": "……", "section": "……"}],
  "type": "definition"
}
```

必填：`question`、`answer`、`sources`、`type`。
`type` 取值：`definition` / `distinction` / `relation` / `citation` / `boundary`。

### 2.3 引证（Evidence）

```json
{"doc_title": "……", "section": "……", "quote": "……", "concept": "元识", "edition": "……"}
```

### 2.4 关系（Relation）

```json
{"from": "元识", "to": "元知", "type": "contrast", "note": "……"}
```

`type` 取值：`is_a` / `part_of` / `contrast` / `depends_on` / `mentions`。

### 2.5 派生数据集

| 文件 | 用途 |
|---|---|
| `concepts.jsonl` | 概念库 |
| `faq.jsonl` | 标准问答 |
| `evidence.jsonl` | 引证 |
| `sft.jsonl` | 指令微调格式 |
| `concepts.csv` | 表格查看 |
| `knowledge-graph.json` | 节点 + 边 |

## 3. 抽取与裁定规则

### 3.1 源文档

- 优先使用**标准词表 / 术语表**，其次正文；
- 记录文档名、章节、原句；出处必须能回查；
- 同一术语多源定义时，进入比对流程；
- **无现成词表的文本，先建立「术语—原句」对照表，再进入抽取**（V1.1 新增）；
- **每份语料必须记录 `edition`（版本、来源、校勘说明）**；同一经典的多版本引证并存，不合并、不改字（V1.2 新增）。

### 3.2 多源定义比对

- 相似度低于阈值 → 记为冲突，进入人工裁定；
- 裁定优先级：标准词表 > 正文定义 > 举例说明；
- 裁定结果必须保留一条 `sources`，禁止无出处定义。

### 3.3 别名规则

- **正名不得作为别名**（防止别名反向吞并）；
- 别名写入用「不覆盖」策略（已存在则跳过）；
- 别名必须有原文依据，禁止凭语义联想添加。

### 3.4 禁止项

- 人物姓名、笔名、机构、联系方式、商业信息；
- 以配置项维护（如 `excluded_entities`），并在抽取、引证、问答、质检四处执行。

### 3.5 术语形态（V1.1 新增）

- 允许**中文数字开头**的术语（如「五事」「九地」）；只拒绝「数字 + 分隔符」的编号行；
- 允许**单字术语**（如「性」「名」），但必须在人工分类中登记，未登记的单字不入库；
- 定义长度不足一句话时，优先补足原文连续句，不自行改写。

### 3.6 术语边界

- 与通用语义冲突的术语（如「元意识」与 meta-awareness），必须在定义或问答中显式区分；
- 可选：维护消歧层，记录「不要答成什么」，该层可随时撤除。

---

## 4. 问答规范

- **人工撰写**，不从定义自动扩写；
- 每个核心术语至少一条定义型问答；
- 易混术语必须有辨析型问答；
- 复合问题在接口层拆分，不在问答库堆砌；
- 回答必须带出处；无出处则不得入库。

---

## 5. 质量门槛

### 5.1 结构检查

- 必填字段齐全；
- 出处可解析到文档与章节；
- 关系两端均存在于概念表；
- `definition_type = "editor"` 时，`definition` 仍能在原文中逐字命中，`editor_note` 非空；
- 每条 `sources` 必须带 `edition`，且与语料配置一致（V1.2 新增）。

### 5.2 一致性检查

- 同一术语多定义 → 冲突清单；
- 别名与正名冲突 → 报错；
- 循环依赖 → 标记。

### 5.3 政策检查

- 禁止项泄露 → 阻断发布；
- 问答中出现人物信息 → 阻断。

### 5.4 人工抽检

- 按比例抽检定义与问答；
- 抽检记录留档。

### 5.5 指标

| 指标 | 说明 |
|---|---|
| 概念数 | 核心 + 衍生 |
| 出处覆盖率 | 有出处的定义占比，目标 100% |
| 冲突数 | 未裁定冲突应为 0 |
| 问答数 | 按术语与场景覆盖 |
| 外部评分 | 如 TDQS，作为参考不是目标 |

## 6. 分发规范

### 6.1 包与接口

- 发布为可安装包（PyPI）；
- 提供 MCP stdio 接口，最小工具集：
  - `answer`：整句问答
  - `concept`：取词条
  - `search`：检索
  - `related`：关系
  - `list`：目录
- 包内自带完整知识库，安装即用，不依赖作者服务器。

### 6.2 数据集

- 以 JSONL / CSV / 图结构发布；
- 申请 DOI（Zenodo 等），保证可引用；
- 数据集卡片写明字段、许可、用途。

### 6.3 站点

- 每个概念独立 URL；
- 结构化数据：`DefinedTerm` / `FAQPage` / `Dataset`；
- 提供 `llms.txt` 与 `sitemap.xml`；
- 有稳定域名（临时隧道不算）。

### 6.4 目录与注册表

- 提交 MCP 官方注册表；
- 提交至少一个第三方目录（如 Glama）；
- 国内平台单独维护（语言、合规不同）。

### 6.5 版本与 DOI

- 包版本语义化；
- 数据集 DOI 区分「版本 DOI」与「总 DOI」；
- 每次内容变更记录变更说明。
