# 发布检查清单

> 用途：每次发版（PyPI / 云托管 / 站点）照此执行。
> 原则：一步一确认；部署前三查，部署后三验。

## 一、发布前

- [ ] `python tools/preflight_release.py` 通过；
- [ ] `python -m unittest discover -s tests` 通过；
- [ ] `mcai validate` 通过；
- [ ] 版本号一致（config / pyproject / `__init__` / server.json / 包内 kb）；
- [ ] 包内 kb 已更新：`mcai/data/default/data/kb.json`；
- [ ] 确认部署分支：**Gitee 用 `master`**（`main` 已停用）；
- [ ] 确认远程分支已包含本次提交：

```powershell
git ls-remote gitee refs/heads/master
git ls-remote origin refs/heads/main
```

## 二、部署云托管

- [ ] 打开服务页：`mcai-mcp-public` / `mcai-mcp-gitee`；
- [ ] 点「更新服务」；
- [ ] 仓库填 `https://gitee.com/Meta-consciousness-AI/Mcai-agent.git`；
- [ ] 分支选 `master`；
- [ ] 端口：访问 80 → 服务 8080；
- [ ] 点「部署」；
- [ ] 记下新的部署 ID；
- [ ] 等状态变为「正常」。

## 三、部署后三验

- [ ] health 版本：

```
https://mcai-mcp-public-338698-11-1316838521.sh.run.tcloudbase.com/api/v1/health
```

应为新版本号，`built_at` 为当天。

- [ ] gitee 服务同样检查；
- [ ] 内容抽检：取一个本次改过的词条，确认定义已更新。

## 静态站点（每次内容更新必做）

- [ ] `python tools/build_site_from_kb.py` 生成 `dist/`；
- [ ] 确认 `dist/index.html` 含新版本号；
- [ ] 静态托管 → 文件管理；
- [ ] 上传 `concepts`、`assets`、`dataset`、`faq` 文件夹；
- [ ] 上传根文件：`index.html`、`disambiguation.html`、`guide.md`、`kb.json`、`llms.txt`、`llms-full.txt`、`openapi.json`、`robots.txt`、`sitemap.xml`；
- [ ] 上传 `.well-known/mcp.json`、`.well-known/agent.json`；
- [ ] 上传 `dashboard.html`；
- [ ] 刷新文件列表，确认 `index.html` 时间为当天；
- [ ] 线上抽检：版本号、一个改过的词条、`/.well-known/mcp.json`。

## 四、记录

- [ ] 在 `docs/发布记录.md` 写入：版本、时间、部署 ID、分支、提交号；
- [ ] 同步 GitHub / Gitee；
- [ ] 如失败，记录失败原因与修复。

## 五、回滚

- 控制台「部署版本」→ 选中上一个「正常」版本 → 回退；
- 或重新部署上一版提交。
