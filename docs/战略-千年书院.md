# 战略：数字千年书院

> 记录时间：2026-11-11
> 性质：总体定位，优先于渠道、增长与技术选择
> 关联：`docs/战略-平台与方向评估.md`、`docs/决策记录-域名与备案.md`

## 一、一句话

我们在建的是一座**数字世界的千年书院**；《元意识》是书院里的经典读本；知识库与 MCP 盒子，是这部读本的装帧与借阅方式。

## 二、三层结构

| 层 | 是什么 | 地位 |
|---|---|---|
| 书院 | 数字世界中长期存在的学术与思想场所 | 本体 |
| 著作 | 《元意识》元意识学说 | 核心资产 |
| 盒子 | `mcai-knowledge` 知识库、MCP、PyPI、DOI | 装帧与入口，可替换 |

## 三、核心任务

1. 让元意识学说**永久保存**：文本定稿、出处可查、版本可追溯；
2. 让 AI 与人都能**准确调用**：术语、问答、来源、版本；
3. 让它在作者不在场时仍然可用：去作者化、开放接口、可复制方法。

## 四、非核心任务

- 盒子被多少人关注；
- 渠道播放量、Star、下载量；
- 品牌知名度；
- 域名与站点是否「专业」。

这些是加分项，不是成败标准。

## 五、什么叫「已经成功」

按核心任务衡量，满足以下三条即成立：

- [x] 学说文本已定稿并有著作权登记；
- [x] 术语与出处已结构化，AI 可准确检索；
- [x] 已通过 DOI、预印本、公开数据集形成可独立引用的存档。

盒子被使用，是额外赠与；不被使用，不改变核心任务的完成。

## 六、由此产生的取舍

1. **钱与精力优先投向资产**：文本、数据、出处、存档；不投向入口装潢；
2. **域名与备案暂不做**：它只影响「盒子好不好进」，不影响「著作在不在」；
3. **渠道发布不追量**：发是因为「可能有人需要」，不是因为「要增长」；
4. **不设增长 KPI**：只设「可调用性」与「存续性」检查；
5. **不接受需要持续付费才能维持的核心依赖**：入口可以塌，资产不能塌。

## 七、长期存续的三条腿

| 腿 | 做法 | 现状 |
|---|---|---|
| 文本存续 | 定稿、版本记录、著作权登记 | 已完成 |
| 学术存续 | DOI、预印本、PhilArchive、OpenAIRE | 已完成 |
| 技术存续 | PyPI 包、GitHub/Gitee 仓库、可复制方法 | 已完成 |

只要这三条在，站点、域名、服务器都可以重建。

## 八、每年的动作（轻量）

- 检查 DOI 与预印本可解析；
- 检查包可安装、MCP 可启动；
- 确认仓库有完整备份；
- 不做「增长复盘」，只做「存续检查」。

## 九、一句话收尾

**书院不靠流量活着，靠文本与可调用性活着。**
盒子能走出去，很好；走不出去，书院仍在。
