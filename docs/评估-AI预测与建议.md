# 评估：外部 AI 给出的发展方向

> 来源：`第二次综合参考.docx`，34 张截图，四个 AI（千问、GLM、讯飞星火、元宝）的预测与建议。
> 评估时间：2026-11-13
> 判断依据：`docs/战略-千年书院.md`、`docs/工作法-反馈驱动.md`、`docs/运营安全规范.md`

## 一、方法

对 27 个方向按五项打分：

1. 与「书院—著作—盒子」定位是否一致；
2. 现有能力能否覆盖（单人、小团队、纯本地工具链）；
3. 成本与周期；
4. 风险（合规、版权、平台、Web3）；
5. 是否有真实反馈基础。

## 二、强推荐：现在就能做

### 1. 自动引文验证器（质检工具）

- AI 原话：「把『引文 100% 核验』从人肉变成机器」「类似软件世界的单元测试 + CI」。
- 我们的基础：`tools/verify_citations.py` 已在用，四语料核验 100%。
- 做法：抽成通用 CLI，输入任意知识包，输出核验报告；开源。
- 成本：1–2 周。
- 风险：低。
- 价值：把「方法」变成「工具」，符合去作者化。

### 2. 数据集变「评测基准」

- AI 原话：「测试 AI 会不会瞎编引用的标准考卷」「幻觉评测正缺这种带标准答案的小数据集」。
- 我们的基础：每条定义带出处与字符区间，天然是标准答案。
- 做法：发布一个 citation-faithfulness 基准说明 + 样例 + 评分脚本。
- 成本：2–3 周。
- 风险：低。
- 价值：可能被研究者引用（Zenodo 已在动，这是同一条线）。

### 3. 工具链化（六步流水线）

- AI 原话：「从开了家店，变成造了建店的机器」。
- 我们的基础：`mcai build` / `mcai mcp` / `doctor` 已有，缺「一条命令跑完六步」。
- 做法：`mcai init` 起骨架、`mcai validate` 自检、`mcai package` 出包。
- 成本：3–4 周。
- 风险：低。
- 价值：别人用工具做自己的包，方法就传播了。

## 三、中期可选：需要条件

| 方向 | 前置条件 | 判断 |
|---|---|---|
| 多版本异文契约 | 需要古籍多版本语料 | 已有 `edition_variants` 字段，可先做《道德经》样例 |
| 知识包互认协议 | 需要第二个真实知识包 | 自己先出规范文档，不急推广 |
| 标准/质检中间件 | 需要企业客户 | 等真实需求 |
| 数字文献学基础设施 | 需要古籍内容与合作 | 与暂缓的中华经典项目重叠 |
| Agent 经验传承层 | 需要验证需求 | 概念新，先小实验 |
| 序生智能体评测基准 | 需要定义与数据 | 可做小样本，不立项 |
| 跨学说翻译器 | 需要多个学说库 | 等第二个库 |
| 民间思想联邦 | 需要协调多个作者 | 成本高，暂不 |
| 个人认知资产确权 | 已有独立项目 | 不在本会话 |
| SaaS / Shopify | 需要产品与运营 | 重，暂不 |

## 四、不建议做

| 方向 | 原因 |
|---|---|
| 脑机接口 | 远超能力，纯想象 |
| 元知协议 / 信用分 | 需要生态，容易变成自嗨 |
| 链上清算 / 微支付 | 碰 Web3，违反既定红线 |
| 哲学人格智能体 | 演示性强，价值不明 |
| 认知沙盒 / 数字导师 | 产品化重，偏离核心 |
| 讲授史语料 | 需要大量史料，且受众极窄 |

## 五、不可规划但可准备

三个 AI 都提到「被外部偶然看中」：被采纳、被当反例、被政策选中。

这类事无法规划，只能提高概率：

- 资产公开、可引用（DOI、RDF、w3id 已做）；
- 文档清楚（README、字段说明）；
- 有可验证的记录（核验 100%、失败报告）。

**对应动作：把已做的资产整理好，不追热点。**

## 六、结论：先立三个项

1. **引文验证器**（1–2 周）；
2. **评测基准包**（2–3 周）；
3. **工具链化 CLI**（3–4 周）。

三者共用同一批资产，风险低，且都符合「可复制的方法」这一长期目标。

## 七、一句话

**AI 们的预测里，最值得做的不是「更大的愿景」，而是「把手上的方法变成别人能用的工具」。**
