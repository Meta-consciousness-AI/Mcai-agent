# 研判：核验器 C+D 的问题清单与初步答案

> 时间：2026-11-16
> 性质：调研第一版，回答「谁在做、为什么能做、大机构来了怎么办」，并列出待查问题。

## 一、谁在做（C 与 D 分开看）

### C：引文忠实度的标准与基准

| 主体 | 做了什么 | 缺什么 |
|---|---|---|
| 学术团队（ALCE、CiteEval、AtomCite、DocCite） | 定义指标、建基准、发论文 | 停在论文，没有标准与认证 |
| NISO（CREC） | 撤稿/更正的传播规范 | 管「撤稿信息」，不管「引文是否忠实」 |
| STM Integrity Hub | 论文工厂与诚信筛查 | 面向整篇论文，不面向引文逐条 |
| C2PA | 内容来源凭证 | 管「谁生成、改没改」，不管「引用对不对」 |
| Scite | 19 亿条引用记录、13 亿条引用陈述分类 | 做「引用语境与态度」，不做「逐字核对」 |

判断：**「引文忠实度」这一层，没有标准组织在管，也没有商业认证。**

### D：Agent 引用核验基础设施

| 主体 | 做了什么 | 缺什么 |
|---|---|---|
| Ragas / DeepEval | faithfulness 指标（基于 LLM 判断/词重叠） | 不回到原文逐字核对，不可审计 |
| LangSmith / Langfuse / Arize / Braintrust | 可观测、评估、追踪 | 看行为，不看来源真实性 |
| Galileo / Credo AI / Fiddler | 治理与运行时控制 | 合规视角，不做引文级核验 |
| CoChat | 写作时校验引用（对 CrossRef/Semantic Scholar） | 查「文献是否存在」，不查「这句话在不在原文」 |

判断：**D 的玩家都在「评估行为」，没有人在「验证来源」。**

## 二、为什么现在还能做

1. **对象不同**：他们核「文献存在吗」，我们核「这句话在原文里吗」；
2. **方法不同**：他们用 LLM 判断（不可审计），我们用逐字比对（可复核）；
3. **买家不同**：他们卖给 AI 团队，我们卖给出版社/期刊；
4. **地域不同**：Edifix、CoChat 以英文文献为主，中文出版是空档；
5. **形态不同**：他们卖平台，我们卖「标准 + 凭证」；
6. **激励不同**：平台厂商做标准有利益冲突，中立方才有位置。

## 三、大机构进来怎么办

先判断他们会以什么方式进来：

| 进入方式 | 可能性 | 我们的应对 |
|---|---|---|
| WPS/知网加「逐字核对」功能 | 中 | 转向「认证与凭证」，不做工具 |
| 国际厂商（Edifix/CoChat）进中文市场 | 中 | 本地化 + 出版社关系 |
| 学术联盟立标准（NISO/STM） | 低中 | 参与而非对抗，提供实现与数据 |
| 大模型厂商内置核验 | 低 | 我们做「可验证凭证」，他们做「生成」 |

核心防御：

1. **中立性**：标准由中立方定，平台厂商自定标准会被质疑；
2. **认证记录**：谁通过、谁没通过，形成公开账本；
3. **失败案例库**：真实错误类型只有做过的人知道；
4. **被采用**：进 3 家出版社流程，比功能领先更重要；
5. **可收购价值**：如果防不住，成为被收购的标的也是结果。

## 四、问题地图（五组，待调研）

### A 谁在做

1. 有没有中国公司在做「书稿引文核对」？
2. 知网/万方/超星是否有类似能力，开放程度如何？
3. 国际厂商（Edifix、CoChat）是否支持中文？
4. 学术基准的中文版本是否存在？

### B 为什么现在能做

5. 出版社现在怎么解决？人工成本多少？
6. 现有工具的准确率如何？用户抱怨什么？
7. 「逐字核对」是否已被某产品覆盖？
8. 中文扫描件的文本质量是否足以支撑核对？

### C 大机构与竞争

9. WPS 黑马的「引文核对」到底做到哪一步？
10. 大厂若入场，最可能从哪个产品切入？
11. 标准组织是否已有相关工作组？
12. 我们能否成为某个标准的参考实现？

### D 需求与付费

13. 出版社的数字化预算是多少？谁批？
14. 期刊集群是否比单社更容易采购？
15. 作者个人是否愿意为「投稿前自检」付费？
16. 试点的最小可交付物是什么？

### E 执行与风险

17. 书稿保密协议怎么签？
18. 核验报告出错的责任边界？
19. 扫描件版权与存储合规？
20. 12 个月内做到什么算成功？
