# 研究：国内开发者渠道要不要上

> 时间：2026-11-16
> 对象：ModelScope（魔搭）、扣子（Coze）、阿里云百炼
> 结论：先上 ModelScope；百炼次之；扣子暂缓。

## 一、三个渠道的机制

| 渠道 | 谁能上 | 怎么上 | 用户是谁 |
|---|---|---|---|
| ModelScope MCP 广场 | 开放，个人可上 | 创建 MCP 服务，支持托管（stdio/uvx、Streamable HTTP、SSE）或远程地址 | 中文开发者、模型使用者 |
| 阿里云百炼 | 需阿里云账号 | 自定义 MCP：注册已有 HTTP 服务，或用脚本部署 | 企业开发者、Agent 构建者 |
| 扣子 Coze | 需扣子账号 | 把扣子应用发布为 MCP 扩展；或插件形式 | 普通用户、Bot 创作者 |

## 二、逐个判断

### ModelScope：上（实验 1）

- **匹配度高**：中文开发者、MCP 广场有搜索与「实验场」，可直接试用；
- **成本低**：我们已有 PyPI 包，用 `uvx --from mcai-knowledge mcai-mcp` 即可托管；
- **风险**：托管走函数计算，按调用计费；若可选「远程地址」，优先用我们自己的服务，避免费用。

### 阿里云百炼：第二批

- **匹配度中高**：企业 Agent 构建者，真正会调 MCP；
- **成本中**：注册自定义 MCP，填 HTTP 端点与鉴权；
- **风险**：需要阿里云账号与企业实名；审核可能更严。
- **判断**：ModelScope 跑通后，用同一份材料注册百炼，成本很低。

### 扣子 Coze：暂缓

- **匹配度低**：用户是 Bot 创作者与普通用户，关心「能做什么」，不关心 MCP 协议；
- **成本高**：要把能力包成扣子应用/插件，等于二次开发；
- **判断**：等我们有明确的「面向普通人的问答产品」再考虑。

## 三、共同前提

上任何渠道之前，先明确「用户搜什么词能找到我们」：

- 不是「元意识」；
- 而是「古籍 引文 核验」「道德经 出处」「术语 一致性」这类任务词。

所以上架文案要按任务写，不按学说写。

## 四、实验 1：ModelScope 上架

### 目标

两周内出现至少 1 次非我方调用。

### 步骤

1. 登录 modelscope.cn，进入 MCP 广场 → 创建 MCP 服务；
2. 名称 `mcai-knowledge`，分类选「知识 / 教育」；
3. 部署方式优先选「远程 / Streamable HTTP」，填我们的公开端点：
   `https://mcai-mcp-public-338698-11-1316838521.sh.run.tcloudbase.com/mcp`
   若只能托管，则用 Stdio：
   `uvx --from mcai-knowledge mcai-mcp`
4. README 按任务写（见下）；
5. 发布，拿到广场页面与 Remote URL；
6. 用「实验场」自测一次，确认工具可见。

### README 草稿（按任务写，不按学说写）

```
# 带出处的术语与引文查询

给 AI 一个可核验的知识源：每个定义都带原文、章节与字符区间。

适合：
- 查一个术语在元意识学说里的准确定义与出处
- 核对一句引文是否真实存在
- 查两个概念之间的关系

工具：mcai_answer / mcai_concept / mcai_search / mcai_related / mcai_cite / mcai_provenance / mcai_list
```

### 观察

- 广场页浏览量；
- 实验场调用次数；
- 我们的 `/api/v1/usage` 业务调用是否从 0 变 1。

## 五、不做什么

- 不在三个平台同时铺开；
- 不为上架改学说定义；
- 不买榜、不刷量。
