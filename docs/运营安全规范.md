# 运营安全规范（MCAI 项目）

> 项目是长期、长尾、不急迫的。**安全、长期、永续**优先于任何短期产出。
> 任何工作开始前，先过一遍本清单；有风险就提示、暂停或放弃。

## 一、总原则

1. 不出状况优先于出成果；
2. 不确定就不做，先问；
3. 被平台限制或警告过的做法，永久不再用；
4. 不用「试探边界」的方式换取流量或数据。

## 二、开工前风险检查

每次接到任务，先判断六类风险：

| 类别 | 要检查什么 | 高风险示例 |
|---|---|---|
| 版权 | 是否使用他人原文、译注、整理本 | 复制现代点校本、白话译文 |
| 平台规则 | 是否违反外链、导流、刷量、自动化条款 | 批量发链接、刷评论、爬取登录后内容 |
| 内容安全 | 是否涉及敏感话题、敏感表述 | 政治、医疗建议、金融承诺 |
| 抓取 | 是否绕过 robots、是否高频请求 | 整站抓取、绕过登录 |
| 隐私 | 是否处理个人信息 | 收集用户聊天、手机号 |
| 自动化 | 是否高频调用、是否影响他人服务 | 循环请求、压测公开接口 |

## 三、风险提示格式

发现风险时，先停下，用三行说清：

```
⚠️ 风险：<一句话>
影响：<可能后果>
建议：<改法 / 暂缓 / 放弃>
```

不做「先做了再说」。

## 四、已经确定的禁区

- 不复制现代点校本、译注、研究著作；
- 不批量群发、不刷评论、不买量；
- 不绕过平台限制（登录墙、频率限制、验证码）；
- 不收集、不存储个人信息；
- 不在被风控的会话里反复重试；
- 不为了「看起来在推进」而做高风险动作。

## 五、遇到异常

1. 立即停止当前动作；
2. 记录时间、现象、已做的操作；
3. 评估是否需要换会话、换路径或放弃；
4. 把结论写进 `HANDOFF.md` 或 `docs/待办.md`。

## 六、判断标准

一个任务是否值得做，先问：

- 出问题会不会影响账号或长期存在？
- 有没有合规的替代做法？
- 不做会损失什么？

如果「不做也没什么损失」，就不做。
