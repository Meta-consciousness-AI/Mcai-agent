> 自动采集：`python tools/metrics_scan.py`，写入 `data/metrics.jsonl`。
> 需要人工/浏览器补查：Zenodo 浏览与下载、Bing 收录状态、第三方提及。

说明：382 次下载集中在 10/29 发布当天，可能包含镜像与扫描服务，不能视为真实用户数。

## 判读规则

| 状态 | 特征 |
|---|---|
| **无人使用** | 下载长期接近 0；无 Star；无第三方提及 |
| **零散使用** | 每周有个位数下载；偶有 Star 或提及 |
| **出现稳定调用** | 连续数周下载增长；Star/引用出现；Zenodo 有下载 |

## 记录节奏

- 每周一 09:00：运行脚本 + 查 Zenodo/Bing，汇报一周变化；
- 每月 1 日 09:00：汇总趋势，写一段结论（无人使用 / 零散使用 / 稳定调用）。

## 调用侧信号（2026-11-01 新增）

远程 MCP 增加 `GET /api/v1/usage`（Bearer 令牌），返回调用次数与按工具分布。这是目前最直接的「有没有 Agent 在调」信号，不依赖平台登录。

已知限制：计数器保存在容器文件里，重新部署或缩容会归零；云端 stdout 也会打 `[usage]` 行，可在 CloudBase 日志里做长期统计。


## Coze / 魔搭 统计（2026-11-01 核查）

| 平台 | 是否有统计 | 结论 |
|---|---|---|
| Coze | 免费版无数据分析面板；商店页前端渲染，无公开使用数 | 不可获取 |
| 魔搭 MCP | 服务页存在，但公开 API 不返回调用数据 | 不可获取 |

因此调用侧目前只有一个可用信号：**远程 MCP 的 `/api/v1/usage`**。

其计数保存在容器内 `data/usage.jsonl`，重新部署会归零；如需长期留存，应改用 CloudBase 日志中的 `[usage]` 行，或把计数写入外部存储（后续再评估）。
