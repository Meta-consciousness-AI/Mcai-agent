# 工作法：会话管理

> 建立：2026-11-22
> 目的：让会话长度可控，同时不丢项目状态。

## 一、原则

1. **一个会话，一个阶段/领域**；
2. 主会话负责决策与跨领域，不承担长执行；
3. 长期记忆放文件，不靠上下文；
4. 换会话不是重新开始，是换工作台。

## 二、什么时候开新会话

满足任一条件就开：

- 新目标需要独立工作 **30 分钟以上**；
- 进入不同领域（发布、平台、内容、理论、搜索、运维）；
- 当前会话上下文超过约 **60%**，或频繁出现 transport failed；
- 需要与当前工作并行；
- 发布/部署前，需要一份干净的检查清单。

## 三、什么时候不换

- 同一问题的短追问；
- 需要刚讨论过的细节才能继续；
- 只是改一个数字、补一句话。

## 四、命名

格式：

```
mcai-knowledge-0000   永久历史主会话
mcai-knowledge-0001   当前主会话
mcai-knowledge-0002   起，专项会话
```

四位固定，单调递增，永不复用；`0000` 专用于永久历史主会话。

- 编号是唯一身份，**名字里不带领域词**；领域、范围、状态一律写在 `docs/会话台账.md`；
- 旧的后缀命名（`-platform`、`-content`、`-release`、`-search`、`-ops`，以及 `-platform-2` 这类加序号的写法）**已于 2026-11-22 废止**，只在台账备注里保留来源说明；
- 不建议加日期；日期放在 HANDOFF 里。

## 五、开新会话的步骤

1. 先更新 `HANDOFF.md` 和 `docs/待办.md`；
2. 在 DSH 左侧点「新会话」；
3. 工作区、预设保持与当前一致；
4. 第一句写：

```
先读 HANDOFF.md 和 docs/待办.md。
本次会话范围：<一句话>。
```

5. 不要再复述完整历史；需要细节时读对应文件。

## 六、当前格局（2026-11-22）

**唯一权威是 `docs/会话台账.md`；本节不复制清单，避免两处各写一套、日后漂移（这次命名冲突就是这么来的）。**

截至 2026-11-22：`0000` 永久历史主会话，只做低频战略与重大决策、不承担执行；`0001` 当前主会话，日常决策与最终裁定；`0002` 平台专项，paused，等 11-25 Bing 复查；`0003` N08 内容审校，planned；`0004` 发布，planned，通常并入 `0002`。旧称呼 `mcai-knowledge-platform / content / release` 已废止。

## 七、判断口诀

> 新目标、新领域、长任务、上下文超六成——开新会话。
> 短追问、同细节、改数字——留在原会话。

## 会话上限与生命周期

- **会话上限**：一般 3 个，工作量大 5 个，工作量超大 9 个（硬上限）；
- 专项会话是任务型的，任务完成就结束，不长期挂着；
- 同一领域复用同一个专项，不按小任务碎开；
- 发布、搜索、注册表等平台事务，尽量并入 `platform`；
- Git、备份、维护并入 `ops`；
- 理论辨析暂不单开，重大问题回主会话；
- 新会话必须由主会话定名，并登记到 `docs/会话台账.md`；
- 关闭/移除前，先把状态写进 HANDOFF 和台账。

### 生命周期

```
planned → active → paused → closed
```

- `active`：正在用；
- `paused`：等外部信号（如 Bing 11-25）；
- `closed`：任务完成，台账保留记录，会话可关闭/移除。

## 协作语言

- 对专项会话说「我们的指令是」「我们的补充指令是」；
- 不说「主会话指令」，不把会话当下属或工具；
- 关闭、状态、归档由我们决定，不写成对它的命令；
- 新会话未磨合，指令要写边界、风险和停止条件。

## 会话工作量分级

依据：DSH 没有轮次/步数硬上限，真正限制是上下文窗口与压缩。详见 `docs/研究-DSH会话与上下文机制.md`。

| 级别 | 用户轮次 | 工具步数 | 上下文 | 处理 |
|---|---:|---:|---:|---|
| 轻 | < 30 | < 150 | < 10% | 并入现有会话 |
| 标准 | 30–100 | 150–500 | 10–30% | 一个专项会话 |
| 重 | 100–300 | 500–1500 | 30–50% | 50% 前压缩，尽快收口 |
| 超大 | > 300 | > 1500 | > 50% | 只做决策，不再执行 |

主动阈值：50% 收尾，60% 停止接新执行，70% 必须压缩/换会话，80% 自动压缩已偏晚。

专项会话最低工作量：至少 30 分钟、30 个用户轮次或 100 个工具步，或有明确独立交付物；否则并入现有会话。
