# 工作法：会话管理

> 建立：2026-11-22
> 目的：让会话长度可控，同时不丢项目状态。

## 一、原则

1. **一个会话，一个阶段/领域**；
2. 主会话负责决策与跨领域，不承担长执行；
3. 长期记忆放文件，不靠上下文；
4. 换会话不是重新开始，是换工作台。

## 二、什么时候开新会话

满足任一条件就开：

- 新目标需要独立工作 **30 分钟以上**；
- 进入不同领域（发布、平台、内容、理论、搜索、运维）；
- 当前会话上下文超过约 **60%**，或频繁出现 transport failed；
- 需要与当前工作并行；
- 发布/部署前，需要一份干净的检查清单。

## 三、什么时候不换

- 同一问题的短追问；
- 需要刚讨论过的细节才能继续；
- 只是改一个数字、补一句话。

## 四、命名

格式：

```
mcai-knowledge-<domain>
```

domain 用短词，小写，不超过 3 个词：

| 后缀 | 用途 |
|---|---|
| `release` | 打包、发布、部署、回滚 |
| `platform` | MCP 平台、扣子、魔搭、注册表 |
| `content` | 问答、关系、文章、语料 |
| `theory` | 理论辨析、本体论、概念体系 |
| `search` | Bing、Google、百度、AI 搜索可见性 |
| `ops` | 备份、监控、日常维护 |

需要重复时加序号：

```
mcai-knowledge-platform-2
```

不建议加日期；日期放在 HANDOFF 里。

## 五、开新会话的步骤

1. 先更新 `HANDOFF.md` 和 `docs/待办.md`；
2. 在 DSH 左侧点「新会话」；
3. 工作区、预设保持与当前一致；
4. 第一句写：

```
先读 HANDOFF.md 和 docs/待办.md。
本次会话范围：<一句话>。
```

5. 不要再复述完整历史；需要细节时读对应文件。

- 新建 `mcai-knowledge-platform`：处理 MCP 注册表 0.4.3、扣子简介、Bing 等平台事务；
- 之后新建 `mcai-knowledge-content`：处理 N08 下一轮问答/关系审校；
- 发布频繁时用 `mcai-knowledge-release`，不与内容混在一起。

## 七、判断口诀

> 新目标、新领域、长任务、上下文超六成——开新会话。
> 短追问、同细节、改数字——留在原会话。
