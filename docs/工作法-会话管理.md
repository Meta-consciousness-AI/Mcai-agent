# 工作法：会话管理

> 建立：2026-11-22
> 目的：让会话长度可控，同时不丢项目状态。

## 一、原则

1. **一个会话，一个阶段/领域**；
2. 主会话负责决策与跨领域，不承担长执行；
3. 长期记忆放文件，不靠上下文；
4. 换会话不是重新开始，是换工作台。

## 二、什么时候开新会话

满足任一条件就开：

- 新目标需要独立工作 **30 分钟以上**；
- 进入不同领域（发布、平台、内容、理论、搜索、运维）；
- 当前会话上下文超过约 **60%**，或频繁出现 transport failed；
- 需要与当前工作并行；
- 发布/部署前，需要一份干净的检查清单。

## 三、什么时候不换

- 同一问题的短追问；
- 需要刚讨论过的细节才能继续；
- 只是改一个数字、补一句话。

## 四、命名

格式：

```
mcai-knowledge-0000   永久历史主会话
mcai-knowledge-0001   当前主会话
mcai-knowledge-0002   起，专项会话
```

四位固定，单调递增，永不复用；`0000` 专用于永久历史主会话。

- 编号是唯一身份，**名字里不带领域词**；领域、范围、状态一律写在 `docs/会话台账.md`；
- 旧的后缀命名（`-platform`、`-content`、`-release`、`-search`、`-ops`，以及 `-platform-2` 这类加序号的写法）**已于 2026-11-22 废止**，只在台账备注里保留来源说明；
- 不建议加日期；日期放在 HANDOFF 里。

## 五、开新会话的步骤

1. 先更新 `HANDOFF.md` 和 `docs/待办.md`；
2. 在 DSH 左侧点「新会话」；
3. 工作区、预设保持与当前一致；
4. 第一句写：

```
先读 HANDOFF.md 和 docs/待办.md。
本次会话范围：<一句话>。
```

5. 不要再复述完整历史；需要细节时读对应文件。

## 六、当前格局（2026-11-22）

**唯一权威是 `docs/会话台账.md`；本节不复制清单，避免两处各写一套、日后漂移（这次命名冲突就是这么来的）。**

截至 2026-11-22：`0000` 永久历史主会话，只做低频战略与重大决策、不承担执行；`0001` 当前主会话，日常决策与最终裁定；`0002` 平台专项，paused，等 11-25 Bing 复查；`0003` N08 内容审校，planned；`0004` 发布，planned，通常并入 `0002`。旧称呼 `mcai-knowledge-platform / content / release` 已废止。

## 七、判断口诀

> 新目标、新领域、长任务、上下文超六成——开新会话。
> 短追问、同细节、改数字——留在原会话。

## 会话上限与生命周期

- **会话上限**：一般 3 个，工作量大 5 个，工作量超大 9 个（硬上限）；
- 专项会话是任务型的，任务完成就结束，不长期挂着；
- 同一领域复用同一个专项，不按小任务碎开；
- 发布、搜索、注册表等平台事务，尽量并入 `platform`；
- Git、备份、维护并入 `ops`；
- 理论辨析暂不单开，重大问题回主会话；
- 新会话必须由主会话定名，并登记到 `docs/会话台账.md`；
- 关闭/移除前，先把状态写进 HANDOFF 和台账。

### 生命周期

```
planned → active → paused → closed
```

- `active`：正在用；
- `paused`：等外部信号（如 Bing 11-25）；
- `closed`：任务完成，台账保留记录，会话可关闭/移除。

## 协作语言

- 对专项会话说「我们的指令是」「我们的补充指令是」；
- 不说「主会话指令」，不把会话当下属或工具；
- 关闭、状态、归档由我们决定，不写成对它的命令；
- 新会话未磨合，指令要写边界、风险和停止条件。

## 会话工作量分级

依据：DSH 没有轮次/步数硬上限，真正限制是上下文窗口与压缩。详见 `docs/研究-DSH会话与上下文机制.md`。

| 级别 | 用户轮次 | 工具步数 | 上下文 | 处理 |
|---|---:|---:|---:|---|
| 轻 | < 30 | < 150 | < 10% | 并入现有会话 |
| 标准 | 30–100 | 150–500 | 10–30% | 一个专项会话 |
| 重 | 100–300 | 500–1500 | 30–50% | 50% 前压缩，尽快收口 |
| 超大 | > 300 | > 1500 | > 50% | 只做决策，不再执行 |

主动阈值：50% 收尾，60% 停止接新执行，70% 必须压缩/换会话，80% 自动压缩已偏晚。

专项会话最低工作量：至少 30 分钟、30 个用户轮次或 100 个工具步，或有明确独立交付物；否则并入现有会话。

## 执行会话的量化分流（2026-11-22 定）

### 一、度量口径

1. **上下文占用 %**（DSH 界面显示）——唯一硬指标；
2. 工具步数——次指标；
3. 用户轮次——只作参考。

会话自己看不到百分比，所以由**用户看界面并告知**；会话在交接时自报轮次与步数。经验换算（据主会话样本 2045 轮 / 6362 步 = 45%）：约 **45 轮 ≈ 1%**、**140 步 ≈ 1%**，只用于开工前估算，不作判据。

### 二、四个阈值（执行会话 `0002`、`0003`、…）

| 上下文 | 动作 |
|---:|---|
| **50%** | 进入收尾：不再接新的独立任务，只把手上这件做完 |
| **60%** | 停止接执行 + 写交接段 + 回报 `0001` |
| **70%** | **硬触发换会话**：`0001` 开下一个编号，剩余任务整段移交，本会话转 `paused` |
| **80%** | 封顶：不再改任何文件，只回一句「已达上限，请换会话」 |

**为什么是 70% 而不是 80%**：DSH 自动压缩的阈值约在窗口的 80%（`floor(min(W×0.8, W−O−65536))`）。一旦触发，旧历史被摘要替换，交接细节会失真。必须留出约 10% 给「交接本身」——写文件、核验、回报都要花上下文和工具步。拖到压缩发生过再交，交出去的就是一份残缺的摘要。

### 三、交接的最小内容

四行，缺一不算交接：

1. 改了哪些文件、哪几个提交；
2. 还剩什么没做；
3. 下一步交给谁（哪个会话、哪个文件）；
4. 停止条件（什么情况下不要继续做）。

写进 `HANDOFF.md` 的「执行交接」段，并回报 `0001`。

### 四、开工前先估批

预计消耗超过 **20%** 上下文的活儿，一次不批，拆成两批，先做前一半。理由：跑到 70% 才发现干不完时，已经来不及做干净交接。

### 五、新任务往哪走

- `0002` 是**执行主渠道**，不限于平台事务：新的执行工作默认进 `0002`；
- `0002` 达到 60% 后，新任务**不再进 `0002`**，直接进 `0003`，不排队等它清空；
- 专项会话不自行开新会话；需要时回报 `0001` 定名。
- **定时任务不新开会话承载执行工作**（2026-11-23 定）：周检、月复盘一类定期执行，也进 `0002`；定时器只投给 `0001`，由 `0001` 写指令、用户转交。开会话的唯一理由是 `0002` 到了 70% 阈值，或用户明确要求。

### 派活的方式：主会话写指令，用户转交

`0001` 不直接操作执行会话。派活的形态是**一份执行指令**，由用户粘给对方：

1. 现状（已发生的事实、版本、提交、时间）；
2. 我们的补充指令（要做的一两件事，写死范围）；
3. 禁止项（不要提交 / 不要改内容 / 不要 force 之类）；
4. 报告要求（回报什么、回到谁）；
5. 停止条件（什么情况下停手等指令）。

**报告要求默认写死为**：结果落盘到 `docs/执行回执/YYYY-MM-DD-HHmm-<任务>.md`（格式见该目录 `README.md`），会话里只说一句「回执已写，路径是…」。原因：`0001` 读不到执行会话的对话，只读得到工作区文件；贴在聊天里的结果，会话一换就没了。

### 六、主会话自己的阈值

对称适用，但更早：**40% 开始收尾、50% 交接换人**。主会话的价值在「轻」，一旦变重，判断质量下降比执行会话失控更危险。

换代时取下一个可用编号（当前为 `0005`），台账里「当前主会话」标记随人走，旧主会话转 `archived`、仍可查。
