# Zenodo 数据：人还是爬虫

> 时间：2026-11-13
> 对象：数据集、预印本、规范 V1.1、规范 V1.3
> 结论先说：公开统计无法直接区分人与爬虫，只能做倾向性推断。

## 二、能推断的

### 1. 没有重复下载

四个记录的「下载数 = 唯一下载数」，说明没有同一会话反复拉取。
排除「一个人狂点」，但不能排除「许多不同的机器人」。

### 2. 三条记录同步增长

11-12 → 11-13：

| 记录 | 浏览增量 | 下载增量 |
|---|---:|---:|
| 预印本 | +13 | +2 |
| 规范 V1.1 | +13 | +3 |
| 规范 V1.3 | +13 | +3 |

同一天、同样 +13 浏览，更像系统性行为（聚合器、爬虫，或同一批读者连点相关记录），不像自然阅读。

### 3. 数据集下载很少

14 天 4 次下载，全部唯一会话。这个量级更像真人，或少量爬虫。

## 三、判断

| 记录 | 倾向 |
|---|---|
| 数据集 | 少量真人或少量爬虫，无法区分 |
| 预印本 | 文章点击 + 部分爬虫 |
| 规范 | 同步增长，系统性行为概率较高 |

## 四、方法极限

- Zenodo 不公开访问日志、referrer、时间序列；
- 「唯一」只按会话去重，不识别 UA；
- 我们自己的检查也贡献浏览；
- 因此不能给出「多少人、多少机器人」的确定数字。

## 五、可改进的做法（已纳入工作计划）

以后文章里的 DOI 链接，先经过我们自己的 `/r`：

```
https://<mcp-host>/r?src=doi-zhihu
```

它记录一次点击，再 302 到 DOI。

对比两个数：

- 我们记到的点击；
- Zenodo 当天增加的浏览/下载。

差值大 → 中间有爬虫或未被记录；接近 → 更可能是真人。

## 六、下次发文章时的具体改法

1. 正文里不再直接写 `https://doi.org/...`；
2. 改为 `https://mcai-mcp-public-338698-11-1316838521.sh.run.tcloudbase.com/r?src=doi-<平台>`；
3. `src` 用平台名：`doi-zhihu`、`doi-wechat`、`doi-juejin`、`doi-weibo`；
4. 发布后 7 天，对比 `/r` 日志与 Zenodo 增量。
