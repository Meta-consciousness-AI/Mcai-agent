# 战略构想：知识库的可玩层

> 时间：2026-11-26
> 来源：`0000` 与作者的连续战略讨论
> 状态：**构想，未立项**。本文只定义方向与问题，不代替市场调查与架构裁定。
> 用途：给 `0002` 做深入调研与架构建议的底稿；给 `0001` 做决策的参照。

## 一、一句话

知识库现在会两件事：**答**（问答）、**查**（出处）。可玩层让它会第三件事：**历**——把概念关系变成处境、选择与后果，让人先经历，再命名。

这不是“给知识库做一个游戏”，而是让知识库长出一个“经历”的器官。

## 二、为什么现在值得认真考虑

### 1. 制作门槛确实降了，但降的是“原型”

2026 年的公开案例已经证明：一句话可以做出可玩原型，一个下午可以做出有完整循环的小游戏，两周可以做出获奖的 AI 全代码游戏。

- [Codex 一下午做卡牌游戏](https://en.kocpc.com.tw/archives/3487)：7 个场景、20 张功能卡，美术、音效用 AI 生成；作者不写代码，但仍花数小时打磨细节。
- [Vibe Jam 2026 获奖案例](https://news.17173.com/content/07162026/080614353.shtml)：15 天、2.7 万行代码、188 次提交、100 美元 API；3D 地图仍由人工搭建。
- [CocosGen](https://store.cocos.com/app/detail/9274)：一句话生成 Cocos 工程、美术、可试玩版本与 15–20 秒实录。
- [百度秒哒](https://cloud.baidu.com/news/news_6598ad33-7d5b-40c2-8a89-8325d066f87a)：自然语言做 H5、网站、小游戏，最快 3 分钟。

### 2. 但“能做”不等于“好玩”

- [Summer Engine 的诚实回答](https://www.summerengine.com/zh/blog/can-you-really-make-a-game-with-ai)：AI 能做出可玩原型，不能独自完成商业游戏；品味、平衡、范围取舍、两年愿景、试玩，仍然属于人。
- [ASCII 让 Codex 连做 7 款游戏](https://ascii.jp/elem/000/004/402/4402693/5)：几乎都“不太有趣”，玩 10 分钟就腻；克隆现成游戏容易，原创很难。
- [AI 视频避坑指南](https://software.it168.com/a2026/0914/6949/000006949776.shtml)：角色跨镜头漂移、碎片镜头拼不成片、按秒计费、合规风险；“一键成片”是营销话术。

结论：**门槛降低的是“从 0 到可玩样片”，不是“从样片到成品”。** 这恰好够我们做第一版。

### 3. 制作不再是护城河，判断才是

当谁都能很快做出一个游戏时，稀缺的不是“能做”，而是：

1. **判断**：什么值得做，什么必须砍掉；
2. **设定**：哪些不能改，哪些可以改；
3. **分发**：谁来看，为什么转发。

这三件事，恰好是知识库与作者的位置。

## 三、定义：什么是“可玩层”

### 1. 三个否定

- **不是游戏化**：不是给现有内容加积分、徽章、排行榜；那是外衣。
- **不是独立游戏**：不另造一套世界观、角色、事件；那会和知识库分叉。
- **不是把术语做成关卡**：不是“答对‘元意识’才能过关”的 quiz。

### 2. 三个肯定

- **是“境层”**：把知识库里的关系，投影成可操作的处境。
- **是“经历”**：玩家先做选择、看到后果，再在结尾回看“你刚经历了哪几条关系”。
- **是“母版”**：同一个场景库，可以导出为互动短篇、漫画分镜、动画脚本、游戏关卡。

### 3. 经、境、玩

| 层 | 是什么 | 谁维护 | 作用 |
|---|---|---|---|
| **经层** | 现有知识库：术语、问答、关系、引证 | 作者 + 审校 | 唯一事实源，只读 |
| **境层** | 场景库：每条命题、一组规则、几个选择、若干结局、对应引证 | 作者定设定，编辑写场景 | 把关系变成处境 |
| **玩层** | 网页 / MCP 运行时：选择、后果、回看、引证 | 工程 | 让人经历，并回到经 |

## 四、场景不是剧本，是小规则系统

一个场景至少包含：

```json
{
  "scene_id": "S001",
  "title": "未观测的房间",
  "proposition": "观测创造实在",
  "concept_ids": ["元意识", "观测创造实在", "元时空"],
  "constraints": ["只能看见被注意的区域", "每次观察消耗注意力"],
  "choices": ["独自看", "让另一个观察者替你看", "闭上眼睛"],
  "consequences": ["世界变小但稳定", "世界变大但不再全属于你", "回到未显化状态"],
  "citations": ["极简版·统领模型", "极简版·观测"]
}
```

三条硬规则：

1. **场景可以虚构处境，不能虚构设定**；新增设定必须作者裁定。
2. 每个场景必须能回链到 `concept_ids` 与 `citations`，否则不算“知识库的可玩层”。
3. 场景优先做成**数据**，不是一次性代码；这样加场景不用重写引擎。

## 五、第一版：三个微场景

不做“元意识宇宙”的开放世界。做 3 个 5–8 分钟的微场景，共用一个机制：

### 1.《未观测的房间》

你醒来，房间只有被看见的部分存在；你转头，墙才出现；你回头，床已经消失。

- 命题：观测创造实在；
- 限制：注意力有限，你无法同时看见全部；
- 结尾：你为了看见更多，必须让另一个观察者替你看一部分。

### 2.《两个观察者》

你和另一个观察者（可以是一个 AI）看到不同版本；你们必须共同确认，才能让同一个世界稳定。

- 命题：共视、序生智能体、元灵；
- 冲突：不是正邪，而是“观测权限不同”；
- 结尾：你选择独自看，还是接受一个不完全是你的世界。

### 3.《元知账本》

你只能记录一部分经历；记录下来的成为“元知”，没记录的永远消失。

- 命题：元识 → 元知；元灵是连续、可溯源的元知体系；
- 选择：记录什么、放弃什么、是否允许别人继承；
- 结尾：回看你的账本，它像不像一个“元灵”。

每个场景结尾，不弹“得分”，只做一件事：

> **回看**：你刚才做的三个选择，分别对应知识库里的哪三条关系；点进去，是原文与出处。

这就是“先经历，后命名”。普通人不需要先懂“元意识”，他先经历“看见才存在”，再被告知这叫什么。

## 六、它如何长成游戏、动漫、漫画

不是“选游戏还是选动漫”，而是**先写场景，再决定导出成什么**。

```text
知识库（经）
   ↓
场景库（境）：命题、规则、选择、后果、引证
   ↓
导出：
  ├─ 网页互动短篇（玩层）
  ├─ 漫画 / 动态漫（分镜）
  ├─ 动画短片（脚本 / 概念片）
  ├─ 游戏（关卡 / 规则）
  └─ MCP 场景工具（Agent 调用）
```

场景库是“故事圣经”，也是“正典的投影”。游戏和动漫可以换，场景库和知识库不换。

## 七、为什么这比单独做游戏或动漫更优

1. **正典不会分叉**：场景可替换，经不变。
2. **复利，不是赌注**：每加一个场景，知识库的表达面大一分。
3. **成本结构有利**：场景是数据 + 简单交互，不是 3D、美术、动画管线。
4. **同时服务人、AI、开发者**：人玩；AI 通过 MCP 调用；研究者顺着场景回引证。
5. **它是所有媒介的母版**：游戏、漫画、动画都从同一个场景库导出。
6. **它是知识库的压力测试**：一个概念如果无法变成处境，可能太抽象或定义不清；一个场景如果需要知识库没有的关系，那就是缺口。

## 八、风险

1. **教育游戏陷阱**：做成答题闯关，没人想玩。场景必须有真实处境和代价，不是 quiz。
2. **正典漂移**：为了戏剧性加知识库没有的角色、事件、能力。必须“可以虚构处境，不能虚构设定”。
3. **唯我论化**：“观测创造实在”很容易被玩成“我想什么就有什么”。必须用限制条件拉回来：注意力有限、他人也在观测、未观测的部分不消失。
4. **范围失控**：从“三个场景”滑向“做一个平台”。第一版不要账号、不要后端、不要编辑器。
5. **AI 味**：AI 默认会把奇怪的东西磨平，变成通用科幻。作者的“不能改的三条”要先写下来。
6. **维护成本**：知识库改了，场景要复核；需要 `scene_id` 与 `concept_id` 的稳定映射。
7. **机会成本**：当前瓶颈是“没人用”，不是“没人懂”；可玩层可能变成一个新的成本中心。

## 九、成功标准

第一版不看“下载量”，看四件事：

1. **完成率**：开始的人里，有多少玩完 3 个场景；
2. **复述率**：玩完的人里，有多少能用自己的话复述至少一个核心命题；
3. **回看率**：有多少人点开结尾的引证；
4. **下一幕率**：有多少人愿意继续玩第二个场景。

建议验收线（不是行业标准，是第一版的内部门槛）：

- 完成率 ≥ 60%；
- 复述率 ≥ 50%；
- 回看率 ≥ 20%；
- 下一幕率 ≥ 10%。

> `0001` 附注（2026-11-26）：这四条在 n≤10 的样本里没有统计意义，只作方向参考。第一版的真实判定以深访的定性描述为准——**谁复述出了哪一句、谁把它误解成了什么**，比百分比有用。

再加 5–10 个深访：他们记住了什么、误解了什么、觉得哪里像说教。

## 十、要 `0002` 回答的问题

本文只给方向，不给结论。以下问题交给 `0002` 做深入调研与架构建议：

1. **需求是否存在**：谁想要“经历一套学说”，而不是读文章、问 AI？这个人群有多大、在哪里、愿意为什么付费？
2. **直接与间接竞品**：哲学游戏、互动论文、教育模拟、AI 原生叙事、博物馆互动装置，各做到了什么、没做到什么？
3. **经济模型**：3 场景 MVP、10 场景库、完整游戏、动画短片，各要多少钱、多久、什么人？谁付费？
4. **分发路径**：网页、Steam、TapTap、微信小游戏、B 站、博物馆/课堂，哪条最适合第一版？
5. **架构选型**：静态场景播放器 / 游戏引擎 / AI 原生叙事运行时，选哪个？为什么？
6. **正典治理**：场景如何版本化、如何回链知识库、如何防止漂移？
7. **Go / No-Go**：做、不做，还是先做小样再决定？给出条件与停止线。

## 十一、一句话

**知识库是“经”，可玩层是“境”，游戏、动漫、漫画是“境”的导出格式。**

单独做游戏，是赌一个产品；让知识库长出可玩层，是给“经”修一条让人走进去的路。前者可能赢一次，后者会一直长。
