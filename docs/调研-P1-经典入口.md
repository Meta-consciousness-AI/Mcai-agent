# 调研 P1：经典打头，学说搭车

> 时间：2026-11-17
> 问题：以公版经典作入口，是否还有空间？

## 一、谁在做（全部免费）

| 平台 | 资源 | 能力 | 状态 |
|---|---|---|---|
| 识典古籍（字节 + 北大） | 7 万部以上古籍，16000+ 阅读平台 | OCR、自动标点、多版本校勘、AI 助手、图文对照 | 免费开放 |
| ctext.org | 中国哲学书电子化计划 | API（按 URN 取原文）、被 Agent 工具直接接入 | 免费 |
| 上海图书馆开放数据 | 97 个接口（古籍、家谱、碑帖、诗词 199 万首） | 已有第三方封装的 MCP（12 工具） | 免费，需 API Key |
| 书格 shuge.org | 700+ 高清古籍 | 第三方 MCP（7 工具） | 免费 |
| 古联 籍合网 / 文达智校 | 7000+ 古籍 + 文史知识库 | 审校、引文核查 | 商业 |
| 识典古籍第三方 MCP | — | 第三方抓取封装 | 免费 |

## 二、判断

1. **资源规模差距悬殊**：7 万部 vs 我们的 3 部；
2. **免费且资金充足**：字节 + 北大、公益平台；
3. **已被 Agent 接入**：ctext API、上图 MCP、书格 MCP 都已存在；
4. **我们的优势只剩「出处规范」**，但用户要的是「能查到」，不是「字段规范」。

## 三、结论

**P1 降为 D（不做产品），保留 B（方法演示）。**

理由：

- 作为入口，打不过免费平台；
- 作为「可核验」示范，仍可用于展示方法，但不构成业务；
- 「学说搭车」的逻辑不成立：经典入口的流量不会自然流向学说。

## 四、教训

内容型入口的竞争，本质是资源规模的竞争。我们没有规模，就不该从入口打。
