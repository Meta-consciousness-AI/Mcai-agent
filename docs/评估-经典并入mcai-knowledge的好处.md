# 评估：把三部经典并入 mcai-knowledge 的好处

> 时间：2026-11-19
> 与《评估-经典并入mcai-knowledge的风险》配套阅读。
> 结论先说：**好处真实，但大多是间接的；只有底本与质量过关后才成立。**

## 一、好处清单

### 1. 证明方法可迁移（确定性最高）

- 论文里已经写了「三部经典复现」，但外人看不到实物；
- 并入后，任何人都能用同一个 MCP 查经典、看区间、核对原文；
- 「一套方法，四种文本」从说法变成可检验的事实。

**价值：高；概率：高；前提：底本可交代。**

### 2. 让「可核验」不只对一个学说成立

- 现在的能力容易被理解成「为元意识定制」；
- 加入公版经典后，可以证明这是**通用方法**，不是自说自话；
- 对审稿人、对潜在合作方，这比任何介绍都有说服力。

**价值：高；概率：高。**

### 3. 扩展真实使用场景

- 查「元意识」的人极少；查「道德经原文」「孙子兵法某句」的人多得多；
- ctext 的流量说明古籍查询是真实需求；
- Agent 在写作、校对、引用场景里，也可能需要查经典原文与出处。

**价值：中高；概率：中；竞争强（识典、ctext、古联）。**

### 4. 提升数据集与 DOI 的完整性

- 现在的数据集主要是元意识库；
- 加入三部经典后，成为「四语料可核验知识资产」，对研究者更有用；
- 与论文、预印本的口径一致。

**价值：中；概率：高。**

### 5. 给工具链与基准做真实回归

- 三份经典文体不同（格言、条文、论说），能暴露规则缺口；
- 并入后每次发布都要跑四库回归，质量更稳；
- 复现中发现的单字术语、数字编号等问题，已经反哺了主库。

**价值：中；概率：高。**

### 6. 降低合作门槛

- 对古籍机构、数字人文实验室，经典比元意识更容易对话；
- 「我们能把《孙子兵法》做到逐字可回查」比「我们有一个新学说」更易被理解。

**价值：中；概率：中。**

### 7. 品牌层面的「一体多面」

- 一个可核验的知识底座，既能承载原创学说，也能承载公版经典；
- 这比「只做一个学说」更有长期想象力。

**价值：中；概率：中；但容易被误解为「什么都做」。**

## 二、好处的依赖条件

| 好处 | 依赖 |
|---|---|
| 方法可迁移 | 底本可交代、引文可回查 |
| 通用方法 | 至少两种文体过质量门槛 |
| 真实场景 | 检索质量、入口词、渠道 |
| 数据集完整性 | 许可清晰、版本可追溯 |
| 回归价值 | 自动化测试覆盖四库 |
| 合作门槛 | 有署名、有底本、有案例 |
| 一体多面 | 定位表达清楚，不让人以为转做古籍 |

**没有这些条件，好处会变成反作用。**

## 三、与「不并入」相比

| 方案 | 好处 | 风险 |
|---|---|---|
| 不并入 | 定位纯粹，风险最低 | 方法可迁移只能靠论文描述 |
| 并入主库 | 场景、数据、证明力都增强 | 定位漂移、答错库、薄定义伤品牌 |
| **单独做成「示例经典」** | 拿到大部分好处，定位不混 | 需要多一套入口与维护 |

**单独做成示例**，是好处与风险的平衡点：

- 同一个 MCP 服务，但用独立命名空间与独立工具/集合；
- 主回答仍以元意识为主；
- README 明确写「示例文本，用于验证方法」。

## 四、净评估

- **确定性收益**：方法可迁移的公开证据、四库回归、数据集完整性；
- **不确定性收益**：古籍流量、合作机会、品牌延展；
- **主要成本**：底本与署名工作、路由改造、长期维护、定位解释；
- **结论**：收益大于成本，**但只在「底本清楚 + 至少一种文体过门槛」之后**。

## 五、建议

1. 先补《孙子兵法》底本与署名（thin 7.7%，已过门槛）；
2. 以「示例经典」形式并入，不并入主回答路由；
3. 道德经、荀子修到 thin < 20% 再逐步加入；
4. 每次加入都跑四库回归与基准；
5. 对外表述统一为「示例文本，用于验证可核验方法」。

## 六、一句话

**并进去的最大好处，不是多一个古籍库，而是让「可核验」从主张变成可检查的事实；前提是别拿薄库去证明。**
