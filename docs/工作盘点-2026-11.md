# 工作盘点与后续路线（2026-11-04）

## 一、主框架是否完成

端到端链路已经跑通：

```
语料 → 抽取 → 知识库 → 站点 / 数据集 / MCP → 内容分发 → 证据与收录
```

| 层 | 内容 | 状态 |
|---|---|---|
| 数据层 | 64 概念、122 问答、270 关系、213 引证；四语料复现 | 完成 |
| 产品层 | MCP 5 工具、HTTP API、站点 70 页、数据集、agent.json / openapi.json | 完成 |
| 分发层（机器） | PyPI、官方注册表、Glama、mcprush、魔搭、Coze | 基本完成 |
| 分发层（人） | 公众号、知乎、掘金、微博、小红书、视频号、抖音、快手、腾讯视频、爱奇艺 | 完成 |
| 证据层 | Zenodo DOI、PhilArchive、IndexNow、sitemap | 完成 |
| 运营层 | 指标记录、两周观察、发现工作计划 | 有骨架，缺闭环 |

**结论：框架完成度约 80%。** 缺的不是新功能，是「持续运转」和「被看见」。

## 二、还缺什么

### A. 必须补的（影响判断）

1. **使用数据的闭环**
   - 现在有 `/api/v1/usage`，但没有固定查看节奏与归因；
   - 缺：每周一次的数据快照、渠道来源区分（站内 / MCP / 内容平台）。

2. **渠道清单与季度扫描 SOP**
   - MCP 市场在变，今天有 mcprush，明天可能有新的；
   - 缺：一张「渠道台账」+ 每季度一次的扫描与申请流程。

3. **第三方证据**
   - 目前只有自动收录，没有真实使用案例；
   - 缺：至少 3 个可公开的调用案例或引用。

### B. 可以补的（影响增长）

4. **国内 MCP 平台覆盖**
   - 已做：魔搭、Coze；
   - 待验证：阿里云百炼、百度千帆、火山方舟、讯飞星辰、华为云、Dify 插件市场、Cherry Studio 内置目录；
   - 注意：部分平台只对企业开放或需审核，先验证入口再投入。

5. **英文入口**
   - README 有英文摘要，但文档、示例、错误信息仍以中文为主；
   - 缺：英文 quickstart、英文 issue 模板。

6. **内容节奏**
   - 十个平台已铺，但没有固定栏目；
   - 缺：每月一篇工程笔记或一个短视频的节奏。

### C. 暂不做的

- 新协议（A2A 等）适配：等有真实调用方再评估；
- 自建前端应用：站点已够用；
- 付费/商业化：现在没有使用量，谈定价过早。

## 三、建设还是补充

**比例建议：建设 20%，补充与运营 80%。**

两个建设项：

1. **指标闭环**（1–2 天）：把 usage、平台数据、GitHub/PyPI 汇总成一张周报；
2. **渠道台账 + 扫描 SOP**（0.5 天建立，每季 0.5 天执行）。

其余都是补充：

- 国内平台逐个验证与申请（每个 0.5–2 天，先验证再投入）；
- 案例与评测（3–5 天）；
- 英文 quickstart（1–2 天）；
- 内容节奏（每周 0.5 天）。

## 四、工作量估算

| 工作 | 工作量 | 优先级 |
|---|---|---|
| 指标闭环 + 周报模板 | 1–2 天 | 高 |
| 渠道台账 + 季度扫描 SOP | 0.5 天 | 高 |
| 国内 MCP 平台验证（5–8 个） | 5–10 天（分散） | 中 |
| 3 个使用案例 | 3–5 天 | 中 |
| 英文 quickstart | 1–2 天 | 中 |
| 内容栏目化 | 每周 0.5 天 | 中 |
| 新协议适配 | 暂缓 | 低 |

## 五、建议的四周边界

- 第 1 周：指标闭环 + 渠道台账；
- 第 2 周：国内平台验证（先查入口，能申请就申请）；
- 第 3 周：案例与评测；
- 第 4 周：英文入口 + 复盘。

## 六、判断标准

不按「做了多少平台」算进度，按三个数：

1. 每周真实调用数（MCP / HTTP）；
2. 每周内容带来的站点访问；
3. 是否出现第一个第三方引用或使用案例。

这三个数不动，扩渠道只是增加分母。
