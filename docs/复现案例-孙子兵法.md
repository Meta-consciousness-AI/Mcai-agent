# 复现案例：孙子兵法（第二语料）

> 目的：验证「学说知识资产化规范 V1.0」是否依赖元意识学说的特定内容。

## 一、语料

- 文本：《孙子兵法》十三篇原文（公共领域）；
- 来源：公开镜像 `dooshu/shu` 的 `cn/219.txt`，仅取「原文」段落，剔除注释、译文与按例；
- 规模：14 段（含总序章节标题）、约 8,300 字；
- 工作区：`workspaces/sunzi/`。

## 二、做法

1. 从原文中人工抽取 13 个核心术语，写成「术语：原文句」的词表（`corpus/glossary.txt`）；
2. 原文全文作为 `evidence` 文档，只提供引证；
3. 在 `curated.json` 中补英文名、六类分类与 6 条人工关系；
4. 用同一套流水线构建：`mcai build --home workspaces/sunzi`。

## 三、结果

| 指标 | 元意识学说 | 孙子兵法 |
|---|---|---|
| 概念 | 64 | 13 |
| 问答 | 122 | 17 |
| 关系 | 270（core 18 + derived 6 + mention 246） | 6（全部 core） |
| 引证 | 213 | 9 |
| 引文核验 | 55/55（100%） | 13/13（100%） |
| 页面 | 69 | 18 |

问答抽样：

- 「什么是奇正」→ 命中定义，带 1 条出处；
- 「知彼知己和用间有什么关系」→ 关系路由，返回「依赖」，带 2 条出处；
- 「什么是全胜」→ 命中定义，带 1 条出处。

## 四、哪些流程直接复用

- 术语抽取（`术语：定义` 行）；
- 多源/单源出处记录、字符区间、引文核验；
- 分类、英文名、别名；
- 问答生成（定义型、关系型）；
- 关系分层与 `related` 过滤；
- 站点、数据集、MCP 接口。

## 五、暴露的问题与修复

| 问题 | 表现 | 修复 |
|---|---|---|
| 中文数字开头被误杀 | 「五事」「九地」被当成编号丢弃 | `_BAD_TERM` 改为仅匹配「数字 + 分隔符」 |
| 定义过短 | 「诡道：兵者，诡道也。」长度不足，未识别为术语行 | 补足为原文连续句 |
| txt 文档无位置号 | 所有块 location 为空，索引互相覆盖，引文核验 7.7% | `_text_blocks` 按行号写入 `l1`、`l2`… |

## 六、结论

1. **方法可迁移**：同一套流水线在完全不同的语料上产出了可用的知识库；
2. **词表仍需人工**：古典文本没有现成定义行，必须人工从原文提炼「术语 + 原句」；
3. **关系需人工确认**：散文不会自动产生核心关系，自动「提及」关系在短文本上几乎为零；
4. **规范 V1.1 应补两条**：
   - 对无词表的文本，先做「术语—原句」对照表，再进入抽取；
   - 抽取规则需允许术语以中文数字开头（如「五事」「九地」）。

## 七、复现命令

```bash
python -m mcai build --home workspaces/sunzi
python tools/verify_citations.py --kb workspaces/sunzi/data/kb.json --config workspaces/sunzi/config/corpus.json
```
