# 引文验证器（P1）

> 目的：输入任意知识包，检查每条引文能否在语料中定位、逐字命中、字符区间一致。
> 状态：可用，2026-11-13。

## 一、运行

```bash
python -m mcai.verify --kb data/kb.json --corpus build/corpus.jsonl
```

也可以直接用旧版语料配置：

```bash
python -m mcai.verify --kb data/kb.json --corpus-config config/corpus.json
```

输出 JSON 报告：

```bash
python -m mcai.verify --kb data/kb.json --corpus-config config/corpus.json --json report.json
```

退出码：`0` 全部通过；`1` 存在问题，可用于 CI。

## 二、输入格式

### kb.json

```json
{
  "concepts": [
    {
      "term": "元意识",
      "sources": [
        {
          "doc_id": "minimal",
          "location": "p1",
          "quote": "元意识是宇宙的本源",
          "char_start": 0,
          "char_end": 9,
          "origin": "corpus"
        }
      ]
    }
  ]
}
```

- `origin=corpus`：参与核验；
- `origin=curated`：人工补充，只计数，不核验。

### corpus.jsonl

每行一个文本块：

```json
{"doc_id": "minimal", "location": "p1", "text": "元意识是宇宙的本源，不可描述。"}
```

`doc_id` + `location` 定位到唯一文本块；`quote` 必须能在 `text` 中逐字找到。

## 三、报告字段

| 字段 | 含义 |
|---|---|
| total | 来源总数 |
| curated | 人工补充条数 |
| located | 能找到文本块的条数 |
| exact | 逐字命中 |
| normalized | 忽略空白/全半角后才命中（视为问题） |
| offset_ok | 字符区间与 quote 完全一致 |
| problems | 问题列表：`location_not_found` / `quote_not_in_block` / `offset_mismatch` / `normalized_match_only` |

## 四、设计原则

- 不依赖特定框架：只要能导出 `kb.json` 与 `corpus.jsonl` 就能用；
- 失败要具体：指出哪个术语、哪个文档、哪个位置、哪类问题；
- 可进 CI：退出码 + JSON 报告。
