# 调研 v3：Agent 引用核验的规范与凭证（进行中）

> 依据：`调研计划-v3-Agent核验凭证.md`
> 状态：D 组（需求）第一轮完成，发现关键分层。

## 一、D 组发现：Agent 侧确实有需求

### 证据

1. **缺失引用是公认失败模式**
   来源：[agent-failure-modes / missing-citations](https://github.com/sarkars/agent-failure-modes/blob/main/agents/by-capability/knowledge-retrieval/goals/citation-accuracy/failures/missing-citations.md)
   - 「RAG 管线（LangChain、LlamaIndex）默认不强制每条主张带引用」；
   - 用户无法核验信息来自哪里。

2. **企业采购把「可审计」变成门槛**
   来源：[Prove It Without Keeping It](https://github.com/veerasgutta/enterprise-ai-platform/blob/88d27fde69bf4eae8a37e31cd8d45adb5b0a7960/prove-it-without-keeping-it-zero-retention-audit.md)
   - 受监管买家（医疗、金融、国防、法律、公共部门）把审计从「加分」变成「准入」；
   - 矛盾：审计要留内容，合规要求零留存；
   - 解法是「证明」而非「保存」——正好是凭证的地盘。

3. **企业 Agent 的出处指标已经成形**
   来源：[Accomplir：AI Agent 出典与 Data Provenance 指南](https://accomplir.co.jp/ai-agent-data-provenance-citations-evidence-verification-guide-2026/)
   - 列出最低测量项：根拠付き主張率、引用一致率、古いSource利用率、再現可能率、レビュー時間；
   - 要求把「输入版本、模型、工具、结果、错误、停止理由」绑到同一个执行 ID。

4. **框架层不提供核验**
   来源：[The Neural Base：Citation generation](https://theneuralbase.com/react-prompting/learn/beginner/citation-generation/)
   - LlamaIndex 的 CitationQueryEngine 返回 source_nodes 与字符位置；
   - 但「引用是否忠实」需要自己实现。

## 二、关键发现：这个赛道已经分四层

| 层 | 做什么 | 代表 | 拥挤度 |
|---|---|---|---|
| L1 执行证明 | 证明 Agent 确实跑了、没被改 | SWT3 Witness、Phala、Orgn、@zanii/core | **已拥挤** |
| L2 数据来源 | 数据授权 + 检索链路溯源 | ipto.ai | 兴起中 |
| L3 **内容忠实度** | 引用与原文是否逐字一致 | **少见** | **空档** |
| L4 标准与认证 | 公开规范、基准、凭证 | 无 | **空** |

### L1 玩家（执行证明）

- [SWT3 AI Witness SDK](https://pypi.org/project/swt3-ai/)：零留存下的密码学见证，绑定模型权重、护栏、推理；
- [Phala](https://docs.phala.com/phala-cloud/confidential-ai/confidential-model/compliance-and-open-source)：TEE 证明 + 签名回执，绑定请求/响应哈希；
- [Orgn](https://www.orgn.com/blog/zero-data-retention)：零留存策略 vs 硬件证明；
- [@zanii/core](https://www.npmjs.com/browse/depended/@zanii/core)：Agent 飞行记录器、哈希链、离线验证。

### L2 玩家（数据来源）

- [ipto.ai](https://www.ipto.ai/articles/data-provenance-ai-agents/)：企业数据授权 + 「citation chain」，五个要素（来源证明、版本、时间、权威性等）。

### L3 空档

没有人做「这句话是否真的在原文里」的核验，并把它做成可验证凭证。

L1 证明「跑过」，L2 证明「从哪来」，**L3 证明「引用对不对」**。

## 三、对我们的修正

1. **不做 L1**：TEE、哈希链、回执，已有多个玩家，且需要硬件与合规积累；
2. **不正面做 L2**：ipto 是数据授权商，模式不同；
3. **做 L3**：内容忠实度核验，是空档，也是我们唯一有积累的地方；
4. **对接 L1/L2**：我们的报告可以签名、可以挂到他们的回执体系，不重复造轮子；
5. **L4 是目标**：用 L3 的核验结果，逐步形成公开规范与认证。

## 四、仍然成立的风险

- ipto 这类 L2 玩家可能向下做 L3；
- L1 玩家可能把「引用核验」当增值功能加上；
- 大模型厂商可能内置「引用校验」，但难做到逐字与可审计。

## 五、待查（D 组剩余）

- 企业采购是否明确要求「引用可核验」？
- 定价与交付形态（API、报告、凭证）；
- 中国市场的对应需求与合规要求。

## 六、重大修正：L3 已被商品化（2026-11-16 晚）

### 证据：按条计价的现成产品

| 产品 | 能力 | 价格 |
|---|---|---|
| [Apify Citation & Quote Verifier](https://apify.com/neverempty/citation-quote-verifier/pricing) | 给 URL + 引文，判断原文是否有这句话（精确/归一化/模糊/没有），返回匹配段落、上下文、页面日期、Wayback 快照 | $3.50–10 / 1000 条 |
| [Apify AI Citation Auditor](https://apify.com/franksterino/ai-citation-auditor/pricing) | 抓取每条引用的来源，给出 supported / contradicted / unsupported 与证据片段 | $5 / 1000 条 |
| [CiteLaw](https://citelaw.org/developers) | 法律引文核验 API，文档模式自动抽取引文，按条计费 | 1 credit / 10 条 |
| PursuitAgent | 逐条 claim 验证，$0.01/条（Haiku），整页审计 $0.10–0.30 | 按条 |

结论：**「这句话在不在原文里」这件事，已经有便宜、现成的 API。**

### 中国市场的需求是真的，但以「知识库项目」形式采购

- [某市场部知识库招标](https://m.chinabidding.cn/zbgg/U-vz0lI8D.html)：要求「为 AI Agent 提供合规、结构化、可追溯的知识服务」、版本留痕、审计日志「具备防篡改能力」；
- [某金融知识库招标](https://www.jrzb.com/purchases/2026-08-20.92c551a9191770def03f32fce13f9f62)：要求「大模型问答可溯源」「完整审计功能」；
- 行业文章：直接引用要求「原文保真、来源溯源、文内标注、全程留痕」。

判断：**需求被写进招标，但作为知识库平台的一部分，不是独立工具。**

### 修正后的位置

| 层 | 原判断 | 修正 |
|---|---|---|
| L3 内容忠实度 | 空档 | **已商品化**（Apify/CiteLaw），价格极低 |
| L4 标准与认证 | 空 | 仍为空，但付费方不明 |

我们原来想的「做核验器卖给别人」，**价格上打不过 $3.5/千条**。

## 七、还剩什么

1. **中文书稿/扫描件**：Apify 面向网页 URL，不处理中文 PDF 书稿；
2. **中文出版合规**：招标要求审计、防篡改、版本留痕，需要本地化方案；
3. **凭证与认证**：把核验结果做成可验证凭证，仍无人做；
4. **标准**：仍空，但需要被采用才有价值。

## 九、L4 调研：标准与认证已被占位（2026-11-16 晚）

### 中国：行业标准已发布

**CY/T 284-2026《数字内容自动校对系统功能要求》**

- 发布：2026-03-02；实施：2026-05-01；
- 归口：全国新闻出版标准化技术委员会（SAC/TC 527）；
- 起草单位：蜜度科技、同方知网、江苏凤凰、外研在线、武汉理工数字传播、测绘出版社、机械工业出版社等；
- 覆盖：预处理、支撑、服务、统计报告、隐私安全、语言文字等模块。

判断：**「自动校对系统」的行业标准，由厂商与出版社共同起草，不是空白。**

相关标准：

- GB/T 44896-2024《新闻出版 知识服务 知识体系建设与应用》；
- CY/Z 32-2023《出版业区块链技术应用标准体系表》；
- 在研：知识增强大模型技术框架、知识图谱应用系统。

### 国际：认证体系成熟

- **ISO/IEC 42001**（AI 管理体系）：BSI 已获 ANAB、UKAS、RvA 三重认可，可发证；
- **EU AI Act**：高风险系统需第三方 conformity assessment，由公告机构执行；
- **C2PA Conformance Program**：产品需提交安全架构文档、通过审核、进入公开列表，才能获得受信签名证书。

判断：**认证是有门槛、有认可机构的行业，不是小团队能自建的。**

### 对 L4 的结论

| 想做的 | 现实 |
|---|---|
| 起草国家标准 | 需要标委会与起草单位资格，已被厂商占据 |
| 做认证机构 | 需要认可资质（ANAB/UKAS 级），不可能 |
| 做 C2PA 式 conformance | 需要联盟与信任列表 |
| 做「引文忠实度」专项认证 | 理论上可做，但无标准依据、无买方 |

## 十、总体研判（截至 11-16 晚）

### 四层全部有主

| 层 | 谁占 | 我们的空间 |
|---|---|---|
| L1 执行证明 | SWT3、Phala、Orgn、zanii | 无 |
| L2 数据来源 | ipto.ai | 无 |
| L3 内容核验 | Apify、CiteLaw、PursuitAgent、古联、方正、WPS | 价格战，无优势 |
| L4 标准认证 | 标委会 + 蜜度/知网；BSI、C2PA | 无资格 |

### 诚实结论

**「核验器」作为独立方向，四层都已被占或正在被占。**

我们原以为的空档（L3、L4），在两天调研后被证伪：

- L3 有 $3.5/千条的现成 API；
- L4 有国家行业标准与认证体系。

### 还剩的可能性

1. **不做产品，做贡献**：把我们的验证器与基准开源，作为行业公共品，换取声誉与引用；
2. **做极窄场景**：中文古籍书稿、扫描件、特定出版社流程，靠关系而非技术；
3. **回到内容本身**：元意识学说的独特性仍是唯一不可替代的资产；
4. **换方向**：承认核验器不是我们的机会。
