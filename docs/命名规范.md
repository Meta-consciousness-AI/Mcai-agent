# 命名规范

> 2026-11-18 修订：区分「对外称呼」与「已发布的技术标识」。

## 一、对外称呼：统一用 MCAI

所有面向人的文字、口头沟通、文档标题、署名、平台简介，一律写 **MCAI**（全大写）：

- 正确：MCAI、MCAI 团队、MCAI 知识库；
- 不写：mca、Mca、MCA、mcai（作为品牌名时）。

这条规则贯穿日常工作：聊天、文档、邮件、投稿、平台资料，都用 MCAI。

## 二、技术标识：保持现状，不随意改

以下名称已经发布，改名会破坏外部引用，**保留原样**：

| 对象 | 标识 | 为什么不能改 |
|---|---|---|
| PyPI 包 | `mcai-knowledge` | 已发布，下载量与安装命令依赖它 |
| 命令行 | `mcai` / `mcai-mcp` | 已写入文档与用户配置 |
| Python 模块 | `mcai` | `import mcai` 已在使用 |
| 环境变量 | `MCAI_HOME` / `MCAI_TOKEN` | 部署配置依赖 |
| MCP 服务器名 | `mcai-knowledge` | 注册表条目已收录 |
| 资源 URI | `mcai://` | 协议标识 |
| w3id 命名空间 | `https://w3id.org/mcai/` | PR 已合并，外部可能已引用 |
| GitHub 仓库 | `Mcai-agent` / `mca-agent`（目录名） | 克隆地址与历史链接 |
| DOI | `10.5281/zenodo.*` | 永久标识，不可改 |

这些是**历史标识**，不是品牌称呼。新项目、新包、新仓库、新域名，一律用 MCAI 命名。

## 三、短路径

`C:\Users\HP\MCAI` → 指向项目目录（目录联接），日常用这个短路径。

## 四、发现旧写法怎么办

- 文档正文：改成 MCAI；
- 历史发布记录（如 0.2.0 的改名说明）：保留，作为历史；
- 技术标识：不改。
