# 反馈驱动工作法

> 建立：2026-11-13
> 适用：所有渠道、功能、内容的取舍
> 一句话：**跟着正反馈走；没有反馈的先观察，不急着下结论，也不追加投入。**

## 一、为什么

- 这是新兴领域，没有成熟经验可参考；
- 主动预判容易偏离方向；
- 市场和环境的反馈，比我们的推演更可靠；
- 但很多事需要时间，短期没反馈不等于错。

## 二、三类信号

| 类型 | 定义 | 处理 |
|---|---|---|
| 正反馈 | 有人用、有人问、有增长、有引用 | 追加投入，顺着走 |
| 无反馈 | 数据不动，但时间还短 | 观察，不加投入，也不砍 |
| 负反馈 | 被拒、被限、被投诉、没人用且时间足够长 | 收缩或停 |

## 四、观察窗口

| 事项 | 观察期 | 到期动作 |
|---|---|---|
| Zenodo 增长 | 每两周 | 持续增长则加做 RDF/示例/关联 |
| MCP 调用 | 每两周 | 三个月为 0，考虑降低接入门槛 |
| 渠道阅读 | 每次发布后 7 天 | 长期低则不再加平台 |
| 关键词 | 每月 | 为 0 则检查入口提示，不放弃功能 |

## 五、决策规则

1. 只在正反馈出现的方向追加投入；
2. 无反馈的方向，不追加，但保留，设定观察期；
3. 观察期未到，不做「看起来该做」的主动出击；
4. 负反馈先判断是内容问题还是基础设施问题；
5. 每两周复盘一次信号表，记录变化。

## 六、不做什么

- 不因为焦虑而多发平台；
- 不因为一次数据下滑就改方向；
- 不把「我们觉得重要」当成「市场需要」；
- 不在没有信号的地方堆人力。

## 七、每两周要回答的三个问题

1. 哪个方向的反馈变强了？
2. 哪个方向仍然是零，观察期到了吗？
3. 下一步只做一件什么事？

## 八、建议的处理流程（广开言路）

外部 AI、专家、朋友的建议，一律按同一套流程处理，不因为来源不同而区别对待。

### 1. 先收，不预判

- 建议先完整记录，不在读之前就否定；
- 记录来源、时间、身份（AI / 人 / 机构）；
- 标注一句：**建议者是否身在其中**。

### 2. 分清「理念」与「落地」

大多数建议在理念上都成立，差别在落地条件。对每条建议问三件事：

1. 谁来做？
2. 什么时候做？
3. 触发条件是什么？

三问答不上来，就先当理念，不当任务。

### 3. 去伪存真

- 看依据：有没有数据、先例、可验证的事实；
- 警惕叙事型建议：听起来宏大，但说不出第一步；
- 警惕「说了等于做了」：建议者不承担执行成本，我们要按自己的约束裁剪。

### 4. 分流

| 判断 | 去向 |
|---|---|
| 现在能做、且与目标一致 | `docs/工作计划.md` |
| 理念成立、时机未到 | 工作备忘包加索引行 + 触发条件 |
| 不成立或不适合我们 | 记录理由，不反复讨论 |

### 5. 回馈，保持渠道

- 采纳、暂缓、不采纳，都给建议者一个明确回应；
- 让人和 AI 都愿意继续提建议；
- 只有广开言路，才有足够多的样本去伪存真。

### 6. 时间尺度

今天的建议来自大模型，十年后可能来自人类专家；来源会变，流程不变。

## 九、一句话

**多一个角度多一个视野；但理念是理念，落地是落地。我们按自己的实际，决定什么时候动。**
