# 需求研究：引文核对

> 时间：2026-11-16
> 方法：全网检索编辑、作者、媒体的自述与行业文章，不预设样本量。
> 结论先说：需求真实、有人付费，但已有商业产品；我们的差异点在「只核对、不改写」。

## 一、证据清单

### 1. 图书编辑的自述（强证据）

来源：[黑猫校对上线啦](https://muguangling.com/2026/05/10/quote-check/)

- 一部 16–17 万字的书稿，涉及「一百多部参考文献」；
- 「这些都需要我人工一一核对」；
- 「有的能全文搜索，核起来很舒心；更多的只能找到原始古籍扫描版 PDF，不得不人工手动翻目录查、翻页查」；
- 连续多日做到晚上九点；
- 三年后自己写了一个引文核校软件，说明痛点强到愿意自建工具。

### 2. 学术期刊的行业文章（强证据）

来源：《学术期刊中古籍引用常见问题及对策》，《汉字文化》2025 年第 8 期（知网）

- 论文引用古籍「错误频现」：错字、漏字、断错句、换错纪年；
- 编辑需要「常备工具书、利用电子资源、使用古籍智能处理系统」；
- 说明这是编辑部的日常问题，不是个例。

### 3. 商业产品已经存在（强证据，也是竞争）

来源：[WPS 黑马校对·引用出处规范核对](https://365.wps.cn/content/a22d72c91bc7466ebbb5c57f7a1f974a.html)

- 支持 GB/T 7714、APA 格式校验、DOI/PMID 验证、古籍卷册页码核查；
- 已用于出版社、期刊、政务审核；
- 私有云与 API 部署，按企业需求加价。

判断：付费市场被验证，但被 WPS 这类厂商占据。

### 4. 自动工具会「改错」（关键差异点）

来源：[豆瓣小组：论文参考文献引用错误会被指认学术不端吗](https://www.douban.com/group/topic/279210974/)

- 作者用「医学文献王」自动补全/替换文献信息；
- 结果 8 篇古籍引用「都是错的」，把《备急千金要方》替换成了论文标题；
- 险些被认定学术不端。

判断：**自动改写的工具会制造新错误**；用户需要的是「只核对、不改写」。

### 5. 作者自己在做低效核对（中证据）

来源：[抖音笔记：SCI 校对说明](https://www.douyin.com/note/7641491358247061163)

- 「七八十个文献全部都重新一核对，还包括卷码，出版日期」；
- 「参考文献跳转的链接，居然不是这个文献」。

### 6. 媒体事实核查（中证据）

来源：[事实核查的三个层次](https://m.dzplus.dzng.com/share/general/0/NEWS2354384SEPSKIPOAUEFP)

- 专业核查员参与每篇稿件，一篇文章「两天，有时四五天」；
- 最大难点是「核查记者从网络上找来的相关信息」。

来源：[Radio France 对 The Atlantic 核查部门的访谈](https://www.radiofrance.fr/franceinter/podcasts/les-80/les-80-de-nicolas-demorand-du-mercredi-26-juin-2024-6628751)

- 短稿数小时，复杂稿「数周甚至数月」。

### 7. 古籍核对的历史难题（弱证据，但说明长期性）

来源：[中研院文哲所：查核《古今图书集成》引文出处](https://www.litphil.sinica.edu.tw/newsletter/64/5-58.pdf)

- 类书引文出处与原书不合，是长期存在的学术问题。

## 二、需求分层

| 人群 | 痛点强度 | 现在怎么解决 | 付费可能 |
|---|---|---|---|
| 出版社/期刊编辑 | 强 | 人工 + 黑马校对 | 机构付费，已有预算 |
| 学术作者（投稿前） | 中 | 人工抽查 + 文献管理软件 | 个人低付费，怕出错 |
| 媒体事实核查 | 中强 | 专人核查 | 机构，但团队小 |
| 学生/一般写作者 | 弱 | 基本不查 | 低 |

## 三、现有方案的缺口

| 方案 | 缺口 |
|---|---|
| 人工核对 | 慢、累、易漏，扫描版 PDF 尤其难 |
| 黑马校对 | 强，但偏格式与书目库比对；需要采购；对「用户自带原文」的逐字核对未必覆盖 |
| 文献管理软件（医学文献王等） | 会自动改写，曾制造错误 |
| 通用大模型 | 会编，不可靠，不能作为核对依据 |

## 四、我们的差异点

1. **只核对，不改写**：给出「哪一句在原文里找不到」，不替用户改；
2. **用户自带原文**：不需要我们先有全量语料；
3. **字符级区间**：指出差在第几个字，而不只是「有问题」；
4. **可离线/本地**：稿件不出本机，适合出版社；
5. **拒答纪律**：找不到来源就说找不到，不猜。

## 五、最小产品雏形（不开发，先设想）

输入：

- 一份文稿（docx/txt）；
- 一份或多份原文（txt/PDF 提取文本）。

输出：

- 每条引文：原文是否存在、位置、差异字符；
- 找不到的引文：单列；
- 不改写、不建议替换。

## 六、待验证的问题

1. 出版社是否愿意用「外部工具」核对未出版稿件（保密）；
2. 黑马校对是否已覆盖「逐字比对」，还是只做格式与书目；
3. 学术作者愿不愿意为「投稿前自检」付费；
4. 扫描版 PDF 的文本提取质量，是否足以支撑核对。

## 七、初步判断

- 需求成立，且强度足够；
- 竞争存在，但集中在「格式/书目库」，我们的「逐字核对 + 不改写」是空档；
- 先做免费工具验证使用，再谈机构版。
