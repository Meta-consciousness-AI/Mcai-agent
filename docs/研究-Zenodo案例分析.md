## 二、六个模式

### 1. 优先提供「语义标准格式」，不只给 JSON

高下载的记录几乎都有：

- RDF / Turtle（`.ttl`）；
- N-Quads（`.nq`）；
- TBX（术语交换标准）；
- OTB、多语言 HTML 实例。

KNOT 直接给 `.ttl` + `.nq`，下载/浏览比高达 84%。
我们的包只有 JSONL/CSV/JSON，对语义网与知识图谱用户不友好。

### 2. 提供「多数据集/多版本」而不是单包

OnT 给了 13 个 ZIP（多个子数据集 × predict/inference），
Ontoterminology 给了 22 个文件（按语言、按对象类型拆分）。

好处：用户只下自己需要的那一块，下载门槛低。

### 3. 与代码、模型、项目主页联动

- OnT 在描述里直接链到 Hugging Face 模型集合；
- ArtKB 描述里列明每个文件是什么；
- 多数记录有 GitHub 链接。

我们的描述里有站点与 GitHub，但没有「使用示例」。

### 4. 摘要写成「文件清单 + 用途」

典型结构：

```
This package includes:
- xxx.ttl — the complete RDF dump
- xxx.json — image metadata
- README.md — field descriptions
```

我们的摘要是连续叙述，读者要读完整段才知道包里有什么。

### 5. 许可影响复用

样本里不少是 CC BY 4.0，允许商用与二次分发。
我们是 CC BY-NC-SA 4.0，学术使用没问题，但会挡住一部分工程复用。

### 6. 社区与关联

- 高浏览记录多提交到相关 Community（Digital Humanities、Open Science 等）；
- 通过 related identifiers 关联论文、项目、版本；
- 版本用 concept DOI 串联。

我们的记录目前没有提交社区，关联也偏少。

## 三、我们与样本的差距

| 维度 | 样本常见做法 | 我们 | 差距 |

| 语义格式 | TTL/NQ/TBX | 仅 JSON/CSV | 大 |

## 四、建议动作（按性价比排序）

### P0：加一份 RDF/Turtle 导出

- 把概念、关系、出处转成 `.ttl`；
- 与现有 JSON 一起打包；
- 工作量：1–2 天。

理由：这是 Zenodo 上同类记录最普遍的「专业信号」，也最容易被知识图谱用户采用。

### P1：加一个最小使用示例

- 一个 `example.py` 或 notebook：加载数据、查一个术语、打印出处；
- 放进 ZIP，描述里写清。

理由：降低「下载后不知道干什么」的流失。

### P2：把摘要改成文件清单

```
- concepts.jsonl — 64 个术语及定义
- faq.jsonl — 122 组问答
- relations.jsonl — 270 条关系
- provenance.jsonl — 出处
- README.md — 字段说明
```

理由：读者 10 秒内知道包里有什么。

### P3：补关联与社区

- 把数据集、预印本、规范三者用 related identifiers 互链；
- 提交到 Digital Humanities 或 Open Science 社区。

### P4：评估许可

是否从 CC BY-NC-SA 调整为 CC BY 4.0，需要你决定。
影响：放宽会提高复用率，但失去非商业限制。

## 五、不建议做的事

- 不为下载量做标题党；
- 不批量提交无关社区；
- 不把浏览/下载当 KPI；
- 不因为样本里有高下载记录就模仿其主题。
