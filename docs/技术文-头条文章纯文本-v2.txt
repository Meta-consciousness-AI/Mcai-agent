起因

“Meta-Consciousness Theory”是MCAI的原创学说，模型遇到它时通常有三种反应：

1. 没听说过，按字面意思猜；
2. 用同名概念替换，比如把它理解成心理学的 meta-awareness；
3. 给出一段似是而非的混合表述，读者分不清哪句来自原文、哪句是模型补的。

第三种最难发现。

我们的判断是：与其指望模型「记住」，不如把它做成一个可以被检索、被引用、被回查的数据服务。这篇文章只讲工程实现和踩过的坑，不讨论“Meta-Consciousness Theory”学说本身。

整体结构

输入是 Word/PDF 语料，输出是一套可分发的东西：

docx/pdf → 抽取 → 知识库 JSON → 站点 / 数据集 / MCP 服务

核心对象只有四个：概念、问答、关系、引证。每个概念必须带至少一条可回查的出处。

一、出处要精确到字符区间

最早的版本只记「文档 + 章节 + 原句」。上线后发现一个问题：引文核验通过率只有 83.6%。

原因很土：Word 里有大量手动换行，同一页被拆成多个段落，位置号重复，索引互相覆盖。

改法是给每条出处补上 char_start / char_end，并在位置号后面加序号区分拆分的段落。改完之后，55 条语料的出处全部逐字命中，字符区间一致率 100%。

这件事让我们确定了一条原则：没有字符区间的出处，不能算可回查。

二、术语形态比想象中麻烦

做第二份语料时，用的是《孙子兵法》。结果「五事」「九地」两个词被丢弃了——抽取规则把「中文数字开头」当成列表编号。

做第三份语料时，用的是《荀子·正名》。「性」「情」「名」「辞」八个单字术语全部丢失——规则要求术语至少两个字。

两次都是规则误杀，不是语料问题。

最后的处理：

- 只拒绝「数字 + 分隔符」的编号行，允许「五事」这种术语；
- 单字术语允许，但必须在人工分类里登记。

这条经验后来写进了规范：对先秦文本，术语形态不能按现代汉语的习惯假设。

三、没有定义句的文本，必须分层

《道德经》里几乎没有「X 者，Y 也」这样的定义句。任何「定义」都是后人的解释。

如果直接写「道：宇宙的本源」，就是把注疏当原文。我们的处理是把定义拆成两层：

{
"definition": "道，可道，非常道。",
"definition_type": "editor",
"editor_note": "编者注：宇宙的本源与总规律，不可言说。"
}

definition 永远是原文，逐字可核验；editor_note 明确标注为编者释义。接口、页面和数据集三处都分开呈现。

这一点看起来只是字段设计，实际决定了这套库能不能被信任。

四、多版本不是冲突

同一部经典的不同版本，字句本来就不一样。比如《道德经》有的版本写「见素抱扑」，通行本写「见素抱朴」。

早期逻辑会把这种差异判为「冲突」，要求人工裁定。但这不是错误，是版本事实。

改法是给每条出处记录 edition（版本、来源、校勘），版本之间的差异记入 edition_variants，并存可查；只有同一版本内出现差异较大的定义，才判为冲突。

{
"edition_variants": [
{"edition": "乙本", "definition": "……"}
]
}

五、关系要分层

270 条概念关系里，246 条是正文里的共现提及。如果默认全返回，关系图基本是噪声。

现在分三层：

- core：人工确认的核心关系；
- derived：衍生关系；
- mention：正文共现，默认不返回。

mcai_related 默认只给前两层，需要全图时显式打开。

结果

主库：64 个概念、122 组问答、270 条关系、213 条引证。

另外用三份公共领域文本做了复现：

- 孙子兵法：13 个概念，引文核验 13/13；
- 荀子·正名：12 个概念，12/12；
- 道德经：10 个概念，10/10。

复现暴露的规则问题，比主库本身更有价值。

怎么用

安装：

pip install mcai-knowledge
mcai-mcp

MCP 客户端配置：

{
"mcpServers": {
"mcai-knowledge": {
"command": "uvx",
"args": ["--from", "mcai-knowledge", "mcai-knowledge"]
}
}
}

也可以直接走 HTTP：

curl "https://mcai-knowledge-d7gtizltz910e2269-1316838521.tcloudbaseapp.com/api/v1/answer?q=什么是元识"
