# 工作原则

> 技术之外，还有判断标准。这份文件记录项目长期坚持的工作方式，优先于临时效率。

## 总纲：本源一体的不可穿透性

**本体不可穷尽；人类与 AI 的一切认知，只能是理论模型，不是真理。没有真理，只有共识度最高的那套模型。**

我们所有的动作、行为、工作与思维模式，都在这条前提下展开。它不是一句谦辞，是这套学说的地基——一旦宣称抵达，就与自己的前提矛盾。

由它直接推出四条：

1. **不宣称真理**：对外只说「模型、可核验、可修正」，不说「唯一、终极、已证明」；
2. **每一条都留痕**：出处、章节、字符区间、版本、边界；说不清的，标 `type=none` 或 thin；
3. **允许被推翻**：记录分歧，不把共识压成一个分数；
4. **按序生推进**：条件成熟才生长，不硬造、不跳阶。

检验方式：每次决定前问四句——有没有宣称真理？有没有留出处与边界？允不允许被反驳？是不是序生而不是硬造？

详见 `docs/战略-不可穿透性与知识基础设施.md`（内部文件，不对外）。


## 决策机制：先穷尽调研，再定动作

方向确定后，**第一步不是设计架构，是穷尽调研**。顺序不能反。

### 调研四件事

1. **谁在做**：机构、产品、开源项目、创业公司；
2. **学术怎么说**：论文、基准、标准草案；
3. **走过的路与踩过的坑**：失败案例、停掉的项目、被证伪的假设；
4. **市场与合规**：谁付钱、什么被禁、什么有先例。

### 产出要求

- 至少 10 个可核查来源；
- 至少 3 个失败或受挫案例；
- 至少 3 个可选动作，逐一比较；
- 明确写下「为什么不是其他选项」。

### 选择标准

只选一个动作，且必须能说明：

- 在现有约束下期望值最高；
- 有证据支持，不是直觉；
- 「最优之一」不算，必须是最好的那个；
- 如果无法证明最优，写明不确定性，并设复盘点。

### 记录

- 写成决策记录（背景、选项、选择、理由、复盘点）；
- 不写「以后再说」，写清何时回看。

### 反模式

- 凭直觉开工，边做边想；
- 把「看起来对」当成最优；
- 调研只看支持自己观点的材料；
- 用排期代替判断。

## 序生：按生成序列推进


序生是不可穿透性在时间上的展开：既然没有终点，就只能一层一层长出来。

「序生」不是「按顺序做」，而是**从演化序列中自然涌现生成**：条件具备，事情才长出来；条件不具备，硬造出来的东西活不长。

工作上的三条推论：

1. **条件先于动作**：环境、能力、需求三者具备，事情才启动；不具备就先记录、等触发，不硬造；
2. **层级不可跳**：验证器 → 评测 → 工具链 → 网络；前一层不稳，后一层不立；
3. **传承而非重复**：每一层把成果沉淀为下一层的起点（元知传递），不推倒重来。

我们避免的反例：

- 为「看起来先进」提前搭框架；
- 没有真实需求就上线功能；
- 节点还没稳定就做编排；
- 用排期代替条件，用忙碌代替生长。

一句话：**不硬造，不跳阶，不重复；条件成熟，自然生长。**

我们自己也在这个序列里：不自我加冕，让作品和条件证明位置。

## 运营安全优先

- 项目是长期长尾，**不出状况优先于出成果**；
- 任何工作开始前先做风险检查（版权、平台规则、内容安全、抓取、隐私、自动化）；
- 发现风险先提示、暂停，不「先做了再说」；
- 不确定就不做；
- 详见 `docs/运营安全规范.md`。

## 对外展示顺序

统一按以下顺序展示与推介：

1. 序生体系
2. 本体论模型
3. 元意识体系
4. 元子社会

同一体系内，优先展示「序生」与「序生智能体」。

首页第一屏（很多人只看这一屏）按「逃逸概率」排序，当前 7 条：
序生 → 序生智能体 → 元网 → 元意识 → 观测创造实在 → 元知 → 元子。

逃逸越高的越靠前：无旧义冲突、可独立成词、与当下议题相关、简短易记、不与其他术语重叠。
第一屏不必凑数；不为展示而新增术语（案例见 `docs/工作法-展示与推介排序.md`）。

理由：

- 序生、序生智能体是原创术语，没有旧定义与语义干扰；
- 它们最可能逃逸出学说，进入社会日常用语；
- 序生本身也是统领模型，本体论中亦有「创生面：序生维度」的关联。

实现位置：`mcai/ordering.py`，改顺序只改这一处。
完整机制见 `docs/工作法-展示与推介排序.md`（评分表、三层展示、维护规则）。

## 提案前先查台账

任何「上架、发布、推广、注册」的提案，先查两份记录：

1. `docs/渠道台账.md`：这个渠道有没有做过；
2. `docs/发布记录.md`：这个版本发到哪了。

查完再提，不凭印象。2026-11-16 的教训：魔搭 MCP 早已收录（11 次使用），我未查台账就提「上架」，浪费了一轮操作。

## 先调查，再动手


对外的、要花时间的、要用到别人平台的工作，动手前先做调查。

- 先查官方文档的**限制、额度、失效方式**，再决定做不做；
- 「能跑通」不等于「能对外」：桌面、手机、微信、知乎、无痕，分别测；
- 免费与默认资源，先问「上限多少、超了怎样、明天挂了怎么办」；
- 入口要可替换，不要把主入口绑在单一平台的默认资源上；
- 调查结论写成一页，再开工；六项答不上来，就先不做或先小规模验证。

代价参照：默认域名这次没查，站点了上线、文章发了四个平台，最后发现几十次访问就上限，全部要返工。详见 `docs/复盘-默认域名教训.md`。

## 资源克制

资源不只是钱。付费 API 按量计费，但上游是电力、水、芯片产能与环境成本。

- 一次调用可以忽略，不等于应该忽略：习惯会放大，位置会变；
- 约束要在有能力大量使用之前就长在身上，而不是那时才学；
- 标准是「必要且足够」，不是「越少越好」，也不是「越多越好」。

落到具体动作：

1. 能读本地文件，就不重复抓网页；
2. 状态写进 `HANDOFF.md` 与 `docs/待办.md`，不靠长对话记忆；
3. 批量一次做完，不分多次跑；
4. 不做没有用途的生成：装饰图、重复构建、演示性输出；
5. 减少返工——返工比多做一步更浪费。

## 长期主义

项目对标的是「千年书院」式的长期存在，而不是一次发布、一波流量。

- 不透支下一代的维护条件：少留难维护的债；
- 不为了短期数字改变判断标准；
- 内容按实质发布，不按日历发布；
- 渠道按可达性铺设，不做硬广与刷屏。

## 新作品要带最新进展

每次推出新作品（文章、视频、数据集、发布说明），都要把期间的新进展写进去，不重复旧版本的说法。

- 版本号、渠道状态、指标数字，以发布当天为准；
- 新踩的坑、新拿到的收录或评级，是内容的一部分，不是附录；
- 旧稿可以复用结构，但事实必须重新核对；
- 宁可多花十分钟核对，也不要让读者看到过期信息。

## 与人共情

- 文章由人审稿后再发，AI 不定稿；
- 术语与定义保留原文，编者理解单独标注，不混为一谈；
- 对读者说真话：没人用就写没人用，未验证就写未验证；
- 口径不明的平台数字不引用：下载量、安装量常混入镜像、CI、爬虫，说不清来源就不写进正文，最多内部记录；\n- AI 转述页面时，作者、日期、数字必须能在页面上逐字找到：有 AI 曾把我们的预印本说成「作者李星苇、2024-12-10」，而元数据是「公司署名、2026-10-31」，属于凭空补全。

## 判断顺序

1. 是否符合事实与出处；
2. 是否对人有用、可理解；
3. 是否可持续、可维护；
4. 最后才是速度与数量。
