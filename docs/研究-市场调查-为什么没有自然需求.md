# 市场调查：为什么没有自然需求

> 时间：2026-11-16
> 数据：自有渠道 + 公开资料
> 结论先说：不是我们做得差，是**品类与渠道错配**。

## 二、同类项目的情况

### 有量的

| 项目 | 量级 | 为什么 |
|---|---|---|
| Context7（文档检索 MCP） | 约 24 万次/周 | 直接服务「写代码查文档」这个高频任务 |
| GitHub MCP | 最常用之一 | 直接接入开发者已有工作流 |
| ctext.org（古籍网站） | 约 3 千–1.8 万访问/天 | 15 年 SEO，834 万收录页，搜索即达 |
| ModelScope 热榜 MCP | 快递、图像、Figma 等 | 工具型，解决具体事务 |

### 没量的

| 项目 | 情况 |
|---|---|
| 大量长尾 MCP | 估计 <100 次/周，很多接近 0 |
| 知识库类 MCP（如 remio-mcp、ai-knowledge-hub） | 下载少、维护停滞 |
| 冷门学说/垂直知识库 | 普遍没有自然访问 |

## 三、原因分析（按证据强度排序）

### 1. 品类错配：MCP 是「被调用」的，不是「被发现」的

- MCP 的入口在 Claude、Cursor、Cline 这类客户端里；
- 用户是带着任务去找工具，不是来逛知识库；
- 我们的东西需要「先知道元意识是什么」才会去装。

**证据**：热榜全是任务型工具；知识库类 MCP 普遍冷清。

### 2. 需求是「拉式」的，不是「推式」的

- 工具型 MCP：装上立刻省事，主动搜索安装；
- 知识库型：先有研究或好奇需求，才会找；
- 这类需求靠内容与搜索触发，不靠上架。

**证据**：ctext 靠 15 年 SEO 与 834 万索引页获得流量；我们站点未被 Bing 收录。

### 3. 渠道错配：我们的渠道不是目标用户的渠道

- 主流 MCP 客户端与目录以英文开发者为主；
- 国内开发者聚集在 ModelScope、扣子、百炼；
- 我们目前在 Glama、mcprush、MCP 注册表——这三个是「目录」，不是「流量入口」。

**证据**：ModelScope 艺术与文化类有 113 个 MCP，热榜由工具占据；我们只上架了数据集，没有上架 MCP。

### 4. 认知门槛：陌生术语无法形成搜索词

- 没人会搜「元意识 MCP」；
- 但有人会搜「道德经 原文 出处」「孙子兵法 引文」；
- 我们的入口词，选错了。

### 5. 信任门槛：冷门学说缺少外部引用

- 开发者不会为陌生学说装一个 MCP；
- 但会为「能核验引文」这种确定性能力装。

## 四、结论

**问题不在「内容不够好」，在「入口与需求不匹配」。**

- 我们把一个「需要被理解」的东西，放进了「需要立刻有用」的货架；
- 又把入口放在「目录」，而不是「搜索与内容」。

## 五、解决方向（三条，按成本排序）

### 实验 1：上架 ModelScope MCP 广场（低成本，1 天）

- 理由：中文开发者渠道，有热榜与搜索；
- 动作：把 `mcai-mcp` 提交到 ModelScope MCP 广场，分类选「知识/教育」；
- 观察：2 周内的调用与安装；
- 成功标准：出现 ≥1 次非我方调用。

### 实验 2：换入口词，做「古籍引文核验」内容（低成本，2–3 天）

- 理由：经典有真实搜索量，学说可搭车；
- 动作：写一篇「怎么核验一句古文的出处」，文末给工具入口（带 `src`）；
- 观察：页面浏览与 `/r` 点击；
- 成功标准：文章带来 ≥10 次站内点击。

### 实验 3：加一个「试用页」，免安装提问（中低成本，3–5 天）

- 理由：安装是最大摩擦；
- 动作：站点加一个输入框，直接调用公开 API，展示定义与出处；
- 观察：试用次数与后续调用；
- 成功标准：试用 ≥20 次/周。

## 六、不做什么

- 不为了流量去讲玄学；
- 不买量、不刷榜；
- 不因为两周没量就否定内容价值；
- 不在没有信号前扩大投入。

## 七、下一步

先做实验 1（成本最低、渠道最匹配），两周后看数据，再决定实验 2、3。
